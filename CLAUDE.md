# CLAUDE.md — правила проекта Props

Учебная игра про пропсы в React для русскоязычного студента фулстак-разработки. Сеттинг — **пещеры Графа Пропсулы**:
18 пещер на трёх ярусах (от простого к сложному), у каждой свой хозяин-чудище, над всеми — вампир Граф (учитель),
помощник — летучая мышь Лунатик. Код — тоже учебный материал: его читают, чтобы учиться.

**Документ передачи в репозиторий не входит.** Пожелания владельца, идеи по развитию и дословная история чата,
в котором создавался проект, лежат у владельца рядом с папкой проекта: `../PROPS_HANDOFF_CLAUDE_CODE_RU.md`.
Если файл доступен — прочитай его перед большой задачей. В открытый репозиторий его не возвращать.

## Команды

- `npm install` — зависимости (Node 20.19+ или 22.12+)
- `npm run dev` — сервер разработки (http://localhost:5173)
- `npm test` — Vitest: целостность контента и чистая логика. **Запускай после любых правок контента.**
- `npm run lint` — ESLint (правила хуков + рекомендованные JS); `npm run format` — Prettier
- `npm run check` — lint + тесты + сборка: **обязательно перед тем, как сказать «готово»**
- `npm run build` — две сборки подряд: сайт в `dist/` (+ `dist/sw.js` для офлайна) и «всё в одном файле»
  `dist-single/Props.html` (копия кладётся в `dist/Props.html` — её скачивают со страницы установки)
- `npm run build:single` — только один файл; `npm run preview` — просмотр сборки сайта
- `npm run library` — пересобрать «Свитки Графа» из `docs/guide.md`

## Стек и ограничения

- React 19.3 + Vite 8, **JavaScript (не TypeScript)**, файлы `.js` / `.jsx`.
- Стили: CSS-модули рядом с компонентом (`Name.module.css`) + общие в `src/styles/`. Цвета — только CSS-переменные
  из `src/styles/variables.css` (две темы: `night` и `day`; переменные антуража — `--amb-*`).
- Шрифты — пакеты `@fontsource-variable/*` (Inter, Cormorant Garamond, JetBrains Mono): работают офлайн.
- Без новых зависимостей без явной необходимости: роутер, подсветка кода, тултипы, Markdown-рендерер и звуки
  написаны вручную нарочно.
- Маршруты — хэш с простыми именами (`#chapter-flow`, `#glossary-props`, `#library-s03`, `#bestiary`, `#install`);
  ссылки строит объект `to` из `src/app/useHashRoute.js`. Не менять на history API (GitHub Pages) и не возвращать
  слэши в хэш (предпросмотр на claude.ai пропускает только простые имена).
- `base: './'` в `vite.config.js` не трогать — иначе сломается публикация в подпапке.
- API React 19: `<Ctx value>` вместо `.Provider`, `use(Ctx)`, `ref` как обычный проп, без `forwardRef`,
  `propTypes`, `defaultProps`.
- `localStorage` — только через `src/utils/storage.js` (try/catch). Ключ прогресса `props-castle/progress/v1`
  **не переименовывать**: у игроков пропадёт прогресс.
- Сервис-воркер регистрируется только в продакшене и молча не работает внутри iframe (предпросмотр claude.ai).
  Его код создаёт `build/serviceWorkerPlugin.js`. Правила: файлы в кэш берутся с `cache: 'reload'`; `skipWaiting()`
  не вызывать (новая версия включается при следующем запуске, иначе у открытой игры пропадут её файлы);
  запасная страница берётся из кэша своей версии. Список файлов собирается на шаге `writeBundle` и сверяется
  с диском: на шаге `generateBundle` в нём были «пустые» скрипты шрифтов, которые Vite потом удаляет, — воркер
  получал 404 и не устанавливался (офлайн на GitHub Pages не работал вовсе).
- **Офлайн проверяй на строгом сервере.** `npm run preview` вместо отсутствующего файла отдаёт страницу игры
  с кодом 200 и скрывает такие ошибки. Годится `python -m http.server --directory dist` или сам GitHub Pages:
  открыть игру, дождаться «✓ Игра сохранена…» на странице установки, выключить сервер или сеть, перезагрузить.
- Сборка одним файлом — `build/singleFilePlugin.js` (режим `--mode single`, переменная `VITE_SINGLE`). Вшивать
  только на шаге `writeBundle`: раньше Vite ещё не дописал код «ленивых» `import()`.
- Телефон: страница занимает весь экран iPhone (`viewport-fit=cover`), отступы от выреза и полоски «домой» —
  переменные `--safe-top/bottom/left/right` и `--header-total` в `variables.css`. Всё «приклеенное» к краям экрана
  обязано их учитывать.

## Стиль кода

- **Комментарии — на русском**, объясняют «зачем», простым языком. Новые файлы начинаются с комментария о назначении.
- Данные отдельно от отображения: учебный текст живёт только в `src/content/`, компоненты получают его пропсами.
- Чистые функции — в `src/utils/` и `src/state/progressReducer.js`; на них есть тесты в `tests/`.
- Состояние неизменяемое: только новые объекты/массивы, без мутаций.
- Проп-функции называются `onЧто-то`, обработчики — `handleЧто-то`.
- Доступность: кнопки — `<button>`, у иконок `aria-hidden`, у интерактивных элементов понятный `aria-label`;
  учитывать `prefers-reduced-motion` (антураж, хозяева, мыши уже это делают).
- Мобильная вёрстка в приоритете: проверяй ширину 360px. В grid-контейнерах с кодом — `minmax(0, 1fr)`.
  Палец на телефоне и мышь на компьютере — равноправные сценарии: элементы не должны перекрывать друг друга.
- Шапка: меню в ней показывается с 1000px, значки в меню и подпись логотипа — с 1280px, колонка Графа сбоку — тоже
  с 1280px. Не возвращай прежние пороги (900 и 1180px): шапка и облачко Графа вылезали за край экрана.
- Термин в тексте — `<span role="button">`, а не `<button>`: кнопка в строке не переносится по словам и отрывает
  от себя знаки препинания.
- Цвет пещеры `--cave` для текста — только через `color-mix(… var(--cave) var(--cave-ink), var(--text))`:
  в дневной теме чистый цвет не читается.

## Контент (тесты в `tests/content.test.js` проверяют всё ниже)

- Разметка в текстах: `**жирный**`, `` `код` ``, `[[id]]` или `[[id|подпись]]` для термина. Внутри `**…**`
  другая разметка не работает.
- Каждый термин `[[id]]` есть в `src/content/glossary.js`, а его английское и кодовое написание — в
  `src/content/glossaryCode.js` (`en` обязателен, `code` — если есть настоящее написание в коде).
- **Порог победы:** хозяин пещеры повержен при 5 верных из 8 (`PASS_SCORE`, `isPassed`, `neededCorrect` в
  `src/state/progressReducer.js`). Победа не отнимается слабой повторной попыткой.
- Пещера = файл `src/content/chapters/NN-имя.js` (4–6 карточек урока, ровно 8 заданий, разминка, заклинание,
  «Объясни Лунатику») + `NN-имя.syntax.js` + строки в `chapters/index.js`, `content/difficulty.js`, `content/story.js`.
- **У каждой карточки — схема (`scheme`) или иллюстрация (`diagram`).** Схемы: `steps`, `tree`, `compare`
  (формат — в `src/components/Scheme/Scheme.jsx`).
- **У каждой карточки с кодом — разбор синтаксиса**: `why` (почему так), `alt[]` (как ещё можно — только рабочие
  варианты) и `wrong[]` (как нельзя и почему). Факты — точные, для React 19.
- Сложность заданий: у каждого задания уровень ★/★★/★★★ в `difficulty.js`; внутри пещеры задания идут от простых.
- У каждой пещеры в `story.js`: `intro`, `outro` и `guardian` (`name`, `kind`, `threat`, `defeat`, `why`).
  `why` — мостик «образ чудища → тема» (сороконожка — массив, богомол с крюками — хуки).
- Ярусы (`TIERS` в `story.js`) — по 6 пещер; порядок пещер = порядок обучения, проверяй зависимости тем.

## Хозяева пещер и маскоты

- Портреты — SVG в `src/mascot/guardians/art/*.jsx`, реестр — `src/mascot/guardians/index.js` (ключ — id пещеры,
  `light` — цвет подсветки). Общие фильтры (`g-flesh`, `g-stone`, `g-glow`, `g-blur`) рисуются один раз
  в `GuardianDefs` — используй их по id. Анимации частей — классы `g-eye`, `g-sway`, `g-flicker`, `g-wave`, `g-drip`.
- Стиль: мрачный, злой, свет снизу, светящиеся глаза, у всех разные силуэты и цвета.
- Граф (`src/mascot/Vampire.jsx`) управляется пропом `mood`; реплики — `src/mascot/phrases.js`;
  указывает на ключевые моменты через `useMascot().pointAt`.

## Свитки Графа (теория)

- Источник — `docs/guide.md` (полное руководство). `npm run library` режет его на `src/content/library/sections/sNN.md`
  и пишет `sections.json`. Заглушки схем превращаются в `::diagram имя` / `::scheme имя`
  (схемы — `src/content/library/schemes.js`). Разделы грузятся лениво (`import.meta.glob`).

## Перед тем как сказать «готово»

1. `npm run check` — без ошибок и предупреждений; `npx prettier --check .` — чисто.
2. Посмотри изменённые экраны на ширине 360px и на компьютере, в обеих темах.
3. Новые тексты — простым языком, термины объяснены, примеры с пояснениями.
