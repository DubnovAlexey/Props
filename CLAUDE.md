# CLAUDE.md — правила проекта Props

Учебная игра про пропсы в React для русскоязычного студента фулстак-разработки. Сеттинг — **пещеры Графа Пропсулы**:
18 пещер на трёх ярусах (от простого к сложному), у каждой свой хозяин-чудище, над всеми — вампир Граф (учитель),
помощник — летучая мышь Лунатик. Код — тоже учебный материал: его читают, чтобы учиться.

**Документ передачи в репозиторий не входит.** Пожелания владельца, идеи по развитию и дословная история чата,
в котором создавался проект, лежат у владельца рядом с папкой проекта: `../PROPS_HANDOFF_CLAUDE_CODE_RU.md`.
Если файл доступен — прочитай его перед большой задачей. В открытый репозиторий его не возвращать.

## Команды

- `npm install` — зависимости (Node 20.19+ или 22.12+)
- `npm run dev` — сервер разработки (http://localhost:5173)
- `npm test` — Vitest: целостность контента, чистая логика и стили (`tests/styles.test.js`: у каждой анимации
  есть свой `@keyframes`). **Запускай после любых правок контента.**
- `npm run lint` — ESLint (правила хуков + рекомендованные JS); `npm run format` — Prettier
- `npm run check` — lint + тесты + сборка: **обязательно перед тем, как сказать «готово»**
- `npm run build` — две сборки подряд: сайт в `dist/` (+ `dist/sw.js` для офлайна) и «всё в одном файле»
  `dist-single/Props.html` (копия кладётся в `dist/Props.html` — её скачивают со страницы установки)
- `npm run build:single` — только один файл; `npm run preview` — просмотр сборки сайта
- `npm run library` — пересобрать «Свитки Графа» из `docs/guide.md`

## Git

Коммиты и пуши делает владелец проекта. **Не выполняй `git commit` и `git push` без прямой просьбы.**

Владелец коммитит часто, в том числе посреди работы: перед продолжением после паузы смотри `git status`.
Переводы строк — LF (`.gitattributes`, `.editorconfig`, Prettier).

## Инструкция по установке

Пошаговая инструкция «для новичков» (iPhone, Android, компьютер) живёт в двух местах: в `README.md` — на пяти
языках, и в игре — в словарях интерфейса (`src/i18n/ui/*.js`, раздел `install.devices`), тоже на пяти.
Меняешь шаги — правь оба места и все пять языков сразу.

## Языки

Решение владельца (10.11.2026): игра и документы — на пяти языках: русский, английский, иврит (справа налево),
испанский, французский.

**Что сделано.** Этап 1 (версия 2.4.0): на пяти языках весь интерфейс — меню, кнопки, подписи, страницы,
реплики Графа, инструкция по установке. Этап 2 (с версии 2.5.0): перевод самих уроков, первым — английский.
**Английский готов целиком с версии 2.6.0** (`ready: true`): сюжет и хозяева, все 18 пещер, факты, методики, раунды
перемены, словарь терминов (117), «Разобрать синтаксис», подписи схем-картинок и свитки Графа (20 разделов и подписи
их схем). Дальше — иврит, испанский, французский, тем же путём: пещера за пещерой, потом свитки, потом `ready: true`.

**Как устроен перевод уроков** (решение 11.11.2026). Русский текст в `src/content/` — оригинал. Перевод — «накладка»
`src/content/i18n/<язык>/`: объект той же формы, но только с текстом. Логика заданий (какой ответ верный, номер
строки с ошибкой, корзины), значки, цвета и порядок берутся из оригинала, поэтому перевод не может сломать задание.
Чего в накладке нет, то остаётся русским — игра работает и с переводом «наполовину».

- `src/utils/localize.js` — наложение (`localize`) и проверка накладки (`overlayProblems`); `src/content/index.js` —
  `buildContent`, `RU_CONTENT`, `loadContent(lang)`: переводы грузятся по требованию, как словари.
- **Компоненты берут уроки только хуком** `const { CHAPTERS, GLOSSARY_MAP } = useContent();` — не импортом файлов
  из `src/content/`: импорт всегда дал бы русский текст. Исключение — свитки (`library/`), их перевод впереди.
- Тексты «Разобрать синтаксис» — `src/content/syntaxGuide.js`, подписи внутри схем-картинок — `src/content/diagrams.js`
  (в `Diagram.jsx` — только рисунок). Новый текст для игрока — только в `src/content/` или в словарях интерфейса.
- **Как перевести пещеру:** файл `src/content/i18n/en/chapters/NN-имя.js` по образцу готовых; её «вывеску» (`cave`,
  `title`, `goal`) перенеси туда из `HEADERS` в `chapters/index.js` и добавь пещеру в список `CHAPTERS` внизу. Правила:
  - списки объектов (карточки, варианты, шаги схем, корзины-объекты) — в том же порядке и той же длины, `{}` — «тут
    переводить нечего»; списки строк (абзацы `body`, пункты схем `items`, `bins`, `bank`) переводятся целиком;
  - разбор кода (`scheme`, `why`, `alt`, `wrong`) кладётся прямо в карточку: в оригинале он в `NN-имя.syntax.js`;
  - код переводи, только если в нём есть русские слова (строки, комментарии), и не меняй число строк и пропусков
    `___`: по номерам строк работают подсветка и задание «Найди ошибку»;
  - термины `[[id|подпись]]` — те же id, что в оригинале; у «Впиши ответ» можно дать свои `answers`, у «Объясни
    Лунатику» — свои слова-маркеры (`words`, строчными буквами);
  - `tests/translation.test.js` проверит всё это и то, что в переведённой пещере не осталось русских букв.
- Пока пещеры переведены не все, карта пещер пишет «Переведено пещер: N из 18» (`lang.partial`). Язык с `ready: true`
  обязан быть переведён целиком — это тоже проверяет тест.

- Всё про языки — в `src/i18n/`:
  - `languages.js` — список языков и выбор языка при запуске. У языка есть флаг `ready`: переведены ли уроки.
    Пока `ready: false`, язык не включается сам по настройкам браузера — только вручную, переключателем.
    Перевёл уроки языка — поставь `ready: true`;
  - `ui/ru.js` — **главный словарь**; `ui/en.js`, `he.js`, `es.js`, `fr.js` повторяют его ключ в ключ. Русский
    вшит в основной код, остальные подгружаются по требованию (`dictionaries.js`) и входят в офлайн-копию;
  - `translate.js` — функция перевода; `I18nContext.jsx` — хук `useI18n()`; `typography.js` — французские
    пробелы; `direction.js` — направление письма по буквам.
- **Текст интерфейса в компонентах не пишем.** В компоненте: `const { t } = useI18n();` и `t('map.title')`.
  Новая строка = ключ в `ru.js` + перевод в четырёх остальных словарях. `tests/i18n.test.js` не пропустит
  потерянный перевод, лишний ключ, расхождение подстановок `{имя}` и строку, которую никто не показывает.
- Значение в словаре — строка с подстановками (`'Пещера {n}'`), формы числа (`{ one, few, many, other }`;
  выбирает `count`) или список (шаги инструкции, реплики Графа). Разметка — как в уроках: `**жирный**`,
  `` `код` ``, `[[id|подпись]]`; такую строку показывает `<RichText text={t('…')} />`.
- Данные без текста: в `navigation.js`, `ranks.js`, `tasks/index.js`, шагах пещеры лежат только id и значки,
  подписи берутся из словаря по id.
- **Французский:** перед `:` `;` `!` `?` и внутри `« »` пиши обычный пробел — при загрузке он станет неразрывным.
- **Испанский:** вопрос и восклицание открываются `¿` и `¡`.
- **Иврит** (справа налево):
  - направление страницы (`dir="rtl"`) ставит `I18nContext`; стрелки в подписях смотрят в другую сторону
    («дальше» — `←`); обращение к игроку — во множественном числе;
  - в стилях — логические свойства: `margin-inline-start`, `padding-inline-start`, `border-inline-start`,
    `inset-inline-start/end`, `text-align: start`. `left` / `right` — только для украшений, которые не должны
    зеркалиться (антураж, «неожиданности», полёты мышей, насест Графа — он пока остаётся справа);
  - код всегда слева направо (`direction: ltr` у `code`, `pre` и у блока кода);
  - заголовки (`BloodTitle`) сами определяют направление по буквам: буква там — отдельный блок, и без этого
    русское слово в ивритской строке встало бы задом наперёд;
  - пока уроки на русском, в `global.css` действует временное правило `unicode-bidi: plaintext`: абзац сам
    выбирает направление по первой букве. После перевода уроков на иврит его нужно убрать.
- Невидимые и особые символы в коде пиши кодом: `\u00a0` (неразрывный пробел), `\u200e`. «Живой» невидимый
  символ в исходнике не отличить от обычного пробела.
- Выбор языка хранится в прогрессе (`progress.lang`, `null` — выбрать автоматически) и переживает сброс.

## Стек и ограничения

- React 19.3 + Vite 8, **JavaScript (не TypeScript)**, файлы `.js` / `.jsx`.
- Стили: CSS-модули рядом с компонентом (`Name.module.css`) + общие в `src/styles/`. Цвета — только CSS-переменные
  из `src/styles/variables.css` (две темы: `night` и `day`; переменные антуража — `--amb-*`).
- Шрифты — пакеты `@fontsource-variable/*` (Inter, Cormorant Garamond, JetBrains Mono): работают офлайн.
- Без новых зависимостей без явной необходимости: роутер, подсветка кода, тултипы, Markdown-рендерер и звуки
  написаны вручную нарочно.
- Маршруты — хэш с простыми именами (`#chapter-flow`, `#glossary-props`, `#library-s03`, `#bestiary`, `#install`);
  ссылки строит объект `to` из `src/app/useHashRoute.js`. Не менять на history API (GitHub Pages) и не возвращать
  слэши в хэш (предпросмотр на claude.ai пропускает только простые имена).
- `base: './'` в `vite.config.js` не трогать — иначе сломается публикация в подпапке.
- API React 19: `<Ctx value>` вместо `.Provider`, `use(Ctx)`, `ref` как обычный проп, без `forwardRef`,
  `propTypes`, `defaultProps`.
- `localStorage` — только через `src/utils/storage.js` (try/catch). Ключ прогресса `props-castle/progress/v1`
  **не переименовывать**: у игроков пропадёт прогресс.
- Сервис-воркер регистрируется только в продакшене и молча не работает внутри iframe (предпросмотр claude.ai).
  Его код создаёт `build/serviceWorkerPlugin.js`. Правила: файлы в кэш берутся с `cache: 'reload'`; `skipWaiting()`
  не вызывать (новая версия включается при следующем запуске, иначе у открытой игры пропадут её файлы);
  запасная страница берётся из кэша своей версии. Список файлов собирается на шаге `writeBundle` и сверяется
  с диском: на шаге `generateBundle` в нём были «пустые» скрипты шрифтов, которые Vite потом удаляет, — воркер
  получал 404 и не устанавливался (офлайн на GitHub Pages не работал вовсе).
- **Офлайн проверяй на строгом сервере.** `npm run preview` вместо отсутствующего файла отдаёт страницу игры
  с кодом 200 и скрывает такие ошибки. Годится `python -m http.server --directory dist` или сам GitHub Pages:
  открыть игру, дождаться «✓ Игра сохранена…» на странице установки, выключить сервер или сеть, перезагрузить.
- Сборка одним файлом — `build/singleFilePlugin.js` (режим `--mode single`, переменная `VITE_SINGLE`). Вшивать
  только на шаге `writeBundle`: раньше Vite ещё не дописал код «ленивых» `import()`.
- Телефон: страница занимает весь экран iPhone (`viewport-fit=cover`), отступы от выреза и полоски «домой» —
  переменные `--safe-top/bottom/left/right` и `--header-total` в `variables.css`. Всё «приклеенное» к краям экрана
  обязано их учитывать.

## Стиль кода

- **Комментарии — на русском**, объясняют «зачем», простым языком. Новые файлы начинаются с комментария о назначении.
- Данные отдельно от отображения: учебный текст живёт только в `src/content/`, компоненты получают его пропсами.
- Чистые функции — в `src/utils/` и `src/state/progressReducer.js`; на них есть тесты в `tests/`.
- Состояние неизменяемое: только новые объекты/массивы, без мутаций.
- Проп-функции называются `onЧто-то`, обработчики — `handleЧто-то`.
- Доступность: кнопки — `<button>`, у иконок `aria-hidden`, у интерактивных элементов понятный `aria-label`;
  учитывать `prefers-reduced-motion` (антураж, хозяева, мыши уже это делают).
- Мобильная вёрстка в приоритете: проверяй ширину 360px. В grid-контейнерах с кодом — `minmax(0, 1fr)`.
  Палец на телефоне и мышь на компьютере — равноправные сценарии: элементы не должны перекрывать друг друга.
- Шапка: меню в ней показывается с 1000px, значки в меню и подпись логотипа — с 1280px, колонка Графа сбоку — тоже
  с 1280px. Не возвращай прежние пороги (900 и 1180px): шапка и облачко Графа вылезали за край экрана.
- Термин в тексте — `<span role="button">`, а не `<button>`: кнопка в строке не переносится по словам и отрывает
  от себя знаки препинания.
- **Окно-пояснение термина** ставит `src/utils/placeTip.js`: над термином, под ним или — если не помещается — с
  ограничением высоты и прокруткой внутри окна, всегда между шапкой и нижним меню (они помечены `data-fixed="top"` /
  `"bottom"`). Размер окна мерь через `offsetWidth`/`offsetHeight`: окно появляется с анимацией-уменьшением, и
  `getBoundingClientRect` давал размер на 15% меньше — окно вылезало за край телефона.
- **Прокрутка при смене экрана** (страница, шаг пещеры, карточка, следующее задание, итог) — только через
  `src/utils/scroll.js` (`scrollToTop`, `scrollToElement`) или хук `useScrollTopOnChange` (`src/hooks/useScrollTop.js`).
  Там `behavior: 'instant'`: плавная прокрутка из общих стилей обрывалась, когда React менял содержимое, и новый экран
  открывался с середины (на iPhone — почти всегда). Выключить её строчным стилем нельзя — проверено замером.
- **Нижнее меню телефона** — шесть пунктов, включая «Перемену» (решение владельца: на телефоне она «терялась»).
  Подписи на узком экране мельче (`clamp` в `Layout.module.css`); замер — ни одна не обрезается с 320px на пяти языках.
- Цвет пещеры `--cave` для текста — только через `color-mix(… var(--cave) var(--cave-ink), var(--text))`:
  в дневной теме чистый цвет не читается.
- **Анимации в модульных стилях.** `@keyframes` описывай в том же `*.module.css`, где его используешь. Сборщик
  переименовывает имена анимаций вместе с классами, и ссылка из модуля на анимацию из `src/styles/animations.css`
  ведёт в никуда — анимация молча не работает (так с самого начала не работала 21 анимация: крылья мышей,
  моргание и парение Графа). В `animations.css` — только анимации общих классов `.anim-*`. Запись `global(имя)`
  сборщик понимает, но IntelliJ считает её ошибкой — не используй. За этим следит `tests/styles.test.js`.
- **Проверка кода IntelliJ** (окно коммита → Code Analysis) должна быть без ошибок и предупреждений: владелец
  смотрит её перед каждым коммитом. Что для этого нужно:
  - переменные CSS, которые задаёт JavaScript через `style`, объявляй в стилях со значением по умолчанию
    (пример — начало `Scares.module.css`), иначе «Cannot resolve custom property»;
  - у `font-family: var(--font-…)` дописывай запасное семейство: `, serif` / `, sans-serif` / `, monospace`;
  - в регулярных выражениях — только общие категории Юникода (`\p{L}`, `\p{M}`, `\p{N}`, `\p{P}`);
  - ложные срабатывания гасит пометка-комментарий: `<!--suppress … -->` в начале `README.md` (якоря
    `<a id>`) и `index.html` (файлы из `public`). Не удаляй эти пометки;
  - примеры кода в строках уроков IntelliJ проверяет как настоящий код («неиспользуемая функция», «картинка без alt»).
    В файлах уроков, которые ты меняешь, перед `export` ставь пометку
    `// noinspection JSUnusedLocalSymbols,HtmlRequiredAltAttribute,HtmlUnknownTarget,HtmlUnknownAttribute`
    (в `*.syntax.js` — ещё `JSNonASCIINames`: ключи там — русские заголовки с латиницей) с пояснением рядом.

## Контент (тесты в `tests/content.test.js` проверяют всё ниже)

- Разметка в текстах: `**жирный**`, `` `код` ``, `[[id]]` или `[[id|подпись]]` для термина. Внутри `**…**`
  другая разметка не работает.
- Каждый термин `[[id]]` есть в `src/content/glossary.js`, а его английское и кодовое написание — в
  `src/content/glossaryCode.js` (`en` обязателен, `code` — если есть настоящее написание в коде).
- **Порог победы:** хозяин пещеры повержен при 5 верных из 8 (`PASS_SCORE`, `isPassed`, `neededCorrect` в
  `src/state/progressReducer.js`). Победа не отнимается слабой повторной попыткой.
- Пещера = файл `src/content/chapters/NN-имя.js` (4–6 карточек урока, ровно 8 заданий, разминка, заклинание,
  «Объясни Лунатику») + `NN-имя.syntax.js` + строки в `chapters/index.js`, `content/difficulty.js`, `content/story.js`.
  Разбор кода в `NN-имя.syntax.js` привязан к **заголовку карточки**: меняешь заголовок — поменяй и ключ там.
  Поменял текст урока — поправь и его перевод (`src/content/i18n/en/…`), если пещера уже переведена.
- **У каждой карточки — схема (`scheme`) или иллюстрация (`diagram`).** Схемы: `steps`, `tree`, `compare`
  (формат — в `src/components/Scheme/Scheme.jsx`).
- **У каждой карточки с кодом — разбор синтаксиса**: `why` (почему так), `alt[]` (как ещё можно — только рабочие
  варианты) и `wrong[]` (как нельзя и почему). Факты — точные, для React 19.
- Сложность заданий: у каждого задания уровень ★/★★/★★★ в `difficulty.js`; внутри пещеры задания идут от простых.
- У каждой пещеры в `story.js`: `intro`, `outro` и `guardian` (`name`, `kind`, `threat`, `defeat`, `why`, `bio`).
  `why` — мостик «образ чудища → тема» (сороконожка — массив, богомол с крюками — хуки). `bio` — биография хозяина
  в два предложения с чёрным юмором, её показывает Бестиарий (12.11.2026); переведённая пещера переводит и её.
- Ярусы (`TIERS` в `story.js`) — по 6 пещер; порядок пещер = порядок обучения, проверяй зависимости тем.

## Хозяева пещер и маскоты

- Портреты — SVG в `src/mascot/guardians/art/*.jsx`, реестр — `src/mascot/guardians/index.js` (ключ — id пещеры,
  `light` — цвет подсветки). Общие фильтры (`g-flesh`, `g-stone`, `g-glow`, `g-blur`) рисуются один раз
  в `GuardianDefs` — используй их по id. Анимации частей — классы `g-eye`, `g-sway`, `g-flicker`, `g-wave`, `g-drip`.
- Стиль: мрачный, злой, свет снизу, светящиеся глаза, у всех разные силуэты и цвета. Кровь и жёсткие детали
  (шрамы, добыча, слёзы, клейма) — можно и нужно: решение владельца «жёстче и реалистичнее».
- Кровь рисуется одним набором — `src/mascot/guardians/gore.jsx`: `Trail` (потёк), `Drop` (падающая капля, классы
  `g-drip` / `g-drip2`), `Splatter` (брызги), `Tips` (кровь на остриях). Цвета крови — только оттуда.
- Поверженный хозяин (`mood="defeated"`) — пепельный и с тремя бороздами от когтей; это делает `Guardian.jsx`
  (прямоугольник с `mix-blend-mode: color` и борозды поверх), а не CSS-фильтр на всём рисунке.
- Граф (`src/mascot/Vampire.jsx`) управляется пропом `mood`; реплики — `src/mascot/phrases.js`;
  указывает на ключевые моменты через `useMascot().pointAt`. Облик — жёсткий: худое лицо, провалы глазниц,
  клыки и подбородок в крови, плащ тает в темноте. Мультяшность не возвращать (решение владельца: «жёстче
  и реалистичнее», кровь и эффекты — можно).
- Движущиеся части Графа — группы с классами из `Vampire.module.css` (`body`, `cape`, `eyes`, `irises`, `glow`,
  `drip`, `browLeft/Right`, `mouthSmile`, `mouthOpen`, `happyEyes`, `arm`). Ось руки — точка (54, 94.8) в координатах
  рисунка: она записана и в `.arm` (transform-origin), и в сдвиге рисунка руки; высота руки (88px при размере 150)
  — в `MascotDock.jsx`. Меняешь одно — поправь остальное.
- Граф всегда на экране и всё время движется, поэтому тяжёлые фильтры (`g-flesh`, `g-stone`) на него не вешать:
  объём — градиентами, из фильтров только лёгкое свечение глаз (`g-glow`).
- Вся графика на одной странице — «Мастерская художника»: `npm run dev` → `#gallery` (в сборку не попадает).
  После правки рисунка смотри её в обеих темах и размеры 150 / 86 / 52 / 34px.

## Кровь, заголовки и «неожиданности»

- **Крови — в меру.** Решение владельца (11.11.2026): «чуть-чуть поменьше, чтобы не оттеняло само наполнение
  сайта», но ничего не убирать совсем — красная кромка букв в заголовках, рамки и потёки остаются. Без просьбы
  крови не добавляй и не убавляй. Цвета — `--blood`, `--blood-dark`, `--blood-glow` в `variables.css`.
- **Заголовки** страниц — компонент `BloodTitle` (`src/components/BloodTitle/`): буквы «пляшут» (каждая в своём
  `<span>`, расчёт — `letterJitter`), нижняя кромка красная, с части букв свисают потёки (`pickDripLetters`:
  один на пять букв, от двух до шести). Расчёты — `src/utils/bloodDrips.js`, для одного текста результат всегда
  одинаковый. Фильтр неровных краёв `t-rough` и градиент потёков `t-blood` лежат в `GuardianDefs`; на iPhone
  фильтр выключен (Safari размывает текст).
- **Рамки.** Портреты хозяев — в кроваво-красной светящейся рамке (`Guardian.module.css`), на карте пещер рамка
  пульсирует (`CaveMap.module.css`, `.ringWrap::before`).
- **«Неожиданности»** — `src/components/Scares/` (слой и рисунки) и `src/utils/scares.js` (чистая логика: кто,
  когда, по какой траектории). Правила:
  - на экране одна неожиданность за раз; слой не ловит нажатия (`pointer-events: none`), `z-index: 45`;
  - их нет, если игрок выключил их (карта пещер → «Неожиданности», поле `progress.scares`), попросил систему
    уменьшить движение, идёт мини-игра или вкладка скрыта; пока игрок печатает, появление откладывается;
  - новый вид = строка в `SCARE_KINDS` + ветка в `buildScare` + ветка в `ScareView` + звук в `sfx.scare`
    (тесты сами перебирают все виды);
  - на движущихся существах — никаких тяжёлых фильтров (`g-flesh`, `g-stone`), только `g-glow` на глазах и огне;
  - вызвать вручную: кнопки в «Мастерской художника» или событие `props:scare` с полем `detail.kind`.
- **Летучая мышь** (`Bat.jsx`): проп `fierce` — злая, с заревом вокруг глаз. Крыло машет поворотом вокруг плеча
  (`wing-flap` в `Bat.module.css`), а не сплющиванием.

## Свитки Графа (теория)

## Вопросы преподавателя, Кафедра Графа и путеводитель

Решение владельца (12.11.2026): вопросы, которые преподаватель задаёт на занятии (20 вопросов о пропсах, списках и
условном рендеринге и мини-тест из 5; из README домашнего задания берём **только вопросы**), — обязательная часть
игры, **«не для замены, а для дополнения»**. Это игра, а не учебник: к каждому вопросу ведёт путь через пещеры.
Игра шире этих вопросов и будет расти (состояние, тайные ходы на бэкенд и т. д.); тема, без которой вопрос не
понять, — повод для новой пещеры или тайного хода со своим хозяином, анимацией и активными элементами.

- Данные — `src/content/course.js` (`COURSE`): вопрос, ответ «как сказать преподавателю», пример кода, пещера
  (`chapterId`), **путь** (`path` — пещеры от простого к сложному, последняя = `chapterId`) и задание; пять тем
  (`blocks`) с теорией, усиленной там, где в пещерах тема затронута коротко; мастерская (`lab`); хозяин Кафедры
  (`guardian`) и сюжет (`story`). Перевод — накладка `src/content/i18n/<язык>/course.js`.
- Задания собирает `courseTasks` (`src/utils/course.js`): id `hw38-q01…q20` и `hw38-t1…t5`. Их **нет в
  `ALL_TASKS`** (в пещере ровно 8 заданий), но они есть в `TASK_MAP` — испытание и склеп повторения находят их по id.
  К пояснению задания приклеен готовый ответ — игрок видит, как отвечать, даже после ошибки.
- Где вопросы живут в игре: блок «На занятии спросят» (`src/features/course/CaveQuestions.jsx`) — после последней
  карточки урока, на итоге пещеры и в свитке пещеры; Кафедра Графа (`#course`, `#course-q7` — сразу седьмой вопрос)
  с хозяином, теорией, мастерской-опытом (`CrmLab.jsx`, `KeyLab.jsx`: при `key={index}` заметки правда
  «переезжают» к чужим строкам) и тренировкой; узел на карте перед Логовом; карточка в бестиарии.
- **Испытание Графа:** после заданий пещер всегда идут **все** вопросы преподавателя и мини-тест по порядку
  (`buildExam`, `courseSummary` в `src/utils/exam.js`); итог показывает их отдельно со ссылками на ошибки, лучший
  результат — `progress.exam.courseBest`. Хозяин Кафедры повержен с 80% (`COURSE_PASS`).
- Хозяин Кафедры — упырь-архивариус Формуляр: `src/mascot/guardians/art/Archivist.jsx`, ключ `course` в реестре
  хозяев (`courseAsCave` превращает Кафедру в «пещеру» для `CaveNode`, `CaveHost`, бестиария).
- **«Чему научат пещеры»** (`#learn`, `src/features/learn/LearnPage.jsx`, текст — `src/content/learn.js`):
  что игрок будет уметь и оглавление, собранное из самих пещер (темы = заголовки карточек урока, вопросы — по
  `chapterId`). Ссылки — на карте пещер (кнопка в шапке карты) и в «Свитках Графа».
- Тесты — `tests/course.test.js` (путь, темы, задания, испытание, прогресс) и `tests/translation.test.js`.
- Переводы: интерфейс Кафедры — во всех пяти словарях; содержимое — русский и английский. Иврит, испанский и
  французский переведут вместе с уроками этих языков: тест переводов требует от любой накладки сначала «вывеску»
  пещер, сюжет и факты, поэтому накладку с одной Кафедрой не завести.
