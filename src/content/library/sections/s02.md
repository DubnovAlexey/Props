Технически компонент — это функция, а пропсы — её единственный аргумент: объект, который React собирает из атрибутов JSX. Ниже путь пропа от строчки кода до экрана.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| JSX | Расширение синтаксиса JavaScript для описания разметки | «HTML внутри JS». Браузер его не понимает, поэтому перед запуском JSX переводят в обычный JavaScript |
| Транспиляция JSX | Преобразование JSX в вызовы функций `jsx()` или `React.createElement()` | Автоматический перевод JSX на язык, понятный браузеру. Его делают Babel, esbuild, TypeScript, а Vite запускает их за вас |
| React-элемент | Объект `{ type, key, props }`, описывающий одну часть интерфейса | Записка для React: «нарисуй `ProductCard` вот с такими данными». Это ещё не картинка на экране |
| Рендер | Вызов функции-компонента, чтобы получить описание интерфейса | Момент, когда React спрашивает компонент: «Как ты сейчас выглядишь?» |
| DOM | Document Object Model: дерево узлов страницы в браузере | Настоящие теги на странице, которые видит пользователь |
| Виртуальный DOM | Неофициальное название дерева React-элементов | Черновик страницы в памяти, который React сравнивает с прошлым черновиком |
| Согласование (reconciliation) | Алгоритм сравнения нового дерева элементов с предыдущим | React находит разницу между «было» и «стало» и меняет в DOM только её |

### Путь пропа за пять шагов

1. Вы пишете JSX: `<ProductCard name="Молоко" quantity={2} />`.
2. Сборщик переводит JSX в вызов функции. Все атрибуты складываются в один объект: `jsx(ProductCard, { name: 'Молоко', quantity: 2 })`.
3. Вызов возвращает React-элемент: `{ type: ProductCard, key: null, props: { name: 'Молоко', quantity: 2 } }`.
4. Во время рендера React берёт из элемента `type` и `props` и вызывает `ProductCard(props)`.
5. Компонент возвращает новый JSX. React сравнивает его с прошлым результатом и обновляет в DOM только изменения.

::scheme jsx-to-dom

Шаги 1–2 случаются один раз при сборке, а шаги 3–5 повторяются в браузере при каждом рендере.

### Шаг 2 крупным планом: во что превращается JSX

```jsx
// Что пишете вы
const element = <ProductCard name="Молоко" quantity={2} />;
```

```js
// Что получается после сборки (автоматический JSX-runtime, React 17 и новее)
import { jsx } from 'react/jsx-runtime';

const element = jsx(ProductCard, { name: 'Молоко', quantity: 2 });

// Классический вариант того же самого: так было до React 17, и это до сих пор работает
const element2 = React.createElement(ProductCard, { name: 'Молоко', quantity: 2 });
```

Оба варианта получены сборщиком esbuild из одной и той же строки JSX. Атрибуты превратились в ключи объекта: `name="Молоко"` стал `name: 'Молоко'`, а `quantity={2}` стал `quantity: 2`.

### Шаг 3 крупным планом: что внутри React-элемента

```js
console.log(element);
// {
//   $$typeof: Symbol(react.transitional.element), // метка «это настоящий React-элемент»
//   type: ProductCard,                            // ЧТО рисовать: ваша функция
//   key: null,                                    // ключ для списков, см. раздел 9
//   props: { name: 'Молоко', quantity: 2 },       // С ЧЕМ рисовать: пропсы
//   _owner: …, _store: …                          // служебные поля режима разработки
// }
```

- `type` отвечает на вопрос «что рисовать». Для своего компонента это функция, для HTML-тега — строка, например `'div'`.
- `props` отвечает на вопрос «с какими данными рисовать».
- `$$typeof` защищает от подделки. Значение типа Symbol нельзя передать через JSON, поэтому чужие данные с сервера не притворятся элементом.

Вывод получен на React 19.3.1. В режиме разработки объект `props` ещё и заморожен через `Object.freeze`, чтобы его нельзя было случайно изменить. Подробнее в разделе 5.

### Что из этого следует на практике

- **Пропсы — это один объект.** Запись `function ProductCard(name, quantity)` не работает: в `name` придёт весь объект пропсов, а `quantity` окажется `undefined`. Проверено запуском.
- **Имя пропа — это ключ объекта.** Поэтому пропсы называют как переменные JavaScript: `expiryDate`, `onDelete`, `isAdmin`.
- **Содержимое между тегами — тоже проп.** `<Modal title="Ошибка">Текст</Modal>` превращается в `jsx(Modal, { title: 'Ошибка', children: 'Текст' })`. Это проп `children`, ему посвящён раздел 8.
- **`key` в пропсы не попадает.** Сборщик передаёт его отдельным аргументом: `jsx(Card, { name: 'Молоко' }, 'milk')`. Если прочитать `props.key`, React предупредит в консоли и вернёт `undefined`.
- **Имя компонента пишется с большой буквы.** `<ProductCard />` превращается в ссылку на функцию, а `<productCard />` — в строку `'productCard'`. React примет её за неизвестный HTML-тег.

### Эксперимент: компонент — это просто функция

```jsx
// Только для понимания! В приложении компоненты так не вызывают
const result = ProductCard({ name: 'Молоко', quantity: 2 });

console.log(result.type);            // 'div' — компонент вернул описание <div>
console.log(result.props.className); // 'product-card'
```

Вызов сработал, потому что компонент — обычная функция JavaScript. Но в приложении вызывать компонент должен только React. Иначе он не сможет следить за состоянием компонента, его хуками и перерисовками.
