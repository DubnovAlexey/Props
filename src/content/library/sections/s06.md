Пропсы компонент получает снаружи и только читает, а состояние хранит сам и может менять. Состояние одного компонента очень часто становится пропсами его детей.

### Простыми словами

Документация React сравнивает пропсы с аргументами функции, а состояние — с памятью компонента. Аналогия из жизни: состояние — ваш собственный холодильник, вы сами кладёте и достаёте продукты.

Пропсы — записка от соседа «возьми молоко». Её можно прочитать и выполнить, но переписывать бессмысленно: у соседа останется свой экземпляр.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| Состояние (state) | Данные, которые компонент хранит между рендерами и меняет через сеттер | Память компонента |
| Хук (hook) | Специальная функция React, имя которой начинается с `use` | «Крючок», которым компонент цепляется за возможности React |
| `useState` | Хук, который создаёт переменную состояния и функцию для её изменения | «Дай мне ячейку памяти и кнопку, чтобы её менять» |
| Сеттер (set-функция) | Функция вида `setProducts`, которая заменяет значение состояния и запускает перерисовку | Кнопка «сохранить новое значение и обновить экран» |
| Перерисовка (re-render) | Повторный вызов функции-компонента с новыми данными | Компонент «перефотографировали» со свежими данными |
| Производное значение | Значение, которое можно вычислить из пропсов или состояния | Не хранится отдельно, а посчитывается на лету |

### Сравнение пропсов и состояния

| Вопрос | Пропсы | Состояние |
| --- | --- | --- |
| Откуда берутся | Их передаёт родитель | Компонент создаёт сам через `useState` |
| Кто может изменить | Только родитель, передав новые значения | Только сам компонент, через сеттер |
| Можно ли присвоить напрямую | Нет | Нет: только через сеттер |
| Что запускает перерисовку | Перерисовка родителя | Вызов сеттера с новым значением |
| Аналогия | Аргументы функции | Память компонента |
| Пример из холодильника | `product` у `ProductCard` | `products` у `App` |

### Одни и те же данные: состояние для одного, пропсы для другого

```jsx
import { useState } from 'react';

function App() {
  // СОСТОЯНИЕ App: список продуктов живёт здесь
  const [products, setProducts] = useState([
    { id: 1, name: 'Молоко', quantity: 2 },
    { id: 2, name: 'Яйца', quantity: 10 },
  ]);

  return (
    <main>
      {/* Состояние App становится ПРОПСАМИ детей */}
      <FridgeSummary count={products.length} />
      <ProductList products={products} />
    </main>
  );
}

function FridgeSummary({ count }) {
  // Для FridgeSummary count — это пропс: читаем и показываем
  return <p>Продуктов в холодильнике: {count}</p>;
}
```

Для `App` массив `products` — состояние: он его создал и может менять через `setProducts`. Для `ProductList` тот же массив — пропсы, их можно только читать. Роль данных зависит от того, чей компонент на них смотрит.

### Цикл перерисовки

1. Пользователь нажимает кнопку.
2. Обработчик вызывает сеттер, например `setProducts(newProducts)`.
3. React запоминает новое состояние и снова вызывает компонент-владелец состояния.
4. Компонент возвращает JSX с новыми значениями пропсов для детей.
5. React вызывает детей с новыми пропсами и обновляет в DOM только те места, что изменились.

::scheme rerender

Подсвечен шаг, который запускает весь круг: без вызова сеттера новых пропсов не будет.

### Важная деталь: дети перерисовываются вместе с родителем

По умолчанию React перерисовывает всех детей вместе с родителем, даже тех, чьи пропсы не изменились. В проверочном запуске ребёнок с постоянным пропом `label` перерисовался после клика по кнопке родителя.

Обычно это не проблема: в DOM React всё равно меняет только реальные отличия. Как пропустить лишние перерисовки, когда они действительно мешают, рассказано в разделе 10.

### Ловушка: копирование пропа в состояние

```jsx
// ПЛОХО: состояние «запоминает» проп только на первом рендере
function ProductCard({ quantity }) {
  const [qty, setQty] = useState(quantity);
  return <p>{qty} шт.</p>;
}
```

Аргумент `useState(quantity)` используется только один раз, при первом рендере. В проверочном запуске родитель сначала передал `quantity={2}`, потом `quantity={1}`. Проп стал 1, а на экране осталось 2.

```jsx
// ХОРОШО: читаем проп напрямую, а производное значение вычисляем при рендере
function ProductCard({ quantity }) {
  const isRunningOut = quantity <= 1; // пересчитывается при каждом рендере
  return <p>{quantity} шт.{isRunningOut ? ' — пора докупить' : ''}</p>;
}

// Если нужно именно НАЧАЛЬНОЕ значение, скажите об этом в имени пропа
function QuantityEditor({ initialQuantity }) {
  const [quantity, setQuantity] = useState(initialQuantity);
  // дальше компонент сам управляет quantity, новые initialQuantity игнорирует
  return <input type="number" value={quantity} onChange={(e) => setQuantity(Number(e.target.value))} />;
}
```

Приставка `initial` честно предупреждает того, кто будет использовать компонент: позже переданные значения учитываться не будут.

### Где хранить данные: три вопроса

1. Можно ли вычислить значение из пропсов или другого состояния? Если да — не храните его, вычисляйте при рендере.
2. Меняется ли оно со временем и нужно ли только одному компоненту? Если да — это состояние этого компонента.
3. Нужно ли оно нескольким компонентам? Если да — храните в их общем родителе, а детям передавайте пропсами. Это подъём состояния из раздела 7.
