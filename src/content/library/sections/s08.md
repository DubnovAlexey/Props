Всё, что стоит между открывающим и закрывающим тегом компонента, приходит в него как проп `children`. Так строят обёртки — карточки, модальные окна, раскладки страницы, — которые не знают заранее, что окажется внутри.

### Простыми словами

Документация React называет `children` «дыркой», которую родитель заполняет любым содержимым. Бытовая аналогия — рамка для фотографий: рамка одна, а фотографии в ней разные. Рамка отвечает за оформление и не задумывается, что изображено на снимке.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| Композиция (composition) | Построение интерфейса вложением одних компонентов в другие | Сборка интерфейса из деталей, как из конструктора |
| `children` | Особый проп с содержимым между тегами компонента | «Начинка» компонента |
| Обёртка (wrapper) | Компонент, который добавляет оформление или поведение вокруг чужого содержимого | Рамка вокруг картины |
| Слот (slot) | Именованное место в компоненте, куда родитель вставляет разметку через проп | Подписанная ячейка: «сюда заголовок, сюда кнопки» |
| ReactNode | Всё, что React умеет отрисовать: строка, число, элемент, массив, `null`, `undefined`, `true` и `false` | Любое содержимое, которое можно положить в JSX |
| Портал (portal) | Отрисовка детей в другой DOM-узел через `createPortal` | Телепорт: компонент живёт в одном месте дерева, а виден в другом месте страницы |

### Как это устроено технически

`children` — обычный ключ объекта пропсов, просто его заполняет сборщик. Запись `<Modal title="Ошибка">Текст</Modal>` превращается в `jsx(Modal, { title: 'Ошибка', children: 'Текст' })`. Форма значения зависит от того, что стоит между тегами:

| Что между тегами | Что придёт в `children` |
| --- | --- |
| Текст: `<Card>Текст</Card>` | строка |
| Один тег: `<Card><b /></Card>` | один React-элемент |
| Несколько тегов: `<Card><b /><b /></Card>` | массив из двух элементов |
| Ничего: `<Card />` | `undefined` |

Все четыре случая проверены запуском. Вывод: не стройте логику на форме `children`. Если компоненту нужно что-то посчитать или перебрать, передайте ему массив данных обычным пропом.

### Пример 1. Карточка-обёртка

```jsx
function Card({ title, children }) {
  return (
    <section className="card">
      <h2 className="card-title">{title}</h2>
      <div className="card-body">{children}</div> {/* сюда встанет всё, что передали */}
    </section>
  );
}

function FridgeDashboard() {
  return (
    <>
      <Card title="Скоро истекает срок">
        <p>Молоко — до 13 ноября</p>
        <p>Йогурт — до 14 ноября</p>
      </Card>

      <Card title="Совет шефа">
        <p>Из молока и яиц выйдет омлет.</p>
      </Card>
    </>
  );
}
```

Пустые теги `<>` и `</>` — это **фрагмент**: обёртка, которая группирует элементы и не добавляет лишнего тега в DOM. Первая карточка в проверочном запуске превратилась в такой HTML:

```html
<section class="card">
  <h2 class="card-title">Скоро истекает срок</h2>
  <div class="card-body"><p>Молоко — до 13 ноября</p><p>Йогурт — до 14 ноября</p></div>
</section>
```

### Пример 2. Модальное окно для ошибок «Умного холодильника»

В вашем проекте есть требование: ошибки показывать пользователю в модальном окне, а не в консоли. Идеальный случай для `children`: окно одно, а тексты ошибок разные.

```jsx
import { useState } from 'react';

// Рамка: заголовок, кнопка и «дырка» для содержимого
function ErrorModal({ isOpen, title = 'Ошибка', onClose, children }) {
  if (!isOpen) return null; // окно закрыто — ничего не рисуем

  return (
    <div className="modal-backdrop" onClick={onClose}>
      <div
        className="modal"
        role="dialog"
        aria-modal="true"
        aria-label={title}
        onClick={(e) => e.stopPropagation()} // клик внутри окна не доходит до фона
      >
        <h2>{title}</h2>
        <div className="modal-body">{children}</div>
        <button onClick={onClose}>Понятно</button>
      </div>
    </div>
  );
}

// Использование: родитель решает, КОГДА показать окно и ЧТО в нём написать
function App() {
  const [error, setError] = useState(null);

  function handleSearch({ username, dish }) {
    if (!username || !dish) {
      setError('Введите имя пользователя и название блюда.');
      return;
    }
    // ... запрос к AI-шефу; при неудаче: setError('AI-шеф не ответил. Попробуйте ещё раз.')
  }

  return (
    <>
      <SearchForm onSearch={handleSearch} />
      <ErrorModal isOpen={error !== null} onClose={() => setError(null)}>
        <p>{error}</p>
      </ErrorModal>
    </>
  );
}
```

Разбор пропсов `ErrorModal`:

- `isOpen` — логический проп: показывать окно или нет. Окно не хранит это знание само, им управляет родитель.
- `title` — строка со значением по умолчанию `'Ошибка'`.
- `onClose` — проп-событие: окно сообщает «меня хотят закрыть», а родитель очищает `error`.
- `children` — текст ошибки или любая другая разметка. То же окно подойдёт для сообщения «У роли GUEST нет доступа».

Поведение проверено запуском в эмуляции браузера. Окно открывается при ошибке и не закрывается от клика по тексту. Закрывается оно от клика по тёмному фону или по кнопке «Понятно».

::diagram modal

Проп `children` — это «дырка» в рамке: родитель кладёт туда любой текст или элементы, а само окно не знает, что именно в ней лежит.

В реальных приложениях модальное окно часто рисуют через портал — `createPortal(…, document.body)`. Тогда его не обрежут стили родительских блоков. На работу с пропсами это не влияет: `isOpen`, `onClose` и `children` остаются теми же.

### Пример 3. Несколько «дырок»: слоты через обычные пропсы

```jsx
// Раскладка страницы: четыре места для содержимого
function PageLayout({ header, sidebar, children, footer }) {
  return (
    <div className="layout">
      <header>{header}</header>
      <aside>{sidebar}</aside>
      <main>{children}</main>
      <footer>{footer}</footer>
    </div>
  );
}

<PageLayout
  header={<h1>Умный холодильник</h1>}
  sidebar={<CategoryFilter />}
  footer={<small>Данные обновлены сегодня</small>}
>
  <ProductList products={products} />
</PageLayout>
```

`children` — главный слот, остальные слоты — обычные пропсы со значением-JSX. Раскладка отвечает за расстановку, а что именно стоит в каждом месте, решает родитель.

### Почему композиция лучше «универсального компонента с флажками»

```jsx
// ПЛОХО: окно обязано знать обо всех своих вариантах
<Modal type="error" showRetryButton showIcon iconName="warning" text="AI-шеф не ответил" />

// ХОРОШО: окно даёт рамку, а содержимое собирает родитель
<ErrorModal isOpen onClose={close}>
  <WarningIcon />
  <p>AI-шеф не ответил</p>
  <RetryButton onRetry={retry} />
</ErrorModal>
```

В первом варианте каждый новый случай добавляет флажок, и компонент растёт без конца. Во втором окно не меняется, а разнообразие даёт содержимое. Композиция ещё и спасает от протаскивания пропсов через много уровней, об этом раздел 12.

### Тонкости

- `children` можно показать по условию: `{isOpen && children}`.
- Значения `null`, `undefined`, `true` и `false` в разметке ничего не рисуют. Число `0` рисует, и это частая ловушка из раздела 16.
- В React есть утилиты `Children.map` и `Children.count` для разбора `children`. Документация React считает их редко нужными: такой код легко ломается. Обычно лучше передать массив данных.
