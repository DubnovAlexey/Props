Почти все пропсы — это ваши данные, но у нескольких имён особая роль. `key` React забирает себе, чтобы различать элементы списка, `ref` даёт доступ к DOM-узлу, а пропсы встроенных тегов вроде `<input>` подчиняются правилам браузера.

### Списки: из массива данных — в массив компонентов

```jsx
function ProductList({ products }) {
  return (
    <ul>
      {products.map((product) => (
        <ProductCard key={product.id} product={product} />
      ))}
    </ul>
  );
}
```

Метод `map` превращает массив данных в массив React-элементов: один продукт — одна карточка. Это та же функция высшего порядка, что в ваших заданиях по JavaScript. Каждому элементу списка нужен проп `key`.

### key — «номерок» элемента списка

**key** (ключ) — уникальная среди соседей строка или число. По ключу React узнаёт элемент между рендерами.

Простыми словами: представьте гардероб. Номерок привязан к пальто, а не к крючку, поэтому перевешенное пальто всё равно найдут. Ключ — такой номерок для компонента, а индекс в массиве — номер крючка.

Эксперимент. В каждой строке списка есть поле для заметки со своим состоянием. В строку «Молоко» ввели «купить ещё», затем в начало списка добавили «Хлеб».

| Что стояло в key | До добавления | После добавления хлеба |
| --- | --- | --- |
| Индекс `i` | Молоко \[купить ещё], Яйца \[ ] | Хлеб \[купить ещё], Молоко \[ ], Яйца \[ ] |
| `product.id` | Молоко \[купить ещё], Яйца \[ ] | Хлеб \[ ], Молоко \[купить ещё], Яйца \[ ] |

С индексом заметка «переехала» к хлебу: React увидел элемент с ключом 0 и решил, что это прежняя строка. С `id` заметка осталась у молока. Результат получен в эмуляции браузера.

Правила для key:

- Ключ уникален среди соседей в одном списке. В разных списках ключи могут повторяться.
- Ключ стабилен: у одного и того же продукта он не меняется между рендерами. Лучше всего подходит id из базы или файла, например из вашего `fridge.json`.
- `Math.random()` в роли ключа — ошибка: на каждом рендере ключи новые, и React пересоздаёт все элементы заново.
- Индекс допустим, только если список никогда не сортируют, не фильтруют и не дополняют в начале или середине.
- `key` ставят на самый внешний элемент внутри `map`, то есть на `<ProductCard key={…} />`, а не внутри самой карточки.
- Если ключ забыли, React предупредит в консоли: «Each child in a list should have a unique "key" prop».

### key не попадает в пропсы

```jsx
// ПЛОХО: внутри компонента key всегда undefined, а React выдаст предупреждение
function ProductCard({ key, product }) { /* ... */ }

// ХОРОШО: если id нужен внутри, передайте его отдельным пропом
<ProductCard key={product.id} productId={product.id} product={product} />
```

В разделе 2 это проверено запуском: React вернул `undefined` и сообщил «`key` is not a prop».

### Бонус: смена key сбрасывает компонент

Новый ключ для React означает новый компонент: старый удаляется вместе со своим состоянием. Это удобно с редактором из раздела 6:

```jsx
// При выборе другого продукта редактор создаётся заново и берёт свежее initialQuantity
<QuantityEditor key={selected.id} initialQuantity={selected.quantity} />
```

### ref как проп (React 19)

**ref** (ссылка) — объект `{ current: … }`, который React заполняет DOM-узлом. Простыми словами: закладка на конкретный элемент страницы, чтобы потом, например, поставить в него курсор.

Начиная с React 19 функциональный компонент получает `ref` как обычный проп. Раньше для этого требовалась обёртка `forwardRef`.

```jsx
import { useRef } from 'react';

// React 19: ref приходит вместе с остальными пропсами
function SearchInput({ ref, ...rest }) {
  return <input ref={ref} className="search-input" {...rest} />;
}

function SearchForm() {
  const dishRef = useRef(null); // сюда React положит DOM-узел <input>

  function handleSubmit(e) {
    e.preventDefault();
    if (!dishRef.current.value.trim()) {
      dishRef.current.focus(); // поле пустое — ставим в него курсор
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <SearchInput ref={dishRef} placeholder="Название блюда" />
      <button>Искать</button>
    </form>
  );
}
```

```jsx
// До React 19 то же самое писали так. Это всё ещё работает, но уже не нужно
import { forwardRef } from 'react';

const SearchInput = forwardRef(function SearchInput(props, ref) {
  return <input ref={ref} className="search-input" {...props} />;
});
```

В эмуляции браузера на React 19.3.1 проверены три факта. `SearchInput` получил `ref` в пропсах, и отправка пустой формы поставила курсор в поле. Запись `{...props}` теперь передаёт дальше и `ref`. Старый `forwardRef` тоже по-прежнему работает.

### Пропсы встроенных HTML-элементов

У тегов `<div>`, `<input>`, `<button>` набор пропсов задан заранее и почти совпадает с атрибутами HTML. Отличий немного, и все они объяснимы:

| В HTML | В React | Почему так |
| --- | --- | --- |
| `class="card"` | `className="card"` | `class` — зарезервированное слово JavaScript |
| `for="dish"` | `htmlFor="dish"` | `for` — тоже слово JavaScript |
| `onclick="go()"` (строка) | `onClick={go}` (функция) | События пишутся в camelCase и принимают функцию |
| `style="background-color: red"` | `style={{ backgroundColor: 'red' }}` | Стиль — объект, свойства в camelCase |
| `tabindex="2"` | `tabIndex={2}` | Имена атрибутов в camelCase |
| `aria-label`, `data-role` | так же, с дефисами | Исключение: `aria-*` и `data-*` пишутся как в HTML |

**camelCase** — способ записи, где слова идут слитно, а каждое следующее начинается с большой буквы: `backgroundColor`, `tabIndex`. Вот что React сделал с такими пропсами в проверочном запуске:

```jsx
<label htmlFor="dish" className="label">Блюдо</label>
<input id="dish" tabIndex={2} aria-label="Название блюда" data-role="dish" />
<p style={{ backgroundColor: 'red', fontSize: 14, zIndex: 2 }}>Просрочено</p>
```

```html
<label for="dish" class="label">Блюдо</label>
<input id="dish" tabindex="2" aria-label="Название блюда" data-role="dish"/>
<p style="background-color:red;font-size:14px;z-index:2">Просрочено</p>
```

Число 14 в `fontSize` React сам дополнил единицей `px`. У свойств без единиц, вроде `zIndex`, число осталось как есть.

### Свои компоненты — не HTML-теги

У вашего компонента нет «встроенных» атрибутов. `<ProductCard className="highlight" />` не добавит класс сам по себе: это просто проп, и компонент должен сам передать его своему тегу. В проверочном запуске компонент без пересылки вернул `<p>Молоко</p>` без всякого класса.

Обратная ошибка — случайно отдать свой проп HTML-тегу через `{...rest}`. На `<div isActive>` React выдал предупреждение «React does not recognize the `isActive` prop on a DOM element». Лечение — забрать свои пропсы до того, как раскладывать остальное:

```jsx
function ProductCard({ isActive, className = '', children, ...rest }) {
  // isActive забрали себе, в <div> уходит только то, что он понимает
  const classes = ['card', isActive && 'card--active', className].filter(Boolean).join(' ');
  return (
    <div className={classes} {...rest}>
      {children}
    </div>
  );
}
```
