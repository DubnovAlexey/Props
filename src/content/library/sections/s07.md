Ребёнок не может изменить данные родителя, но может сообщить ему о событии. Для этого родитель передаёт в пропсах функцию, а ребёнок вызывает её в нужный момент. Коротко: данные идут вниз, события — вверх.

### Простыми словами

Родитель даёт ребёнку пульт с одной кнопкой. Ребёнок не знает, что именно делает кнопка: он нажимает её в нужный момент и сообщает подробности, например «удалить продукт номер 7». Что сделать с этим сообщением, решает родитель.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| Колбэк (callback) | Функция, которую передают другой функции или компоненту, чтобы тот вызвал её позже | «Перезвони мне, когда что-то случится». Вы уже встречали колбэки в функциях высшего порядка |
| Обработчик события (event handler) | Функция, которую React вызывает в ответ на действие пользователя | Реакция на клик, ввод текста или отправку формы |
| Проп-событие | Проп-функция с именем на `on`: `onDelete`, `onSearch` | Канал, по которому ребёнок сообщает родителю о событии |
| Подъём состояния (lifting state up) | Перенос состояния из детей в их ближайшего общего родителя | Вместо двух холодильников в разных комнатах — один на общей кухне |
| Единый источник истины | Каждое значение хранится ровно в одном месте | У данных один хозяин, остальные получают их через пропсы |

### Соглашение об именах

| Что называем | Правило | Примеры |
| --- | --- | --- |
| Проп-функцию, которую получает ребёнок | `on` + событие с большой буквы | `onDelete`, `onSearch`, `onCardPlay` |
| Функцию-обработчик в родителе | `handle` + событие | `handleDelete`, `handleSearch` |

Такие имена рекомендует документация React ([источник](https://react.dev/learn/responding-to-events)). Называйте пропсы по смыслу события в приложении (`onDelete`), а не по действию мышью (`onButtonClick`). Тогда тот же проп потом можно будет вызвать и с клавиатуры.

### Схема: данные вниз, события вверх

::diagram flow

Сплошная стрелка — пропсы, которые идут вниз; пунктир — вызов функции, который идёт вверх.

### Пример 1. Удаление продукта

```jsx
import { useState } from 'react';

// Ребёнок: показывает продукт и СООБЩАЕТ о желании его удалить
function ProductCard({ product, onDelete }) {
  return (
    <li>
      {product.name} — {product.quantity} шт.
      <button onClick={() => onDelete(product.id)}>Удалить</button>
    </li>
  );
}

// Родитель: хранит список и РЕШАЕТ, что значит «удалить»
function ProductList() {
  const [products, setProducts] = useState([
    { id: 1, name: 'Молоко', quantity: 2 },
    { id: 7, name: 'Яйца', quantity: 10 },
    { id: 9, name: 'Сыр', quantity: 1 },
  ]);

  function handleDelete(id) {
    setProducts(products.filter((p) => p.id !== id)); // новый массив без удалённого
  }

  return (
    <ul>
      {products.map((p) => (
        <ProductCard key={p.id} product={p} onDelete={handleDelete} />
      ))}
    </ul>
  );
}
```

Что происходит после клика по «Удалить» у яиц:

1. `ProductList` заранее передал функцию `handleDelete` под именем `onDelete`.
2. Клик запускает стрелочную функцию, и она вызывает `onDelete(7)`.
3. На самом деле выполняется `handleDelete(7)`: родитель создаёт массив без яиц и вызывает `setProducts`.
4. React перерисовывает список. В проверочном запуске до клика было «Молоко, Яйца, Сыр», после — «Молоко, Сыр».

### Типичная ошибка: вызов вместо передачи

```jsx
<button onClick={onDelete(product.id)}>Удалить</button>       // ОШИБКА
<button onClick={() => onDelete(product.id)}>Удалить</button> // ПРАВИЛЬНО
```

В первой строке `onDelete` вызывается сразу, во время рендера. В проверочном запуске все три продукта удалились сами, без единого клика. React при этом предупредил: «Cannot update a component while rendering a different component».

Стрелочная функция во второй строке откладывает вызов до клика. Правило простое: во время рендера функции-пропсы не вызывают, их вызывают только из обработчиков событий.

### Пример 2. Подъём состояния: поиск по холодильнику

Задача: поле поиска `SearchBar` и список `ProductList` должны знать один и тот же текст запроса. Это соседи, а соседи не могут передавать друг другу пропсы напрямую. Решение: поднять состояние `query` в их общего родителя `FridgePage`.

::diagram lifting

После подъёма оба ребёнка получают данные из одного места, а поле поиска сообщает о новом тексте через `onQueryChange`.

```jsx
import { useState } from 'react';

// Поле поиска: само ничего не хранит, всё получает от родителя
function SearchBar({ query, onQueryChange }) {
  return (
    <input
      value={query}                                   // значение пришло сверху
      onChange={(e) => onQueryChange(e.target.value)} // событие ушло наверх
      placeholder="Найти продукт"
    />
  );
}

// Список: показывает только то, что дали
function ProductList({ products }) {
  if (products.length === 0) return <p>Ничего не найдено</p>;
  return (
    <ul>
      {products.map((p) => <li key={p.id}>{p.name}</li>)}
    </ul>
  );
}

// Общий родитель — единственный владелец query
function FridgePage({ products }) {
  const [query, setQuery] = useState('');

  // производное значение: вычисляем при рендере, а не храним
  const visible = products.filter((p) =>
    p.name.toLowerCase().includes(query.toLowerCase())
  );

  return (
    <section>
      <SearchBar query={query} onQueryChange={setQuery} />
      <ProductList products={visible} />
    </section>
  );
}
```

Результат проверочного запуска на продуктах «Молоко», «Яйца», «Сыр»:

| Ввели в поле | Показал список |
| --- | --- |
| `мол` | Молоко |
| `ы` | Сыр |
| `хлеб` | Ничего не найдено |
| пустая строка | Молоко, Яйца, Сыр |

Запись `onQueryChange={setQuery}` передаёт сеттер напрямую, и это нормально. Если позже понадобится дополнительная логика, её добавят в родительский `handleQueryChange`, а `SearchBar` менять не придётся.

### Как передать данные вместе с событием

- **Один аргумент:** `onDelete(product.id)`.
- **Несколько значений:** удобнее один объект, например `onSearch({ username, dish })`. Порядок не важен, а имена полей объясняют сами себя.
- **Перевод DOM-события в данные:** ребёнок достаёт `e.target.value` и отдаёт наверх простой текст. Родителю не нужно знать, что внутри был именно `<input>`.
