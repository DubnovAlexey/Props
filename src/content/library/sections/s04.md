Компонент получает все пропсы одним объектом. Читать его можно через точку (`props.name`) или сразу распаковать на отдельные переменные деструктуризацией — так пишут чаще всего.

### Способ 1. Объект props целиком

```jsx
function ProductCard(props) {
  return (
    <h3>
      {props.name} — {props.quantity} {props.unit}
    </h3>
  );
}
```

Удобно, когда пропсов мало или объект нужно целиком передать дальше. Минус: по первой строке функции не видно, какие пропсы компонент ожидает.

### Способ 2. Деструктуризация прямо в параметрах

**Деструктуризация** — синтаксис JavaScript, который достаёт поля объекта в отдельные переменные. Простыми словами: распаковать коробку и разложить вещи по полкам.

```jsx
// Распаковываем пропсы прямо в скобках параметров
function ProductCard({ name, quantity, unit }) {
  return (
    <h3>
      {name} — {quantity} {unit}
    </h3>
  );
}
```

Это ровно то же самое, что:

```jsx
function ProductCard(props) {
  const { name, quantity, unit } = props; // та же деструктуризация, но отдельной строкой
  // ...
}
```

Этот способ считается стандартным в документации React. Список пропсов виден сразу, как список параметров у обычной функции.

Частая ошибка — забыть фигурные скобки:

```jsx
function ProductCard(name) { // ОШИБКА: нет { }
  return <h3>{name}</h3>;    // name — это весь объект { name: 'Молоко' }
}
```

В проверочном запуске React упал с ошибкой «Objects are not valid as a React child (found: object with keys {name})». Смысл: объект нельзя вывести на экран как текст.

### Значения по умолчанию

```jsx
function ProductCard({ name, quantity = 1, unit = 'шт.' }) {
  return <p>{name}: {quantity} {unit}</p>;
}
```

`quantity = 1` читается так: «если `quantity` не передали, считай его равным 1». Срабатывает оно только для `undefined`:

| Что передал родитель | Что получит компонент |
| --- | --- |
| Ничего: `<ProductCard name="Молоко" />` | `1` |
| `quantity={undefined}` | `1` |
| `quantity={null}` | `null` — значение по умолчанию не сработало |
| `quantity={0}` | `0` — ноль тоже настоящее значение |

Все четыре строки проверены запуском. Если нужно подменять и `null`, поможет оператор `??` («объединение с null»): `const q = quantity ?? 1;` подставит 1 и для `null`, и для `undefined`.

Раньше значения по умолчанию задавали так: `ProductCard.defaultProps = { quantity: 1 }`. В React 19 для функциональных компонентов это убрали: запись молча игнорируется, и в проверочном запуске компонент получил `undefined`. Подробнее в разделе 11.

### Переименование при распаковке

```jsx
// Проп называется name, а внутри компонента удобнее playerName
function PlayerSeat({ name: playerName, isDealer }) {
  return <p>{playerName}{isDealer ? ' (сдаёт)' : ''}</p>;
}
```

Запись `name: playerName` значит «возьми поле `name` и положи в переменную `playerName`». Слева от двоеточия — имя пропа, справа — имя переменной.

### Вложенная деструктуризация

```jsx
// expiry = { date: '2026-11-13', daysLeft: 3 }
function ExpiryBadge({ expiry: { date, daysLeft } = {} }) {
  if (!date) return <span>Срок не указан</span>;
  return <span>До {date}, осталось {daysLeft} дн.</span>;
}
```

Хвост `= {}` защищает от падения. Без него `<ExpiryBadge />` без пропа `expiry` падает с ошибкой «Cannot read properties of undefined (reading 'date')». Проверено запуском.

### Остаточные пропсы: ...rest

**Rest-синтаксис** `...rest` собирает в один объект всё, что вы не распаковали по имени. Простыми словами: «всё остальное — в этот пакет».

```jsx
// Своя кнопка для холодильника: сама знает только variant, остальное отдаёт <button>
function FridgeButton({ variant = 'primary', ...rest }) {
  // rest = { disabled: true, title: 'Удалить продукт', children: 'Удалить' }
  return <button className={`btn btn-${variant}`} {...rest} />;
}

<FridgeButton variant="danger" disabled title="Удалить продукт">
  Удалить
</FridgeButton>
// Результат: <button class="btn btn-danger" disabled="" title="Удалить продукт">Удалить</button>
```

В параметрах `...rest` собирает пропсы в объект, а в JSX `{...rest}` снова раскладывает их на атрибуты. Так устроены обёртки над HTML-элементами: им не нужно перечислять все возможные атрибуты кнопки. Результат в комментарии получен запуском.

### Классовые компоненты: this.props

В старом коде встречаются компоненты-классы. Пропсы там лежат в `this.props`:

```jsx
import { Component } from 'react';

class ProductCard extends Component {
  static defaultProps = { quantity: 1 }; // у классов defaultProps работает и в React 19

  render() {
    const { name, quantity } = this.props; // пропсы читаются из this.props
    return <p>{name}: {quantity}</p>;
  }
}
```

Новый код пишут на функциях. Классы стоит уметь читать: они ещё встречаются в старых проектах и статьях.

### Какой способ выбрать

| Способ | Запись | Когда использовать |
| --- | --- | --- |
| Деструктуризация | `function Card({ name, quantity })` | По умолчанию, почти всегда |
| Значения по умолчанию | `{ quantity = 1 }` | Для необязательных пропсов |
| Объект целиком | `function Card(props)` | Пропсов мало или объект нужно передать дальше |
| Переименование | `{ name: playerName }` | Имя пропа неудобно или конфликтует с переменной |
| Остаточные пропсы | `{ variant, ...rest }` | Обёртки над HTML-элементами и чужими компонентами |
| `this.props` | `class Card extends Component` | Только для чтения старого кода |
