Almost all mistakes with props come down to three causes: the wrong type was passed, someone else’s data was changed, or a reference was confused with a call. Every mistake below was reproduced by running it on React 19.3.1, and the texts of the messages were taken from the console.

### A summary table

| No. | Mistake | Symptom | Section |
| --- | --- | --- | --- |
| 1 | A number in quotes: `quantity="2"` | `quantity + 1` gives `"21"` | 3 |
| 2 | The `{ }` in the parameters were forgotten: `function Card(name)` | “Objects are not valid as a React child” | 4 |
| 3 | A prop was assigned: `props.quantity = 1` | “Cannot assign to read only property”; silently in production | 5 |
| 4 | An object from the props was changed: `product.quantity -= 1` | No error, but the parent’s data is spoiled | 5 |
| 5 | A function was called instead of passed: `onClick={onDelete(id)}` | Deletion without a click and “Cannot update a component while rendering a different component” | 7 |
| 6 | A prop was copied into state: `useState(quantity)` | The new value from the parent is not shown | 6 |
| 7 | An index as the key in a changing list | The state “moves” to the neighbouring item | 9 |
| 8 | Reading `props.key` inside a component | `undefined` and “`key` is not a prop” | 2, 9 |
| 9 | `{quantity && …}` with zero | A “0” appears on the screen | 13 |
| 10 | `class` and `for` instead of `className` and `htmlFor` | “Invalid DOM property `class`. Did you mean `className`?” | 9 |
| 11 | Your own prop went into an HTML tag through `{...rest}` | “React does not recognize the `isActive` prop on a DOM element” | 9 |
| 12 | The name of a component with a lowercase letter: `<productCard />` | An empty `<productcard>` tag appears in the DOM | 2 |
| 13 | `defaultProps` on a function component | In React 19 the value is not substituted | 4, 11 |
| 14 | New objects and functions in the props of a memo component | `memo` does not work | 10 |
| 15 | `value` without `onChange` | The field is read-only and there is a warning in the console | 13 |

### 1. A number in quotes

```jsx
<ProductCard quantity="2" />  // WRONG: the string '2' arrives
<ProductCard quantity={2} />  // RIGHT: the number 2 arrives
```

### 2. The curly braces of destructuring were forgotten

```jsx
function ProductCard(name) { return <h3>{name}</h3>; }    // WRONG: name is the whole props object
function ProductCard({ name }) { return <h3>{name}</h3>; }  // RIGHT
```

### 3–4. Changing props and the objects inside them

```jsx
// WRONG: the child changes someone else’s data
function ProductCard({ product }) {
  product.quantity -= 1;
  return <p>{product.quantity}</p>;
}

// RIGHT: the child asks, the parent creates a new object
function ProductCard({ product, onEat }) {
  return <button onClick={() => onEat(product.id)}>Eat one</button>;
}
// in the parent: setProducts(products.map((p) => p.id === id ? { ...p, quantity: p.quantity - 1 } : p))
```

### 5. A call instead of passing

```jsx
<button onClick={onDelete(product.id)}>Delete</button>       // WRONG: fires during render
<button onClick={() => onDelete(product.id)}>Delete</button> // RIGHT: fires on a click
<button onClick={onDelete}>Delete</button>                  // also right, if no argument is needed
```

### 6. Copying a prop into state

```jsx
function ProductCard({ quantity }) {
  const [qty] = useState(quantity); // WRONG: remembers only the first value
  return <p>{qty}</p>;
}

function ProductCard({ quantity }) {
  return <p>{quantity}</p>;        // RIGHT: we read the prop directly
}
```

### 7–8. The keys of a list

```jsx
{products.map((p, i) => <ProductRow key={i} product={p} />)}    // WRONG, if the list changes
{products.map((p) => <ProductRow key={p.id} product={p} />)}    // RIGHT

<ProductRow key={p.id} productId={p.id} product={p} />           // the id is needed inside — in a separate prop
```

### 9. Zero with the && operator

```jsx
{product.quantity && <span>{product.quantity} pcs</span>}     // WRONG: with 0 it prints “0”
{product.quantity > 0 && <span>{product.quantity} pcs</span>} // RIGHT
```

### 10–12. Names: HTML attributes and components

```jsx
<label class="label" for="dish">Dish</label>          // WRONG: works, but with warnings
<label className="label" htmlFor="dish">Dish</label>  // RIGHT

function Card({ isActive, ...rest }) {                 // RIGHT: our own prop was taken before the spread
  return <div className={isActive ? 'card active' : 'card'} {...rest} />;
}

<productCard />  // WRONG: React takes this for an HTML tag
<ProductCard />  // RIGHT
```

On `<productCard />` React printed two warnings. The first: “is using incorrect casing. Use PascalCase for React components”. The second: “If you meant to render a React component, start its name with an uppercase letter”. **PascalCase** is a way of writing in which every word, the first one included, starts with a capital letter: `ProductCard`.

### 13. defaultProps in React 19

```jsx
function Badge({ size }) { /* ... */ }
Badge.defaultProps = { size: 100 };       // WRONG: ignored in React 19

function Badge({ size = 100 }) { /* ... */ } // RIGHT
```

### 14. memo and new references

```jsx
<MemoCard product={{ ...p }} onDelete={() => remove(p.id)} /> // WRONG: everything is new on every render
<MemoCard product={p} onDelete={handleDelete} />               // RIGHT: p from state, handleDelete from useCallback
```

### 15. value without onChange

```jsx
<input value={dish} />                                              // WRONG: the field cannot be edited
<input value={dish} onChange={(e) => setDish(e.target.value)} />  // RIGHT: a controlled field
<input defaultValue="Milk" />                                       // or an uncontrolled field with an initial value
```
