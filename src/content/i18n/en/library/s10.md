React compares props by reference, not by content. An object, an array or a function created anew during render is a new value for it, even if everything inside is the same. This becomes important when you optimise a component with `memo`.

### In simple words: “the same” and “just like it”

Two identical mugs from a shop are alike, but they are not the same mug: they are two different objects. React asks “is this the very same mug?”, not “does it look similar?”. Strings and numbers are compared by value, while objects, arrays and functions are compared by reference.

```js
// The results were checked in Node.js
({ a: 1 }) === ({ a: 1 })   // false — two different objects
[] === []                   // false — two different arrays
(() => {}) === (() => {})   // false — two different functions
2 === 2                     // true  — numbers are compared by value
'Milk' === 'Milk'           // true  — strings too
Object.is(NaN, NaN)         // true  — this is how React compares (NaN === NaN gives false)
```

### Terms of the section

| Term | Strict definition | In simple words |
| --- | --- | --- |
| Comparing by reference | Two objects are equal only if they are one and the same object in memory | “Is this the very same object?”, not “does it look similar?” |
| Shallow comparison | Comparing every prop with `Object.is` without looking inside objects | The props were checked one by one, nobody looked inside |
| Memoisation | Remembering a result so as not to compute it again for the same input | “We already computed it — take it from memory” |
| `memo` | A React function that skips the re-render of a component if its props have not changed | A guard: “the props are the same — no need to re-render” |
| `useCallback` | A hook that returns the same function until the dependencies change | “Do not create the function anew without a reason” |
| `useMemo` | A hook that remembers the result of a calculation between renders | The same for objects, arrays and long calculations |
| Dependency array | The second argument of a hook: a list of values whose change makes the result be computed again | “Recompute only if this has changed” |

### How memo works

`memo(Component)` returns a “guard” component. When the parent re-renders, the guard compares every new prop with the old one through `Object.is`. If all of them are equal, React takes the previous result and does not call the component.

`memo` compares every prop with the old one through `Object.is` and skips the render only if not a single prop has changed.

### An experiment: what breaks memo

```jsx
import { memo, useState, useCallback } from 'react';

// A card with a “guard”: it re-renders only if the props have changed
const ProductCard = memo(function ProductCard({ product, onDelete }) {
  return (
    <li>
      {product.name}
      <button onClick={() => onDelete(product.id)}>Delete</button>
    </li>
  );
});

function Fridge() {
  const [products, setProducts] = useState([
    { id: 1, name: 'Milk' },
    { id: 2, name: 'Eggs' },
  ]);
  const [query, setQuery] = useState(''); // changes on every key press

  // The very same function on every render: there are no dependencies
  const handleDelete = useCallback((id) => {
    setProducts((prev) => prev.filter((p) => p.id !== id));
  }, []);

  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <ul>
        {products.map((p) => (
          <ProductCard key={p.id} product={p} onDelete={handleDelete} />
        ))}
      </ul>
    </>
  );
}
```

The notation `setProducts((prev) => …)` is an **updater function**: React itself passes the current state into it. That is why `handleDelete` does not depend on `products`, and the dependency array is empty.

In a browser emulation three letters were typed into the search field, and the re-renders of the two cards were counted:

| The variant of the code | Card re-renders | Why |
| --- | --- | --- |
| Without `memo` | 6 | Children re-render together with the parent: 2 cards × 3 key presses |
| `memo`, but `handleDelete` is an ordinary function inside `Fridge` | 6 | A new function is created on every render, and the “guard” sees a new prop |
| `memo` + `useCallback` | 0 | All the props are the very same, the re-render is skipped |
| `memo`, but `product={{ ...p }}` in JSX | 6 | A new object on every render, even with the same content |
| `memo`, but a `<small>` tag is passed inside the card | 6 | `children` is a prop too, and JSX creates a new element on every render |

### How not to break memo

- Move constants outside the component, and keep changing data in state. Then the references to them are stable.
- Wrap functions for props in `useCallback`, and computed arrays and objects in `useMemo`.
- Remember that `children` is a prop too. New JSX between the tags on every render turns `memo` off.
- If a component needs one field, pass it directly: `name={p.name}`. Strings and numbers are compared by value.

### When to optimise at all

Not by default. Most re-renders are cheap: React calls a function, compares the result and does not touch the DOM if there are no differences. `memo` makes sense when a component is heavy — a long list, complex calculations, charts — and often re-renders with the same props. Measure first with the Profiler tab in React DevTools, then optimise.

There is an automatic way too. On 7 October 2025 the first stable version of **React Compiler** came out — a build tool that adds memoisation by itself ([the React blog](https://react.dev/blog/2025/10/07/react-compiler-1)). In a project with the compiler most of the manual `memo`, `useCallback` and `useMemo` do not have to be written. Understanding comparison by reference is still useful: it explains what exactly the compiler does.
