Everything that stands between the opening and the closing tag of a component comes into it as the `children` prop. That is how wrappers are built — cards, modal windows, page layouts — that do not know in advance what will end up inside.

### In simple words

The React documentation calls `children` a “hole” that the parent fills with any content. An everyday analogy is a photo frame: the frame is one, and the photos in it are different. The frame is responsible for the look and does not think about what is in the picture.

### Terms of the section

| Term | Strict definition | In simple words |
| --- | --- | --- |
| Composition | Building an interface by nesting some components inside others | Assembling an interface from parts, like a construction set |
| `children` | A special prop with the content between the tags of a component | The “filling” of a component |
| Wrapper | A component that adds a look or behaviour around someone else’s content | A frame around a painting |
| Slot | A named place in a component where the parent inserts markup through a prop | A labelled cell: “the heading here, the buttons here” |
| ReactNode | Everything React can draw: a string, a number, an element, an array, `null`, `undefined`, `true` and `false` | Any content that can be put into JSX |
| Portal | Drawing children into another DOM node with `createPortal` | A teleport: the component lives in one place of the tree but is seen in another place of the page |

### How it works technically

`children` is an ordinary key of the props object, the bundler simply fills it. The notation `<Modal title="Error">Text</Modal>` turns into `jsx(Modal, { title: 'Error', children: 'Text' })`. The shape of the value depends on what stands between the tags:

| What is between the tags | What comes into `children` |
| --- | --- |
| Text: `<Card>Text</Card>` | a string |
| One tag: `<Card><b /></Card>` | one React element |
| Several tags: `<Card><b /><b /></Card>` | an array of two elements |
| Nothing: `<Card />` | `undefined` |

All four cases were checked by running them. The conclusion: do not build logic on the shape of `children`. If a component needs to count or go through something, pass it an array of data in an ordinary prop.

### Example 1. A wrapper card

```jsx
function Card({ title, children }) {
  return (
    <section className="card">
      <h2 className="card-title">{title}</h2>
      <div className="card-body">{children}</div> {/* everything that was passed goes here */}
    </section>
  );
}

function FridgeDashboard() {
  return (
    <>
      <Card title="Expiring soon">
        <p>Milk — until 13 November</p>
        <p>Yoghurt — until 14 November</p>
      </Card>

      <Card title="The chef’s tip">
        <p>Milk and eggs will make an omelette.</p>
      </Card>
    </>
  );
}
```

The empty tags `<>` and `</>` are a **fragment**: a wrapper that groups elements and adds no extra tag to the DOM. In the test run the first card turned into this HTML:

```html
<section class="card">
  <h2 class="card-title">Expiring soon</h2>
  <div class="card-body"><p>Milk — until 13 November</p><p>Yoghurt — until 14 November</p></div>
</section>
```

### Example 2. A modal window for the errors of the “Smart Fridge”

Your project has a requirement: show errors to the user in a modal window, not in the console. A perfect case for `children`: the window is one, and the error texts are different.

```jsx
import { useState } from 'react';

// The frame: a heading, a button and a “hole” for the content
function ErrorModal({ isOpen, title = 'Error', onClose, children }) {
  if (!isOpen) return null; // the window is closed — we draw nothing

  return (
    <div className="modal-backdrop" onClick={onClose}>
      <div
        className="modal"
        role="dialog"
        aria-modal="true"
        aria-label={title}
        onClick={(e) => e.stopPropagation()} // a click inside the window does not reach the backdrop
      >
        <h2>{title}</h2>
        <div className="modal-body">{children}</div>
        <button onClick={onClose}>Got it</button>
      </div>
    </div>
  );
}

// Usage: the parent decides WHEN to show the window and WHAT to write in it
function App() {
  const [error, setError] = useState(null);

  function handleSearch({ username, dish }) {
    if (!username || !dish) {
      setError('Enter the user name and the name of the dish.');
      return;
    }
    // ... a request to the AI chef; on failure: setError('The AI chef did not answer. Try again.')
  }

  return (
    <>
      <SearchForm onSearch={handleSearch} />
      <ErrorModal isOpen={error !== null} onClose={() => setError(null)}>
        <p>{error}</p>
      </ErrorModal>
    </>
  );
}
```

The props of `ErrorModal` one by one:

- `isOpen` is a boolean prop: show the window or not. The window does not keep this knowledge itself, the parent controls it.
- `title` is a string with the default value `'Error'`.
- `onClose` is an event prop: the window reports “they want to close me”, and the parent clears `error`.
- `children` is the text of the error or any other markup. The same window will do for the message “The GUEST role has no access”.

The behaviour was checked by running it in a browser emulation. The window opens on an error and does not close on a click on the text. It closes on a click on the dark backdrop or on the “Got it” button.

::diagram modal

The `children` prop is the “hole” in the frame: the parent puts any text or elements there, and the window itself does not know what exactly lies in it.

In real apps a modal window is often drawn through a portal — `createPortal(…, document.body)`. Then the styles of the parent blocks do not cut it off. This does not affect the work with props: `isOpen`, `onClose` and `children` stay the same.

### Example 3. Several “holes”: slots through ordinary props

```jsx
// A page layout: four places for content
function PageLayout({ header, sidebar, children, footer }) {
  return (
    <div className="layout">
      <header>{header}</header>
      <aside>{sidebar}</aside>
      <main>{children}</main>
      <footer>{footer}</footer>
    </div>
  );
}

<PageLayout
  header={<h1>Smart Fridge</h1>}
  sidebar={<CategoryFilter />}
  footer={<small>The data was updated today</small>}
>
  <ProductList products={products} />
</PageLayout>
```

`children` is the main slot, the other slots are ordinary props with a JSX value. The layout is responsible for the arrangement, and what exactly stands in each place is decided by the parent.

### Why composition is better than a “universal component with flags”

```jsx
// BAD: the window has to know about all its variants
<Modal type="error" showRetryButton showIcon iconName="warning" text="The AI chef did not answer" />

// GOOD: the window gives a frame, and the parent assembles the content
<ErrorModal isOpen onClose={close}>
  <WarningIcon />
  <p>The AI chef did not answer</p>
  <RetryButton onRetry={retry} />
</ErrorModal>
```

In the first variant every new case adds a flag, and the component grows without end. In the second the window does not change, and the variety comes from the content. Composition also saves you from dragging props through many levels — more about this in section 12.

### Subtleties

- `children` can be shown on a condition: `{isOpen && children}`.
- The values `null`, `undefined`, `true` and `false` draw nothing in markup. The number `0` does draw, and that is a frequent trap from section 16.
- React has the utilities `Children.map` and `Children.count` for taking `children` apart. The React documentation considers them rarely needed: such code breaks easily. It is usually better to pass an array of data.
