Several recurring techniques are built on props: conditional rendering, controlled components, a component as a prop, render props and HOCs. A **pattern** is a proven, typical solution to a frequent task — a recipe instead of improvisation.

### 1. Conditional rendering by props

**Conditional rendering** means a component shows different markup depending on its props. There are three tools: an early `return`, the ternary operator `? :` and the `&&` operator.

```jsx
// An early return: a simple if inside the component
function ExpiryBadge({ daysLeft }) {
  if (daysLeft < 0) return <span className="badge badge--danger">Expired</span>;
  if (daysLeft <= 2) return <span className="badge badge--warning">Expires soon</span>;
  return null; // null means “show nothing”
}

function ProductCard({ product }) {
  return (
    <li>
      {product.name}
      <ExpiryBadge daysLeft={product.daysLeft} />
      {/* the ternary operator: one of two */}
      {product.quantity > 0 ? ` — ${product.quantity} pcs` : ' — run out'}
      {/* &&: show it or nothing */}
      {product.isFavorite && <span> (favourite)</span>}
    </li>
  );
}
```

A check on three products gave this result:

| The product’s props | On the screen |
| --- | --- |
| Milk: `daysLeft: -1`, `quantity: 2`, `isFavorite: true` | Milk · Expired · 2 pcs · (favourite) |
| Yoghurt: `daysLeft: 1`, `quantity: 0` | Yoghurt · Expires soon · run out |
| Cheese: `daysLeft: 10`, `quantity: 1` | Cheese · 1 pcs |

The zero trap:

```jsx
{product.quantity && <span>{product.quantity} pcs</span>}     // with 0 a “0” appears on the screen
{product.quantity > 0 && <span>{product.quantity} pcs</span>} // right: a boolean on the left
```

The `&&` operator returns the left side if it is “falsy”. React does not draw `false`, but it does draw the number `0`. In the test run the first line gave `<p>0</p>`, the second an empty `<p></p>`.

### 2. Controlled and uncontrolled components

A **controlled component** gets its value through the `value` prop and reports changes through `onChange`. In simple words: the parent holds the steering wheel. An **uncontrolled** one keeps its value itself, and the parent can set only the initial value, for example `<input defaultValue="Milk" />`.

```jsx
import { useState } from 'react';

// A controlled quantity stepper: it has no state of its own
function QuantityStepper({ value, onChange, min = 0, max = 99 }) {
  return (
    <div className="stepper">
      <button onClick={() => onChange(Math.max(min, value - 1))} disabled={value <= min}>−</button>
      <span>{value}</span>
      <button onClick={() => onChange(Math.min(max, value + 1))} disabled={value >= max}>+</button>
    </div>
  );
}

// The parent holds the value and always knows it
function AddProductForm() {
  const [qty, setQty] = useState(1);
  return (
    <>
      <QuantityStepper value={qty} onChange={setQty} max={3} />
      <p>The parent knows: {qty}</p>
    </>
  );
}
```

In a browser emulation the stepper behaved like this. From 1 the “−” button gave 0 and became inactive. Four presses of “+” brought it to 3, and the “+” button was disabled. At every step the parent showed the same number.

Two React warnings worth recognising on sight:

- `<input value="Milk" />` without `onChange` — “You provided a `value` prop to a form field without an `onChange` handler”. The field becomes read-only.
- `value` is first `undefined`, then a string — “A component is changing an uncontrolled input to be controlled”. The cure: start with an empty string, `useState('')`.

Both texts were obtained in the test run.

### 3. A component as a prop

You can pass not ready markup but the component itself — a function that the receiver calls with its own props:

```jsx
function CompactCard({ product }) {
  return <li className="compact">{product.name}</li>;
}

// renderAs: Card — renaming with a capital letter, otherwise JSX takes it for an HTML tag
function ProductList({ products, renderAs: Card = ProductCard }) {
  return <ul>{products.map((p) => <Card key={p.id} product={p} />)}</ul>;
}

<ProductList products={products} renderAs={CompactCard} />
// The result: <ul><li class="compact">Milk</li><li class="compact">Cheese</li></ul>
```

The difference from passing JSX: `icon={<SnowIcon />}` is an element already created with its own props. `renderAs={CompactCard}` is a “blueprint” by which the receiver itself creates elements with the data it needs.

### 4. Render props: a function prop that returns markup

A **render prop** is a function prop that a component calls to find out what to draw, passing its own data into it. In simple words: the component does the work and asks the parent about the look.

```jsx
// The list filters by itself, but HOW to draw an item and an empty list is decided by the parent
function FilteredList({ items, filter, renderItem, renderEmpty }) {
  const visible = items.filter(filter);
  if (visible.length === 0) return renderEmpty();
  return <ul>{visible.map((item) => renderItem(item))}</ul>;
}

<FilteredList
  items={products}
  filter={(p) => p.daysLeft <= 2}
  renderItem={(p) => <li key={p.id}>{p.name}: {p.daysLeft} days left</li>}
  renderEmpty={() => <p>No urgent products</p>}
/>
```

On the products “Milk” (1 day) and “Cheese” (10 days) the component returned one row “Milk: 1 days left”. With the filter “expired” it called `renderEmpty` and showed “No urgent products”. The `key` here is set by whoever creates the `<li>`, that is the `renderItem` function.

### 5. HOC: a higher-order component

A **HOC** (higher-order component) is a function that takes a component and returns a new one with extra props. It is the same idea as the higher-order functions from your assignments, only at the level of components.

```jsx
import { useContext } from 'react';

// Takes a component → returns a component that adds the user prop
function withUser(Component) {
  return function WithUser(props) {
    const user = useContext(UserContext);
    return <Component {...props} user={user} />;
  };
}

function RoleCard({ product, user }) {
  return <li>{product.name}{user.role === 'ADMIN' && <button>Delete</button>}</li>;
}

const RoleCardWithUser = withUser(RoleCard);
```

Inside a provider with the ADMIN role `RoleCardWithUser` showed the button, without a provider it did not. Today the same task is more often solved with a hook right in the component, but HOCs still appear in libraries and old code.

### A summary of the patterns

| Pattern | What is passed in the props | When to use it |
| --- | --- | --- |
| Conditional rendering | The data the look depends on | Always, when the look changes with the data |
| Controlled component | `value` + `onChange` | The parent needs the value: forms, filters, counters |
| JSX in a prop (a slot) | Ready markup | Frames, layouts, modal windows (section 8) |
| A component as a prop | The component function itself | The receiver has to create elements with its own data |
| Render props | A function that returns JSX | The component gives data, and the parent chooses the look |
| HOC | Extra props from the wrapper | In old code and libraries; in new code hooks are more common |
