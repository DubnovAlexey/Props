Technically a component is a function, and props are its only argument: an object that React builds from the JSX attributes. Below is the path of a prop from a line of code to the screen.

### Terms of the section

| Term | Strict definition | In simple words |
| --- | --- | --- |
| JSX | A syntax extension of JavaScript for describing markup | “HTML inside JS”. The browser does not understand it, so before running JSX is turned into ordinary JavaScript |
| JSX transpilation | Turning JSX into calls of the functions `jsx()` or `React.createElement()` | An automatic translation of JSX into a language the browser understands. Babel, esbuild and TypeScript do it, and Vite runs them for you |
| React element | An object `{ type, key, props }` that describes one part of the interface | A note for React: “draw `ProductCard` with this data”. It is not yet a picture on the screen |
| Render | Calling a component function to get a description of the interface | The moment React asks a component: “What do you look like now?” |
| DOM | Document Object Model: the tree of the page’s nodes in the browser | The real tags on the page that the user sees |
| Virtual DOM | An unofficial name for the tree of React elements | A draft of the page in memory that React compares with the previous draft |
| Reconciliation | The algorithm that compares the new tree of elements with the previous one | React finds the difference between “before” and “after” and changes only that in the DOM |

### The path of a prop in five steps

1. You write JSX: `<ProductCard name="Milk" quantity={2} />`.
2. The bundler turns JSX into a function call. All the attributes are put into one object: `jsx(ProductCard, { name: 'Milk', quantity: 2 })`.
3. The call returns a React element: `{ type: ProductCard, key: null, props: { name: 'Milk', quantity: 2 } }`.
4. During render React takes `type` and `props` from the element and calls `ProductCard(props)`.
5. The component returns new JSX. React compares it with the previous result and updates only the changes in the DOM.

::scheme jsx-to-dom

Steps 1–2 happen once during the build, and steps 3–5 repeat in the browser on every render.

### Step 2 close up: what JSX turns into

```jsx
// What you write
const element = <ProductCard name="Milk" quantity={2} />;
```

```js
// What comes out after the build (the automatic JSX runtime, React 17 and newer)
import { jsx } from 'react/jsx-runtime';

const element = jsx(ProductCard, { name: 'Milk', quantity: 2 });

// The classic version of the same thing: that is how it was before React 17, and it still works
const element2 = React.createElement(ProductCard, { name: 'Milk', quantity: 2 });
```

Both versions were produced by the esbuild bundler from the same line of JSX. The attributes turned into keys of an object: `name="Milk"` became `name: 'Milk'`, and `quantity={2}` became `quantity: 2`.

### Step 3 close up: what is inside a React element

```js
console.log(element);
// {
//   $$typeof: Symbol(react.transitional.element), // the mark “this is a real React element”
//   type: ProductCard,                            // WHAT to draw: your function
//   key: null,                                    // the key for lists, see section 9
//   props: { name: 'Milk', quantity: 2 },         // WITH WHAT to draw: the props
//   _owner: …, _store: …                          // service fields of development mode
// }
```

- `type` answers the question “what to draw”. For your own component it is a function, for an HTML tag it is a string, for example `'div'`.
- `props` answers the question “with what data to draw”.
- `$$typeof` protects against forgery. A value of the Symbol type cannot be passed through JSON, so foreign data from a server cannot pretend to be an element.

The output was obtained on React 19.3.1. In development mode the `props` object is also frozen with `Object.freeze`, so that it cannot be changed by accident. More in section 5.

### What follows from this in practice

- **Props are one object.** The notation `function ProductCard(name, quantity)` does not work: the whole props object comes into `name`, and `quantity` turns out to be `undefined`. Checked by running it.
- **The name of a prop is a key of an object.** That is why props are named like JavaScript variables: `expiryDate`, `onDelete`, `isAdmin`.
- **The content between the tags is a prop too.** `<Modal title="Error">Text</Modal>` turns into `jsx(Modal, { title: 'Error', children: 'Text' })`. This is the `children` prop, section 8 is devoted to it.
- **`key` does not get into the props.** The bundler passes it as a separate argument: `jsx(Card, { name: 'Milk' }, 'milk')`. If you read `props.key`, React warns in the console and returns `undefined`.
- **The name of a component is written with a capital letter.** `<ProductCard />` turns into a reference to a function, and `<productCard />` into the string `'productCard'`. React takes it for an unknown HTML tag.

### An experiment: a component is just a function

```jsx
// Only for understanding! In an app components are not called like this
const result = ProductCard({ name: 'Milk', quantity: 2 });

console.log(result.type);            // 'div' — the component returned a description of a <div>
console.log(result.props.className); // 'product-card'
```

The call worked because a component is an ordinary JavaScript function. But in an app only React should call a component. Otherwise it cannot keep track of the component’s state, its hooks and its re-renders.
