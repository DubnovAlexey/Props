A component gets all the props as one object. You can read it with a dot (`props.name`) or unpack it right away into separate variables with destructuring — that is how it is written most often.

### Way 1. The whole props object

```jsx
function ProductCard(props) {
  return (
    <h3>
      {props.name} — {props.quantity} {props.unit}
    </h3>
  );
}
```

It is handy when there are few props or the object has to be passed on whole. The downside: the first line of the function does not show which props the component expects.

### Way 2. Destructuring right in the parameters

**Destructuring** is a JavaScript syntax that takes the fields of an object out into separate variables. In simple words: unpack the box and put the things on the shelves.

```jsx
// We unpack the props right in the parentheses of the parameters
function ProductCard({ name, quantity, unit }) {
  return (
    <h3>
      {name} — {quantity} {unit}
    </h3>
  );
}
```

This is exactly the same as:

```jsx
function ProductCard(props) {
  const { name, quantity, unit } = props; // the same destructuring, but on a separate line
  // ...
}
```

This way is considered the standard in the React documentation. The list of props is visible at once, like the list of parameters of an ordinary function.

A common mistake is to forget the curly braces:

```jsx
function ProductCard(name) { // A MISTAKE: no { }
  return <h3>{name}</h3>;    // name is the whole object { name: 'Milk' }
}
```

In the test run React crashed with the error “Objects are not valid as a React child (found: object with keys {name})”. The meaning: an object cannot be shown on the screen as text.

### Default values

```jsx
function ProductCard({ name, quantity = 1, unit = 'pcs' }) {
  return <p>{name}: {quantity} {unit}</p>;
}
```

`quantity = 1` reads like this: “if `quantity` was not passed, take it as 1”. It works only for `undefined`:

| What the parent passed | What the component gets |
| --- | --- |
| Nothing: `<ProductCard name="Milk" />` | `1` |
| `quantity={undefined}` | `1` |
| `quantity={null}` | `null` — the default value did not work |
| `quantity={0}` | `0` — zero is a real value too |

All four rows were checked by running them. If `null` has to be replaced as well, the `??` operator (“nullish coalescing”) helps: `const q = quantity ?? 1;` puts 1 both for `null` and for `undefined`.

Default values used to be set like this: `ProductCard.defaultProps = { quantity: 1 }`. In React 19 this was removed for function components: the notation is silently ignored, and in the test run the component got `undefined`. More in section 11.

### Renaming while unpacking

```jsx
// The prop is called name, but inside the component playerName is handier
function PlayerSeat({ name: playerName, isDealer }) {
  return <p>{playerName}{isDealer ? ' (deals)' : ''}</p>;
}
```

The notation `name: playerName` means “take the field `name` and put it into the variable `playerName`”. To the left of the colon is the name of the prop, to the right the name of the variable.

### Nested destructuring

```jsx
// expiry = { date: '2026-11-13', daysLeft: 3 }
function ExpiryBadge({ expiry: { date, daysLeft } = {} }) {
  if (!date) return <span>No date given</span>;
  return <span>Until {date}, {daysLeft} days left</span>;
}
```

The tail `= {}` protects against a crash. Without it `<ExpiryBadge />` without the `expiry` prop crashes with the error “Cannot read properties of undefined (reading 'date')”. Checked by running it.

### The remaining props: ...rest

The **rest syntax** `...rest` gathers into one object everything you did not unpack by name. In simple words: “everything else into this bag”.

```jsx
// Our own button for the fridge: it knows only variant itself and gives the rest to <button>
function FridgeButton({ variant = 'primary', ...rest }) {
  // rest = { disabled: true, title: 'Delete the product', children: 'Delete' }
  return <button className={`btn btn-${variant}`} {...rest} />;
}

<FridgeButton variant="danger" disabled title="Delete the product">
  Delete
</FridgeButton>
// The result: <button class="btn btn-danger" disabled="" title="Delete the product">Delete</button>
```

In the parameters `...rest` gathers the props into an object, and in JSX `{...rest}` lays them out into attributes again. That is how wrappers over HTML elements are built: they do not need to list all the possible attributes of a button. The result in the comment was obtained by running it.

### Class components: this.props

In old code you meet class components. There the props lie in `this.props`:

```jsx
import { Component } from 'react';

class ProductCard extends Component {
  static defaultProps = { quantity: 1 }; // for classes defaultProps still works in React 19

  render() {
    const { name, quantity } = this.props; // the props are read from this.props
    return <p>{name}: {quantity}</p>;
  }
}
```

New code is written with functions. It is worth being able to read classes: they still appear in old projects and articles.

### Which way to choose

| Way | Notation | When to use |
| --- | --- | --- |
| Destructuring | `function Card({ name, quantity })` | By default, almost always |
| Default values | `{ quantity = 1 }` | For optional props |
| The whole object | `function Card(props)` | There are few props or the object has to be passed on |
| Renaming | `{ name: playerName }` | The name of the prop is awkward or clashes with a variable |
| The remaining props | `{ variant, ...rest }` | Wrappers over HTML elements and other people’s components |
| `this.props` | `class Card extends Component` | Only for reading old code |
