Six tasks from easy to hard, all built on your projects. The conditions come first, and the answers are gathered below so that you do not peek. Every answer was checked by running it.

### Conditions

1. **Easy. QuantityLabel.** Write a component with the props `quantity` (a number) and `unit` (a string, by default `'pcs'`). It shows “2 pcs”, and at zero — “out of stock”.
2. **Easy. Find four mistakes** in the code below and fix them.
3. **Medium. CategoryFilter.** Make a controlled filter with the props `categories`, `selected` and `onSelect`. The parent `FridgePage` keeps the selected category and shows only the matching products. The “all” button resets the filter.
4. **Medium. Lifting state up.** There is a form `AddProductForm` and a list of products. After pressing “Add” the new product appears in the list, the counter grows, and the field is cleared. An empty name is not added.
5. **Hard. TrickCounter for preferans.** Props: `tricks` — an object like `{ Alexey: 4, Maria: 2, Bot: 1 }`, `declarer` — the name of the declarer, `contract` — the number of tricks bid. For the declarer show “4 of 6, 2 more to take” or “6 of 6, the contract is made”.
6. **Hard. Types as a guard of secrets.** Describe the props type of `OpponentSeat` in TypeScript so that the compiler does not let anyone pass the opponent’s cards into the component.

### Answer 1

```jsx
function QuantityLabel({ quantity, unit = 'pcs' }) {
  if (quantity === 0) return <span>out of stock</span>; // an early return
  return <span>{quantity} {unit}</span>;
}
```

The check: `quantity={2}` gave “2 pcs”, `quantity={0}` — “out of stock”, `quantity={500} unit="g"` — “500 g”. The comparison `=== 0` is more precise than `!quantity`: it does not confuse zero with a prop that was not passed.

### Answer 2

The mistakes: `quantity="2"` is a string instead of a number; there is no destructuring in the parameters; `class` instead of `className`; `onDelete(id)` is called during render.

```jsx
// The parent
<ProductCard name="Milk" quantity={2} id={1} onDelete={handleDelete} />

// The child
function ProductCard({ name, quantity, id, onDelete }) {
  return (
    <li className="card">
      {name}: {quantity + 1} pcs after shopping
      <button onClick={() => onDelete(id)}>Delete</button>
    </li>
  );
}
```

The check: “Milk: 3 pcs after shopping” on the screen. Before the click `onDelete` was not called, after the click it got `1`.

### Answer 3

```jsx
import { useState } from 'react';

// A controlled filter: it keeps nothing itself
function CategoryFilter({ categories, selected, onSelect }) {
  return (
    <div className="filter">
      {['all', ...categories].map((c) => (
        <button key={c} aria-pressed={c === selected} onClick={() => onSelect(c)}>
          {c}
        </button>
      ))}
    </div>
  );
}

function FridgePage({ products }) {
  const [selected, setSelected] = useState('all');

  // both values are derived — we compute them instead of storing them
  const categories = [...new Set(products.map((p) => p.category))];
  const visible = selected === 'all' ? products : products.filter((p) => p.category === selected);

  return (
    <>
      <CategoryFilter categories={categories} selected={selected} onSelect={setSelected} />
      <ul>{visible.map((p) => <li key={p.id}>{p.name}</li>)}</ul>
    </>
  );
}
```

The check on three products: the buttons “all, dairy, fruit”. After a click on “dairy” Milk and Yoghurt stayed, “all” brought the full list back. The `aria-pressed` attribute tells screen readers which button is pressed.

### Answer 4

```jsx
import { useState } from 'react';

// The form keeps only the text being typed, and the list lives in the parent
function AddProductForm({ onAdd }) {
  const [name, setName] = useState('');

  function handleSubmit(e) {
    e.preventDefault();
    if (!name.trim()) return; // we do not add an empty name
    onAdd(name.trim());       // the event goes up
    setName('');              // we clear the field
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="A new product" />
      <button>Add</button>
    </form>
  );
}

function Fridge() {
  const [items, setItems] = useState([{ id: 'milk', name: 'Milk' }]);

  function handleAdd(name) {
    setItems((prev) => [...prev, { id: crypto.randomUUID(), name }]); // a unique id for the key
  }

  return (
    <>
      <AddProductForm onAdd={handleAdd} />
      <p>Products: {items.length}</p>
      <ul>{items.map((p) => <li key={p.id}>{p.name}</li>)}</ul>
    </>
  );
}
```

The check: “  Cheese ” was typed with spaces — “Cheese” appeared in the list, and the counter showed 2. Input of nothing but spaces added nothing. `crypto.randomUUID()` creates a random unique id. It is created once when an item is added and does not change afterwards, so it is fit to be a `key`, unlike `Math.random()` inside JSX.

### Answer 5

```jsx
function TrickCounter({ tricks, declarer, contract }) {
  return (
    <ul className="tricks">
      {Object.entries(tricks).map(([player, count]) => {
        const isDeclarer = player === declarer;
        const left = contract - count; // how many more must be taken
        return (
          <li key={player} className={isDeclarer ? 'declarer' : undefined}>
            {player}: {count}
            {isDeclarer &&
              (left > 0 ? ` of ${contract}, ${left} more to take` : ` of ${contract}, the contract is made`)}
          </li>
        );
      })}
    </ul>
  );
}

<TrickCounter tricks={{ Alexey: 4, Maria: 2, Bot: 1 }} declarer="Alexey" contract={6} />
```

The check: with 4 tricks it showed “Alexey: 4 of 6, 2 more to take”, with 6 — “Alexey: 6 of 6, the contract is made”. `Object.entries` turns an object into an array of pairs `[name, number]`, and the name of a player is unique and fit for the `key`. React simply does not output `className={undefined}`.
