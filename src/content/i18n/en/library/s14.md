The web interface from assignment 28 fits into React entirely: all the state lives in one component `App`, and seven components get their data only through props. Below is a working sketch: the code was run in a browser emulation, but it is not in your repository yet.

### What we take from the project

- The app keeps products and their expiry dates and can ask the AI chef on Gemini for a recipe.
- Assignment 28: a user name field, a dish name field, a “Search” button and a result area.
- The roles ADMIN, USER and GUEST are looked up by name; an unknown name gives GUEST.
- Errors are shown in a modal window, not in the console.
- Right now the chain is: `index.html` → `main.js` → `authService.js`, `fileService.js`, `promptService.js`, `aiService.js`, `config.js`.

### The full code with comments

```jsx
// FridgeApp.jsx — a sketch of the React interface of the “Smart Fridge” (assignment 28)
// All the data comes into the components through props, the state lives in App.
import { useState } from 'react';

// The roles from the assignment: the role is looked up by name, an unknown name is a guest
export const ROLES = { ADMIN: 'ADMIN', USER: 'USER', GUEST: 'GUEST' };
const KNOWN_USERS = { alexey: ROLES.ADMIN, maria: ROLES.USER }; // sample data

export function getRole(username) {
  return KNOWN_USERS[username.trim().toLowerCase()] ?? ROLES.GUEST;
}

// ---------- “Dumb” components: only props, no state of their own ----------

function Header({ userName, role }) {
  return (
    <header>
      <h1>Smart Fridge</h1>
      {userName && <p className="who">You are logged in as {userName} ({role})</p>}
    </header>
  );
}

function ExpiryBadge({ daysLeft }) {
  if (daysLeft < 0) return <span className="badge danger">Expired</span>;
  if (daysLeft <= 2) return <span className="badge warning">Expires soon</span>;
  return null; // the date is fine — no badge is needed
}

function ProductCard({ product, canDelete, onDelete }) {
  return (
    <li className="product-card">
      <span>{product.name} — {product.quantity} pcs</span>
      <ExpiryBadge daysLeft={product.daysLeft} />
      {canDelete && <button onClick={() => onDelete(product.id)}>Delete</button>}
    </li>
  );
}

function ProductList({ products, canDelete, onDelete }) {
  if (products.length === 0) return <p>The fridge is empty</p>;
  return (
    <ul className="product-list">
      {products.map((p) => (
        <ProductCard key={p.id} product={p} canDelete={canDelete} onDelete={onDelete} />
      ))}
    </ul>
  );
}

function RecipeResult({ result, isLoading }) {
  if (isLoading) return <p className="result">The AI chef is thinking…</p>;
  if (!result) return null;
  return (
    <section className="result">
      <h2>{result.dish}</h2>
      <p>{result.text}</p>
    </section>
  );
}

function ErrorModal({ isOpen, onClose, children }) {
  if (!isOpen) return null;
  return (
    <div className="modal-backdrop" onClick={onClose}>
      <div className="modal" role="dialog" aria-modal="true" aria-label="Error" onClick={(e) => e.stopPropagation()}>
        <h2>Error</h2>
        <div className="modal-body">{children}</div>
        <button onClick={onClose}>Got it</button>
      </div>
    </div>
  );
}

// ---------- The form from assignment 28: it keeps the fields itself and gives only the event out ----------

function SearchForm({ onSearch, isLoading }) {
  const [username, setUsername] = useState('');
  const [dish, setDish] = useState('');

  function handleSubmit(e) {
    e.preventDefault(); // do not reload the page
    onSearch({ username: username.trim(), dish: dish.trim() });
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="username" value={username} onChange={(e) => setUsername(e.target.value)} placeholder="User name" />
      <input name="dish" value={dish} onChange={(e) => setDish(e.target.value)} placeholder="The name of the dish" />
      <button type="submit" disabled={isLoading}>{isLoading ? 'Searching…' : 'Search'}</button>
    </form>
  );
}

// ---------- The root: the only owner of the state ----------

export default function App({ initialProducts, findRecipe }) {
  const [user, setUser] = useState(null); // { name, role }
  const [products, setProducts] = useState(initialProducts);
  const [result, setResult] = useState(null);
  const [error, setError] = useState(null);
  const [isLoading, setIsLoading] = useState(false);

  const canDelete = user?.role === ROLES.ADMIN; // a derived value: we compute it instead of storing it

  async function handleSearch({ username, dish }) {
    if (!username || !dish) {
      setError('Enter the user name and the name of the dish.');
      return;
    }
    const role = getRole(username);
    setUser({ name: username, role });
    setIsLoading(true);
    try {
      const recipe = await findRecipe({ role, dish, products }); // the service came in a prop
      setResult(recipe);
    } catch (err) {
      setError(err.message); // we show the error in a modal window, not in the console
    } finally {
      setIsLoading(false);
    }
  }

  function handleDelete(id) {
    setProducts((prev) => prev.filter((p) => p.id !== id));
  }

  return (
    <>
      <Header userName={user?.name} role={user?.role} />
      <SearchForm onSearch={handleSearch} isLoading={isLoading} />
      <ProductList products={products} canDelete={canDelete} onDelete={handleDelete} />
      <RecipeResult result={result} isLoading={isLoading} />
      <ErrorModal isOpen={error !== null} onClose={() => setError(null)}>
        <p>{error}</p>
      </ErrorModal>
    </>
  );
}
```

### The decisions explained

- **The state in one place.** `user`, `products`, `result`, `error` and `isLoading` are needed by several components, so they live in their common parent `App` (section 7).
- **The local state of the form.** The text being typed is needed only by `SearchForm`. The form gives out the ready result through `onSearch({ username, dish })`.
- **Permissions as a derived value.** `canDelete` is not stored but computed from the role on every render. The notation `user?.role` is optional chaining: if `user` is `null`, the result is `undefined` without an error.
- **The service comes in a prop.** `App` does not know how the recipe search works: it simply calls `findRecipe`. Thanks to this, in the check below a stub function stands in for Gemini.
- **Errors go to the modal window.** Both empty fields and a service error get into `error`, and the window shows the text through `children`.

### Start-up: where initialProducts and findRecipe come from

```jsx
// main.jsx — the entry point instead of the current main.js
import { createRoot } from 'react-dom/client';
import App from './FridgeApp.jsx';

// A request to your own server. The address /api/recipe is made up — it still has to be built
async function findRecipe({ role, dish, products }) {
  const response = await fetch('/api/recipe', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ role, dish, products }),
  });
  if (!response.ok) throw new Error('The AI chef did not answer. Try again.');
  return response.json(); // we expect { dish, text }
}

const initialProducts = [
  { id: 1, name: 'Milk', quantity: 2, daysLeft: 1 },
  { id: 2, name: 'Eggs', quantity: 10, daysLeft: 7 },
  { id: 3, name: 'Yoghurt', quantity: 1, daysLeft: -2 },
];

createRoot(document.getElementById('root')).render(
  <App initialProducts={initialProducts} findRecipe={findRecipe} />
);
```

Why through a server: in your `aiService.js` the Gemini key is read from `.env` in Node.js. In the browser any visitor would see the key, so the request to the AI has to go from a server. The product structure `{ id, name, quantity, daysLeft }` here is made up: adjust it to your `fridge.json`.

### What the check showed

The code above was run in a browser emulation on React 19.3.1. A stub stands in for the real AI. Like your `promptService.js`, it throws “Access denied” for all roles except ADMIN and USER.

| Action | Who is logged in | “Delete” buttons | Modal window | Result |
| --- | --- | --- | --- | --- |
| The first render | nobody | 0 | no | no |
| “Search” with empty fields | nobody | 0 | “Enter the user name and the name of the dish.” | no |
| The name “guest123”, the dish “omelette” | guest123 (GUEST) | 0 | “Access denied” | no |
| The name “Alexey”, the dish “omelette” | Alexey (ADMIN) | 3 | no | “Omelette” with the text of the recipe |
| The admin deletes “Eggs” | Alexey (ADMIN) | 2 | no | Milk and Yoghurt stayed in the list |

The expiry badges were visible at once: “Expires soon” at the milk and “Expired” at the yoghurt. The name “Alexey” with a capital letter gave ADMIN, because `getRole` turns the name into lowercase.
