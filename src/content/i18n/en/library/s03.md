A prop is passed as an attribute in JSX: a name, an equals sign and a value. A string can be written in quotes, everything else is written in curly braces.

### In simple words

Quotes mean “here is ready text, pass it as it is”. Curly braces open a “window into JavaScript”: inside you can write a number, a variable, a calculation or a function call.

Only an **expression** is allowed inside the braces — code that evaluates to a value: `2`, `daysLeft < 0`, `user.name`, `calcTotal(products)`. **Statements** like `if`, `for` or `let x = 1` return nothing, so they do not fit there.

### Reference table: all kinds of values

| What we pass | How to write it | What arrives in props |
| --- | --- | --- |
| A string | `unit="pcs"` | `'pcs'` |
| A number | `quantity={2}` | `2` |
| `true` in the short form | `isFavorite` | `true` |
| A boolean expression | `isExpired={daysLeft < 0}` | `true` or `false` |
| An array | `tags={['dairy', 'chilled']}` | an array of two strings |
| An object | `expiry={{ date: '2026-11-13', daysLeft: 3 }}` | an object with two fields |
| A function | `onDelete={handleDelete}` | the function itself, not the result of calling it |
| JSX markup | `badge={<span>Expires soon</span>}` | a React element |
| An empty value | `expiry={null}` | `null` |
| The prop was not passed | — | `undefined` |

### Strings

The notations `name="Milk"` and `name={'Milk'}` mean the same thing. Quotes are just a short way to pass a ready string. If a string has to be built from variables, a template string inside curly braces is used:

```jsx
const daysLeft = 3;

<ProductCard title={`${daysLeft} days left`} /> // title === '3 days left'
```

### Numbers: the main trap

```jsx
function Qty({ quantity }) {
  return <p>It will be: {quantity + 1}</p>;
}

<Qty quantity="2" />  // “It will be: 21” — the string '2' came, and '2' + 1 glues strings together
<Qty quantity={2} />  // “It will be: 3” — the number 2 came
```

Quotes always give a string, even if there are digits inside. Numbers, booleans, arrays and objects are passed only in curly braces. Both results were checked by running them.

### Booleans

```jsx
<ProductCard isFavorite />               // the same as isFavorite={true}
<ProductCard isFavorite={false} />       // false has to be written explicitly
<ProductCard />                          // isFavorite was not passed: undefined comes
<ProductCard isExpired={daysLeft < 0} /> // the result of a comparison: true or false
```

In a condition `undefined` behaves like `false`, so a boolean prop that was not passed usually works as “no”. There is a difference from ordinary HTML: in the browser `disabled="false"` still disables the button. But in React `<button disabled={false}>` turns into a `<button>` without the attribute — this was checked too.

### Arrays and objects: double curly braces

```jsx
<ProductCard tags={['dairy', 'chilled']} />
<ProductCard expiry={{ date: '2026-11-13', daysLeft: 3 }} />
<div style={{ color: 'red', fontSize: 14 }}>Expired</div>
```

Double braces are not a special syntax. The outer braces open the “window into JavaScript”, and the inner ones are an ordinary object literal. The second line is equivalent to this:

```jsx
const expiry = { date: '2026-11-13', daysLeft: 3 };

<ProductCard expiry={expiry} />
```

### Functions: we pass a reference, not the result

```jsx
<ProductCard onDelete={handleDelete} />                   // we pass the function itself
<ProductCard onDelete={() => handleDelete(product.id)} /> // a wrapper, if an argument is needed
<ProductCard onDelete={handleDelete()} />                 // A MISTAKE: the function is called at once during render
```

In the third line what gets into the prop is not the function but what it returned. Section 7 is devoted to functions in props.

### JSX as the value of a prop

```jsx
<ProductList
  products={products}
  emptyState={<p>The fridge is empty. Time to go shopping!</p>}
/>
```

The component gets a ready piece of markup and decides itself where to show it. The “slots” from section 8 are built on this.

### Spread: pass all the fields of an object at once

The **spread syntax** `{...obj}` lays an object out into separate props, the way you lay out groceries from a bag onto the shelves.

```jsx
const product = { name: 'Milk', quantity: 2 };

<ProductCard {...product} />
// the same as:
<ProductCard name={product.name} quantity={product.quantity} />
```

The order matters: if a name repeats, whatever is written further to the right wins.

```jsx
<ProductCard {...product} quantity={0} /> // quantity === 0
<ProductCard quantity={0} {...product} /> // quantity === 2
```

The React documentation advises not to overuse spread ([source](https://react.dev/learn/passing-props-to-a-component)). If it stands in every other component, it is no longer clear which props each of them really needs.

### A full example: a card with every kind of prop

```jsx
function FridgeShelf() {
  const product = { id: 7, name: 'Milk', quantity: 2 };
  const daysLeft = 3;

  function handleDelete(id) {
    console.log('Delete the product', id);
  }

  return (
    <ProductCard
      name={product.name}                       // a string from an object
      quantity={product.quantity}               // a number
      unit="pcs"                                // a string literal
      tags={['dairy', 'chilled']}               // an array
      expiry={{ date: '2026-11-13', daysLeft }} // an object
      isFavorite                                // true
      isExpired={daysLeft < 0}                  // a boolean expression
      onDelete={() => handleDelete(product.id)} // a function
      badge={<span className="badge">Expires soon</span>} // JSX
      title={`${daysLeft} days left`}           // a template string
    />
  );
}
```

The notation `{ date: '2026-11-13', daysLeft }` uses a JavaScript shorthand: `daysLeft` here means `daysLeft: daysLeft`. `//` comments between attributes are allowed: the bundler simply cuts them out.

```text
expiry:     object = {"date":"2026-11-13","daysLeft":3}
isFavorite: boolean = true

```
