Almost all props are your data, but a few names have a special role. React takes `key` for itself to tell list items apart, `ref` gives access to a DOM node, and the props of built-in tags like `<input>` obey the rules of the browser.

### Lists: from an array of data to an array of components

```jsx
function ProductList({ products }) {
  return (
    <ul>
      {products.map((product) => (
        <ProductCard key={product.id} product={product} />
      ))}
    </ul>
  );
}
```

The `map` method turns an array of data into an array of React elements: one product — one card. It is the same higher-order function as in your JavaScript assignments. Every list item needs a `key` prop.

### key is the “ticket” of a list item

A **key** is a string or a number that is unique among the neighbours. By the key React recognises an item between renders.

In simple words: imagine a cloakroom. The ticket is tied to the coat, not to the hook, so a coat that was moved will still be found. A key is such a ticket for a component, and an index in the array is the number of the hook.

An experiment. Every row of a list has a field for a note with its own state. “buy more” was typed into the row “Milk”, then “Bread” was added at the start of the list.

| What was in key | Before adding | After adding the bread |
| --- | --- | --- |
| The index `i` | Milk \[buy more], Eggs \[ ] | Bread \[buy more], Milk \[ ], Eggs \[ ] |
| `product.id` | Milk \[buy more], Eggs \[ ] | Bread \[ ], Milk \[buy more], Eggs \[ ] |

With the index the note “moved” to the bread: React saw an item with the key 0 and decided it was the old row. With `id` the note stayed with the milk. The result was obtained in a browser emulation.

The rules for key:

- A key is unique among the neighbours in one list. In different lists keys may repeat.
- A key is stable: for the same product it does not change between renders. An id from a database or a file works best, for example from your `fridge.json`.
- `Math.random()` as a key is a mistake: the keys are new on every render, and React recreates all the items anew.
- An index is acceptable only if the list is never sorted, filtered or added to at the start or in the middle.
- `key` goes on the outermost element inside `map`, that is on `<ProductCard key={…} />`, not inside the card itself.
- If you forgot the key, React warns in the console: “Each child in a list should have a unique "key" prop”.

### key does not get into the props

```jsx
// BAD: inside the component key is always undefined, and React prints a warning
function ProductCard({ key, product }) { /* ... */ }

// GOOD: if the id is needed inside, pass it in a separate prop
<ProductCard key={product.id} productId={product.id} product={product} />
```

In section 2 this was checked by running it: React returned `undefined` and reported “`key` is not a prop”.

### A bonus: a change of key resets the component

For React a new key means a new component: the old one is removed together with its state. This is handy with the editor from section 6:

```jsx
// When another product is selected, the editor is created anew and takes the fresh initialQuantity
<QuantityEditor key={selected.id} initialQuantity={selected.quantity} />
```

### ref as a prop (React 19)

A **ref** (a reference) is an object `{ current: … }` that React fills with a DOM node. In simple words: a bookmark on a particular element of the page, so that later you can, for example, put the cursor into it.

Starting with React 19 a function component gets `ref` as an ordinary prop. Before, this needed the `forwardRef` wrapper.

```jsx
import { useRef } from 'react';

// React 19: ref comes together with the other props
function SearchInput({ ref, ...rest }) {
  return <input ref={ref} className="search-input" {...rest} />;
}

function SearchForm() {
  const dishRef = useRef(null); // React puts the DOM node of the <input> here

  function handleSubmit(e) {
    e.preventDefault();
    if (!dishRef.current.value.trim()) {
      dishRef.current.focus(); // the field is empty — we put the cursor into it
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <SearchInput ref={dishRef} placeholder="The name of the dish" />
      <button>Search</button>
    </form>
  );
}
```

```jsx
// Before React 19 the same thing was written like this. It still works, but it is no longer needed
import { forwardRef } from 'react';

const SearchInput = forwardRef(function SearchInput(props, ref) {
  return <input ref={ref} className="search-input" {...props} />;
});
```

In a browser emulation on React 19.3.1 three facts were checked. `SearchInput` got `ref` in its props, and submitting an empty form put the cursor into the field. The notation `{...props}` now passes `ref` on as well. The old `forwardRef` still works too.

### The props of built-in HTML elements

The tags `<div>`, `<input>`, `<button>` have a set of props given in advance that almost matches the HTML attributes. There are few differences, and all of them can be explained:

| In HTML | In React | Why |
| --- | --- | --- |
| `class="card"` | `className="card"` | `class` is a reserved word of JavaScript |
| `for="dish"` | `htmlFor="dish"` | `for` is a JavaScript word too |
| `onclick="go()"` (a string) | `onClick={go}` (a function) | Events are written in camelCase and take a function |
| `style="background-color: red"` | `style={{ backgroundColor: 'red' }}` | A style is an object, the properties are in camelCase |
| `tabindex="2"` | `tabIndex={2}` | The names of attributes are in camelCase |
| `aria-label`, `data-role` | the same, with hyphens | An exception: `aria-*` and `data-*` are written as in HTML |

**camelCase** is a way of writing where the words go together and each next one starts with a capital letter: `backgroundColor`, `tabIndex`. Here is what React did with such props in the test run:

```jsx
<label htmlFor="dish" className="label">Dish</label>
<input id="dish" tabIndex={2} aria-label="The name of the dish" data-role="dish" />
<p style={{ backgroundColor: 'red', fontSize: 14, zIndex: 2 }}>Expired</p>
```

```html
<label for="dish" class="label">Dish</label>
<input id="dish" tabindex="2" aria-label="The name of the dish" data-role="dish"/>
<p style="background-color:red;font-size:14px;z-index:2">Expired</p>
```

React added the unit `px` to the number 14 in `fontSize` by itself. For properties without units, like `zIndex`, the number stayed as it was.

### Your own components are not HTML tags

Your component has no “built-in” attributes. `<ProductCard className="highlight" />` does not add a class by itself: it is just a prop, and the component has to pass it to its tag itself. In the test run a component that did not pass it on returned `<p>Milk</p>` without any class.

The opposite mistake is accidentally giving your own prop to an HTML tag through `{...rest}`. On `<div isActive>` React printed the warning “React does not recognize the `isActive` prop on a DOM element”. The cure is to take your own props before laying out the rest:

```jsx
function ProductCard({ isActive, className = '', children, ...rest }) {
  // we took isActive for ourselves, only what the <div> understands goes into it
  const classes = ['card', isActive && 'card--active', className].filter(Boolean).join(' ');
  return (
    <div className={classes} {...rest}>
      {children}
    </div>
  );
}
```
