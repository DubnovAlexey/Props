Props are data that one component passes to another, just as arguments are passed into a function. The word props is short for properties.

### First, two words about components

A **component** is a piece of the interface shaped as a function: a button, a product card, a playing card, a whole page. The function returns markup, and React shows it on the screen.

Components are nested inside each other like Russian dolls. A component that uses another component inside itself is called the **parent**. The one being used is called the **child**.

### The main idea on a familiar example

You already know functions with parameters from your homework:

```js
// An ordinary function: the value of name comes from outside
function greet(name) {
  return `Hello, ${name}!`;
}

greet('Alexey'); // "Hello, Alexey!"
greet('Maria');  // "Hello, Maria!"
```

A React component works the same way. Only the arguments are written not in parentheses but as attributes of an HTML tag:

```jsx
// A component: the values come from outside in the props object
function Greeting(props) {
  return <h1>Hello, {props.name}!</h1>;
}

// Usage: name="Alexey" is the prop
<Greeting name="Alexey" />  // shows “Hello, Alexey!”
<Greeting name="Maria" />   // shows “Hello, Maria!”
```

One function gives different results because it gets different arguments. One component draws different cards because it gets different props.

### Three everyday analogies

| Analogy | Who is the component here | What are the props here | What it explains |
| --- | --- | --- | --- |
| An order in a café | The cook | The order slip: the dish, the portion, “no onions” | The cook cooks from the slip and does not rewrite it: props are only read |
| A document form | An empty card template | The values written into the fields | One template is filled with different data: the component is reused |
| HTML attributes | The `<img>` tag | The `src` and `alt` attributes | Your own components get “attributes” just like the built-in tags |

### An example from the “Smart Fridge”

```jsx
// The child component: the “form” of a product card
function ProductCard(props) {
  return (
    <div className="product-card">
      <h3>{props.name}</h3>
      <p>Quantity: {props.quantity} pcs</p>
    </div>
  );
}

// The parent component: fills the “form” with data
function Fridge() {
  return (
    <section>
      <ProductCard name="Milk" quantity={2} />
      <ProductCard name="Eggs" quantity={10} />
    </section>
  );
}
```

What happens here:

1. `Fridge` is the parent. It uses `ProductCard` twice and passes different data each time.
2. React calls the `ProductCard` function twice: with the object `{ name: 'Milk', quantity: 2 }` and with the object `{ name: 'Eggs', quantity: 10 }`.
3. Inside `ProductCard` the values are read with a dot: `props.name`, `props.quantity`.
4. Two different cards appear on the screen, although the code of the card is written once.

The curly braces in `quantity={2}` mean “a JavaScript value here”, not text. More about this in section 3.

The same `ProductCard` function gets different props objects and that is why it draws different cards.

### Five rules worth remembering right away

- Props go from top to bottom: from the parent to the child, never the other way round.
- The child only reads props. You must not change them inside the component.
- You can pass any JavaScript value: a string, a number, an array, an object, a function and even a piece of markup.
- If the parent passed new props, the child re-renders with the new data.
- Props make a component reusable: one `ProductCard` for hundreds of products.
