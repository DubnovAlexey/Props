In a card game props solve two tasks at once: they show the player their own view of the game and keep the interface from learning too much. The engine keeps the full state, and the components get only what this player is allowed to see. Below is a sketch of a table checked in a browser emulation; the engine is not implemented in it.

### The architectural idea: the interface is a function of the “player view”

- **The engine knows everything:** all the hands, the talon, the tricks, whose turn it is.
- **The player view** is an object the engine builds for one player: their own cards are open, the opponents show only the number of cards. boardgame.io has the `playerView` option for this, which cuts the secrets out of the state.
- **The components get the player view in props** and draw it. They do not know the rules of storage and calculation.
- **Moves go up** through the function props `onPlayCard(cardId)` and `onBid(bid)`. The engine checks the move and builds a new state.
- **The AI thinks separately**, for example ISMCTS in a Web Worker. The table only needs an `isThinking` prop for the right opponent and the final move.

Why this matters: if `OpponentSeat` gets only `cardCount`, then even a layout bug will not show someone else’s cards — they simply are not in the props. For a network game the player view has to be built on the server: everything that got into the browser can be seen in the developer tools, props in React DevTools included.

### The component tree of the table

::scheme kosmo

The engine gives the interface only the player view, so `GameTable` cannot show someone else’s cards, and the moves come back up through `onPlayCard` and `onBid`.

| Component | Props | What matters |
| --- | --- | --- |
| `GameTable` | `view`, `onPlayCard`, `onBid` | The only entrance: the player view and two callbacks |
| `OpponentSeat` | `name`, `cardCount`, `isActive`, `isDealer`, `isThinking`, `lastBid` | Only the number of cards comes |
| `TrickArea` | `trick`, `trump` | The cards of the current trick and the trump |
| `BiddingPanel` | `availableBids`, `onBid` | Appears only during the bidding and only on your turn |
| `PlayerHand` | `cards`, `playableIds`, `onPlayCard` | Your cards and the list of the allowed ones |
| `Card` | `card`, `isPlayable`, `onPlay` | Without `onPlay` — just a picture, with `onPlay` — a button |

### The code of the table

```jsx
// PreferansTable.jsx — a preferans table (Kosmo Game Hub): a sketch built on props
// The components know nothing about the engine: they get the “player view” and give moves up.

const SUIT_SYMBOL = { spades: '♠', clubs: '♣', diamonds: '♦', hearts: '♥' };

// The rule of a move: follow suit; no suit — a trump; no trump either — any card
export function getPlayableIds(hand, trick, trump) {
  if (trick.length === 0) return hand.map((c) => c.id); // any card may lead
  const leadSuit = trick[0].card.suit;
  const sameSuit = hand.filter((c) => c.suit === leadSuit);
  if (sameSuit.length > 0) return sameSuit.map((c) => c.id);
  const trumps = trump ? hand.filter((c) => c.suit === trump) : [];
  if (trumps.length > 0) return trumps.map((c) => c.id);
  return hand.map((c) => c.id);
}

// A card: if onPlay was not passed — just a picture, otherwise a button
function Card({ card, isPlayable = false, onPlay }) {
  const label = `${card.rank}${SUIT_SYMBOL[card.suit]}`;
  if (!onPlay) return <span className={`card card--${card.suit}`}>{label}</span>;
  return (
    <button className={`card card--${card.suit}`} disabled={!isPlayable} onClick={() => onPlay(card.id)}>
      {label}
    </button>
  );
}

function CardBack() {
  return <span className="card card--back" aria-label="A face-down card" />;
}

// An opponent: gets only the NUMBER of cards, not the cards themselves
function OpponentSeat({ name, cardCount, isActive, isDealer, isThinking, lastBid }) {
  return (
    <div className={isActive ? 'seat seat--active' : 'seat'}>
      <strong>{name}</strong>{isDealer && ' (deals)'}
      <div className="seat-cards">
        {/* the backs are identical and have no state, so an index as the key is acceptable here */}
        {Array.from({ length: cardCount }, (_, i) => <CardBack key={i} />)}
      </div>
      {lastBid && <p className="bid">Bid: {lastBid}</p>}
      {isThinking && <p className="thinking">thinking…</p>}
    </div>
  );
}

function TrickArea({ trick, trump }) {
  return (
    <div className="trick">
      <p>Trump: {trump ? SUIT_SYMBOL[trump] : 'no trump'}</p>
      {trick.map(({ seat, card }) => (
        <div key={card.id}>
          <small>{seat}</small> <Card card={card} />
        </div>
      ))}
    </div>
  );
}

function BiddingPanel({ availableBids, onBid }) {
  return (
    <div className="bidding">
      {availableBids.map((bid) => (
        <button key={bid} onClick={() => onBid(bid)}>{bid}</button>
      ))}
    </div>
  );
}

function PlayerHand({ cards, playableIds, onPlayCard }) {
  return (
    <div className="hand">
      {cards.map((card) => (
        <Card key={card.id} card={card} isPlayable={playableIds.includes(card.id)} onPlay={onPlayCard} />
      ))}
    </div>
  );
}

// The whole table: all the state comes in the view prop, moves go out through onPlayCard and onBid
export default function GameTable({ view, onPlayCard, onBid }) {
  const { phase, me, opponents, trick, trump, availableBids } = view;

  // a derived value: which cards can be played right now
  const playableIds = phase === 'playing' && me.isActive ? getPlayableIds(me.cards, trick, trump) : [];

  return (
    <div className="table">
      <div className="opponents">
        {opponents.map((o) => (
          <OpponentSeat key={o.name} {...o} /> // the shape of the object matches the props — spread fits here
        ))}
      </div>
      {phase === 'playing' && <TrickArea trick={trick} trump={trump} />}
      {phase === 'bidding' && me.isActive && <BiddingPanel availableBids={availableBids} onBid={onBid} />}
      <PlayerHand cards={me.cards} playableIds={playableIds} onPlayCard={onPlayCard} />
    </div>
  );
}
```

### What the player view looks like

```jsx
// The engine builds such an object for the player “Alexey”. There are no other players’ cards in it
const view = {
  phase: 'playing',
  trump: 'hearts',
  me: {
    name: 'Alexey',
    isActive: true,
    cards: [
      { id: '7S', rank: '7', suit: 'spades' },
      { id: 'QS', rank: 'Q', suit: 'spades' },
      { id: '10D', rank: '10', suit: 'diamonds' },
      { id: 'AH', rank: 'A', suit: 'hearts' },
      { id: 'KC', rank: 'K', suit: 'clubs' },
    ],
  },
  opponents: [
    { name: 'Maria', cardCount: 9, isActive: false, isDealer: true, lastBid: '6♠' },
    { name: 'Bot', cardCount: 10, isActive: false, isThinking: false },
  ],
  trick: [{ seat: 'Maria', card: { id: '9S', rank: '9', suit: 'spades' } }],
  availableBids: ['Pass', '6♠', '6♣', 'Misère'],
};

// engine is a made-up object of your engine
<GameTable view={view} onPlayCard={(id) => engine.play(id)} onBid={(bid) => engine.bid(bid)} />
```

In the example the ranks are written in English letters: A — ace, K — king, Q — queen, J — jack.

### The decisions explained

- **One `Card` — two modes.** The optional function prop `onPlay` turns a card into a button. In a trick the card is simply shown, in the hand it can be played.
- **The list of allowed cards is a derived value.** `playableIds` is computed from the props on every render. In a real project it is better to take the list of allowed moves from the engine, so that the rules live in one place.
- **Spread where it belongs.** An opponent object in `view` matches the props of `OpponentSeat` in shape, so `{...o}` reads easily here.
- **An index as the key — on purpose.** The card backs are identical and have no state, so the trap from section 9 does not work here.
- **Conditional rendering by phase.** The bidding panel is visible only when `phase === 'bidding'` and only on your turn, the trick only when `phase === 'playing'`.

### What the check showed

| The situation at the table | Result |
| --- | --- |
| A lead of 9♠, trump ♥ | Only 7♠ and Q♠ are active |
| A click on the inactive 10♦, then on Q♠ | `onPlayCard` was called once, with `'QS'` |
| A lead of clubs, no clubs, trump ♥ | Only A♥ is active: you have to trump |
| The same without a trump | All the cards are active |
| Not your turn | Not a single active card |
| The opponents Maria (9 cards) and Bot (10 cards) | 9 and 10 backs, not a single open card |
| Bidding, your turn | A panel with bids; a click on 6♣ passed `'6♣'` to `onBid` |
| Bot is moving, `isThinking: true` | Bot has the highlight of the active seat and the caption “thinking…” |

### The link to performance

While the AI is thinking, the engine may update `view` often — for example, the `isThinking` flag. Together with the table the ten cards in the hand re-render too, although nothing has changed for them. If this becomes noticeable, `memo(Card)` and a stable `onPlayCard` through `useCallback` from section 10 will help. Even better is to make the engine not recreate the `me.cards` array when the hand has not changed: then the reference stays the same.
