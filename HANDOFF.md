## 1. О проекте

**Props — Пещеры Графа Пропсулы** — игра-тренажёр по пропсам в React и всем темам, без которых их не понять.
Аудитория — русскоязычный студент фулстак-разработки, в первую очередь сам владелец проекта. Часть примеров
в уроках взята из его проектов: «Умный холодильник» и игровой хаб Kosmo со столом для преферанса.

- **Сеттинг:** спуск по 18 пещерам на трёх ярусах — от простого к сложному. У каждой пещеры свой хозяин-чудище,
  облик которого подсказывает тему. Над всеми — вампир **Граф Пропсула** (учитель), помощник — летучая мышь
  **Лунатик**.
- **Версия:** 2.0.0 (см. `CHANGELOG.md`).
- **Опубликованная копия для игры с телефона:** <https://claude.ai/artifact/VfZVxpLdzTexJmPXvSxpeE>
  (артефакт claude.ai, видим владельцу).
- **Полное руководство по пропсам** (исходный документ, из которого сделаны «Свитки»):
  <https://claude.ai/artifact/Q1ep9hCwaPVEVT9NANzrH4>, копия — `docs/guide.md`.
- **Где жить проекту на компьютере:** `проект/фулстак/Props`.

**Цифры:** 18 пещер на 3 ярусах · 103 карточки урока, из них 95 с кодом — у каждого примера разбор «почему так · как ещё (115 рабочих вариантов) · как нельзя (141 пример)» · 93 схемы и 8 SVG-иллюстраций (на 11 карточках) · 144 задания 8 типов · 117 терминов · 20 разделов руководства в «Свитках» · 18 хозяев пещер + Граф и Лунатик · 345 автотестов.

## 2. Быстрый старт

```bash
npm install        # Node.js 20.19+ или 22.12+
npm run dev        # http://localhost:5173
npm run check      # lint + 345 тестов + сборка — перед каждым коммитом
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | сервер разработки |
| `npm test` / `npm run test:watch` | Vitest: контент и логика |
| `npm run lint` / `npm run format` | ESLint / Prettier |
| `npm run build` / `npm run preview` | сборка в `dist/` (+ `sw.js`) / просмотр сборки |
| `npm run build:artifact` | сборка для предпросмотра claude.ai в `dist-artifact/` (шрифты с Google Fonts, без сервис-воркера) |
| `npm run library` | пересобрать «Свитки» из `docs/guide.md` |
| `npm run check` | всё сразу |

IntelliJ IDEA / WebStorm и плагин Claude Code — пошагово в `docs/INTELLIJ.md`; конфигурации запуска лежат в
`.run/`. Готовый промпт — `docs/PROMPT.md`.

## 10. Известные ограничения

- В предпросмотре claude.ai нет сервис-воркеров, скачиваний и установки — офлайн работает с собственного адреса.
- Прогресс хранится в localStorage конкретного браузера: у артефакта, GitHub Pages и `localhost` он разный.
- Хозяева пещер — SVG: мрачные, но стилизованные, не фотореализм.
- Основной JS-файл сборки — около 0,9 МБ (255 КБ в сжатом виде): контент всех пещер в одном куске; свитки уже
  грузятся отдельно.
- «Анатомия кода» — эвристика по токенам, а не полноценный парсер: на редких конструкциях подсказка может быть
  общей («ключевое слово»).
- Проверка «Объясни Лунатику» — по ключевым словам, смысл не анализирует.
- Тестов компонентов (Testing Library) и e2e-тестов в репозитории пока нет; проверка вёрстки делалась
  скриптами Playwright вне проекта.

## 11. Идеи по развитию

### 11.A. Подача материала

1. **Песочница в карточках.** Редактируемый пример с живым результатом (Sucrase/Babel в браузере + изолированный
   `iframe`): поменял проп — сразу увидел, что изменилось. Самый сильный приём для «пощупать» пропсы.
2. **Рентген рендера.** Анимированное дерево компонентов: проп едет от родителя к ребёнку, перерисованные узлы
   вспыхивают, рядом счётчик рендеров. Связывает пещеры «Поток», «Состояние», «Виртуальный DOM» и «Скорость».
3. **Битвы с хозяевами в конце яруса.** Смешанные задания из шести пещер яруса, у хозяина «здоровье», за ошибку
   он отвечает репликой-насмешкой. Чередование + эмоция + азарт.
4. **Хозяин реагирует в своей пещере.** На ошибку — злорадство и тряска портрета, на серию верных ответов —
   шипение и отступление. Уже есть данные (`threat`, `defeat`) — нужны реплики на ошибки и победы.
5. **Задания на настоящих ошибках React.** Показать реальный текст предупреждения («Each child in a list should
   have a unique key», «Too many re-renders») — найти строку-причину. Учит читать консоль.
6. **Сквозной проект.** Через все три яруса шаг за шагом собрать мини-«Умный холодильник»: каждая пещера
   добавляет в него свой кусок (пропсы, состояние, колбэки, Context, загрузку данных).
7. **Адаптивная сложность.** Ошибся на ★★★ — дать ★★ по той же теме с подсказкой; карта слабых тем по
   конструкциям «анатомии» (какие конструкции чаще путает) → персональная «Ночная охота» на 5 заданий.
8. **Повторение ключевых моментов.** Карточки «ключевой момент» пещер — тоже в интервальное повторение,
   не только задания и термины.
9. **Переключатель JS ↔ TS** у примеров кода: тот же пример с типами пропсов — мостик к пещере типов.
10. **Карта понятий.** Связи терминов словаря (`related`) — интерактивным графом: видно, на чём держится тема.
11. **Режим «кратко / подробно»** у карточек и озвучка текста карточки (Web Speech API, уже используется
    в заклинаниях) — для повторения на ходу.
12. **Объяснение Лунатику с разбором:** подсвечивать в модельном ответе, какие ключевые идеи ученик назвал,
    а какие пропустил.

### 11.B. Работа компонентов и техническая часть

1. **Проверка всех примеров кода парсером** (скрипт + тест): каждый `code` и `alt` должен разбираться
   Babel/Acorn с JSX, каждый `wrong` с синтаксической ошибкой помечен `expectError`. Гарантия, что примеры точны.
2. **Ленивая загрузка пещер:** вынести содержимое каждой пещеры в отдельный кусок (`import()` по маршруту,
   предзагрузка следующей) — основной бандл станет в разы меньше, быстрее старт на телефоне.
3. **Тесты компонентов и e2e:** Vitest + Testing Library для 8 типов заданий и `PracticeRunner`; Playwright для
   прохождения пещеры, ширины 360 px и офлайна (такие проверки уже делались разовыми скриптами при разработке — оформить их в репозитории как `npm run e2e`).
4. **Доступность:** axe-core в тестах; клавиатурный режим для `sort` / `match` / `order` (сейчас — клики).
5. **Обновление офлайн-версии:** при новой сборке показывать «Доступна новая версия — обновить» вместо тихой
   подмены; сообщение «Игра готова работать без интернета» после первого кэширования.
6. **Экспорт и импорт прогресса** в файл (вне iframe) — перенос между устройствами без сервера.
7. **React Compiler** (`babel-plugin-react-compiler` через плагин Vite): проект сам учит компилятору —
   стоит его включить и показать в пещере скорости до/после.
8. **Кэш «анатомии»:** мемоизировать `explainCode(code)` по строке кода; заменить эвристику на разбор Acorn
   (`acorn-jsx`) — точнее определение конструкций.
9. **Хозяева пещер:** вынести общие части SVG (глаза, зубы, свет) в переиспользуемые компоненты; для «жёсткого
   мрачного реализма» — растровые портреты (WebP, тёмный фон) с SVG как запасным вариантом; ленивая загрузка
   портретов вне экрана.
10. **Звук:** громкость, тихий эмбиент пещеры (капли, ветер) с выключателем, отдельная настройка «без звука
    в практике».
