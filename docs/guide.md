# Пропсы в React — полное руководство

Nov 10, 2026 · @Alexey

## 1. Пропсы простыми словами

Пропсы — это данные, которые один компонент передаёт другому, так же как аргументы передаются в функцию. Слово props — сокращение от английского properties, «свойства».

### Сначала два слова о компонентах

**Компонент** — это кусочек интерфейса, оформленный как функция: кнопка, карточка продукта, игральная карта, целая страница. Функция возвращает разметку, а React показывает её на экране.

Компоненты вкладываются друг в друга, как матрёшки. Компонент, который использует внутри себя другой компонент, называют **родительским** (родитель). Тот, кого используют, называют **дочерним** (ребёнок).

### Главная идея на знакомом примере

Функции с параметрами вам уже знакомы по домашним заданиям:

```js
// Обычная функция: значение name приходит снаружи
function greet(name) {
  return `Привет, ${name}!`;
}

greet('Алексей'); // "Привет, Алексей!"
greet('Мария');   // "Привет, Мария!"
```

Компонент React устроен так же. Только аргументы пишутся не в круглых скобках, а как атрибуты HTML-тега:

```jsx
// Компонент: значения приходят снаружи в объекте props
function Greeting(props) {
  return <h1>Привет, {props.name}!</h1>;
}

// Использование: name="Алексей" — это и есть проп
<Greeting name="Алексей" />  // покажет «Привет, Алексей!»
<Greeting name="Мария" />    // покажет «Привет, Мария!»
```

Одна функция даёт разные результаты, потому что получает разные аргументы. Один компонент рисует разные карточки, потому что получает разные пропсы.

### Три бытовые аналогии

| Аналогия | Кто здесь компонент | Что здесь пропсы | Что это объясняет |
| --- | --- | --- | --- |
| Заказ в кафе | Повар | Бланк заказа: блюдо, порция, «без лука» | Повар готовит по бланку и не переписывает его: пропсы только читают |
| Бланк документа | Пустой шаблон карточки | Значения, вписанные в поля | Один шаблон заполняют разными данными: компонент переиспользуется |
| Атрибуты HTML | Тег `<img>` | Атрибуты `src` и `alt` | Свои компоненты получают «атрибуты» так же, как встроенные теги |

### Пример из «Умного холодильника»

```jsx
// Дочерний компонент: «бланк» карточки продукта
function ProductCard(props) {
  return (
    <div className="product-card">
      <h3>{props.name}</h3>
      <p>Количество: {props.quantity} шт.</p>
    </div>
  );
}

// Родительский компонент: заполняет «бланк» данными
function Fridge() {
  return (
    <section>
      <ProductCard name="Молоко" quantity={2} />
      <ProductCard name="Яйца" quantity={10} />
    </section>
  );
}
```

Что здесь происходит:

1. `Fridge` — родитель. Он дважды использует `ProductCard` и каждый раз передаёт другие данные.
2. React вызывает функцию `ProductCard` два раза: с объектом `{ name: 'Молоко', quantity: 2 }` и с объектом `{ name: 'Яйца', quantity: 10 }`.
3. Внутри `ProductCard` значения читаются через точку: `props.name`, `props.quantity`.
4. На экране появляются две разные карточки, хотя код карточки написан один раз.

Фигурные скобки в `quantity={2}` означают «здесь значение JavaScript», а не текст. Подробно об этом в разделе 3.

Одна и та же функция `ProductCard` получает разные объекты props и поэтому рисует разные карточки.

### Пять правил, которые стоит запомнить сразу

- Пропсы идут сверху вниз: от родителя к ребёнку, никогда наоборот.
- Ребёнок пропсы только читает. Менять их внутри компонента нельзя.
- Передать можно любое значение JavaScript: строку, число, массив, объект, функцию и даже кусок разметки.
- Если родитель передал новые пропсы, ребёнок перерисуется с новыми данными.
- Пропсы делают компонент переиспользуемым: один `ProductCard` на сотни продуктов.

Каждое правило подробно разобрано в следующих разделах.

## 2. Как это устроено технически

Технически компонент — это функция, а пропсы — её единственный аргумент: объект, который React собирает из атрибутов JSX. Ниже путь пропа от строчки кода до экрана.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| JSX | Расширение синтаксиса JavaScript для описания разметки | «HTML внутри JS». Браузер его не понимает, поэтому перед запуском JSX переводят в обычный JavaScript |
| Транспиляция JSX | Преобразование JSX в вызовы функций `jsx()` или `React.createElement()` | Автоматический перевод JSX на язык, понятный браузеру. Его делают Babel, esbuild, TypeScript, а Vite запускает их за вас |
| React-элемент | Объект `{ type, key, props }`, описывающий одну часть интерфейса | Записка для React: «нарисуй `ProductCard` вот с такими данными». Это ещё не картинка на экране |
| Рендер | Вызов функции-компонента, чтобы получить описание интерфейса | Момент, когда React спрашивает компонент: «Как ты сейчас выглядишь?» |
| DOM | Document Object Model: дерево узлов страницы в браузере | Настоящие теги на странице, которые видит пользователь |
| Виртуальный DOM | Неофициальное название дерева React-элементов | Черновик страницы в памяти, который React сравнивает с прошлым черновиком |
| Согласование (reconciliation) | Алгоритм сравнения нового дерева элементов с предыдущим | React находит разницу между «было» и «стало» и меняет в DOM только её |

### Путь пропа за пять шагов

1. Вы пишете JSX: `<ProductCard name="Молоко" quantity={2} />`.
2. Сборщик переводит JSX в вызов функции. Все атрибуты складываются в один объект: `jsx(ProductCard, { name: 'Молоко', quantity: 2 })`.
3. Вызов возвращает React-элемент: `{ type: ProductCard, key: null, props: { name: 'Молоко', quantity: 2 } }`.
4. Во время рендера React берёт из элемента `type` и `props` и вызывает `ProductCard(props)`.
5. Компонент возвращает новый JSX. React сравнивает его с прошлым результатом и обновляет в DOM только изменения.

&#91;embedded content: путь пропа от JSX до DOM · 5 шагов\]

Шаги 1–2 случаются один раз при сборке, а шаги 3–5 повторяются в браузере при каждом рендере.

### Шаг 2 крупным планом: во что превращается JSX

```jsx
// Что пишете вы
const element = <ProductCard name="Молоко" quantity={2} />;
```

```js
// Что получается после сборки (автоматический JSX-runtime, React 17 и новее)
import { jsx } from 'react/jsx-runtime';

const element = jsx(ProductCard, { name: 'Молоко', quantity: 2 });

// Классический вариант того же самого: так было до React 17, и это до сих пор работает
const element2 = React.createElement(ProductCard, { name: 'Молоко', quantity: 2 });
```

Оба варианта получены сборщиком esbuild из одной и той же строки JSX. Атрибуты превратились в ключи объекта: `name="Молоко"` стал `name: 'Молоко'`, а `quantity={2}` стал `quantity: 2`.

### Шаг 3 крупным планом: что внутри React-элемента

```js
console.log(element);
// {
//   $$typeof: Symbol(react.transitional.element), // метка «это настоящий React-элемент»
//   type: ProductCard,                            // ЧТО рисовать: ваша функция
//   key: null,                                    // ключ для списков, см. раздел 9
//   props: { name: 'Молоко', quantity: 2 },       // С ЧЕМ рисовать: пропсы
//   _owner: …, _store: …                          // служебные поля режима разработки
// }
```

- `type` отвечает на вопрос «что рисовать». Для своего компонента это функция, для HTML-тега — строка, например `'div'`.
- `props` отвечает на вопрос «с какими данными рисовать».
- `$$typeof` защищает от подделки. Значение типа Symbol нельзя передать через JSON, поэтому чужие данные с сервера не притворятся элементом.

Вывод получен на React 19.3.1. В режиме разработки объект `props` ещё и заморожен через `Object.freeze`, чтобы его нельзя было случайно изменить. Подробнее в разделе 5.

### Что из этого следует на практике

- **Пропсы — это один объект.** Запись `function ProductCard(name, quantity)` не работает: в `name` придёт весь объект пропсов, а `quantity` окажется `undefined`. Проверено запуском.
- **Имя пропа — это ключ объекта.** Поэтому пропсы называют как переменные JavaScript: `expiryDate`, `onDelete`, `isAdmin`.
- **Содержимое между тегами — тоже проп.** `<Modal title="Ошибка">Текст</Modal>` превращается в `jsx(Modal, { title: 'Ошибка', children: 'Текст' })`. Это проп `children`, ему посвящён раздел 8.
- **`key` в пропсы не попадает.** Сборщик передаёт его отдельным аргументом: `jsx(Card, { name: 'Молоко' }, 'milk')`. Если прочитать `props.key`, React предупредит в консоли и вернёт `undefined`.
- **Имя компонента пишется с большой буквы.** `<ProductCard />` превращается в ссылку на функцию, а `<productCard />` — в строку `'productCard'`. React примет её за неизвестный HTML-тег.

### Эксперимент: компонент — это просто функция

```jsx
// Только для понимания! В приложении компоненты так не вызывают
const result = ProductCard({ name: 'Молоко', quantity: 2 });

console.log(result.type);            // 'div' — компонент вернул описание <div>
console.log(result.props.className); // 'product-card'
```

Вызов сработал, потому что компонент — обычная функция JavaScript. Но в приложении вызывать компонент должен только React. Иначе он не сможет следить за состоянием компонента, его хуками и перерисовками.

## 3. Передача пропсов: что и как можно передать

Проп передают как атрибут в JSX: имя, знак «равно» и значение. Строку можно записать в кавычках, всё остальное записывают в фигурных скобках.

### Простыми словами

Кавычки означают «вот готовый текст, передай как есть». Фигурные скобки открывают «окно в JavaScript»: внутри можно написать число, переменную, вычисление или вызов функции.

Внутри скобок допустимо только **выражение** — код, который вычисляется в значение: `2`, `daysLeft < 0`, `user.name`, `calcTotal(products)`. **Инструкции** вроде `if`, `for` или `let x = 1` ничего не возвращают, поэтому туда не помещаются.

### Справочная таблица: все виды значений

| Что передаём | Как записать | Что придёт в props |
| --- | --- | --- |
| Строка | `unit="шт."` | `'шт.'` |
| Число | `quantity={2}` | `2` |
| `true` короткой записью | `isFavorite` | `true` |
| Логическое выражение | `isExpired={daysLeft < 0}` | `true` или `false` |
| Массив | `tags={['молочное', 'охлаждённое']}` | массив из двух строк |
| Объект | `expiry={{ date: '2026-11-13', daysLeft: 3 }}` | объект с двумя полями |
| Функция | `onDelete={handleDelete}` | сама функция, а не результат её вызова |
| JSX-разметка | `badge={<span>Скоро истекает</span>}` | React-элемент |
| Пустое значение | `expiry={null}` | `null` |
| Проп не передали | — | `undefined` |

### Строки

Записи `name="Молоко"` и `name={'Молоко'}` означают одно и то же. Кавычки — просто короткий способ передать готовую строку. Если строку нужно собрать из переменных, берут шаблонную строку внутри фигурных скобок:

```jsx
const daysLeft = 3;

<ProductCard title={`Осталось ${daysLeft} дн.`} /> // title === 'Осталось 3 дн.'
```

### Числа: главная ловушка

```jsx
function Qty({ quantity }) {
  return <p>Будет: {quantity + 1}</p>;
}

<Qty quantity="2" />  // «Будет: 21» — пришла строка '2', а '2' + 1 склеивает строки
<Qty quantity={2} />  // «Будет: 3» — пришло число 2
```

Кавычки всегда дают строку, даже если внутри цифры. Числа, логические значения, массивы и объекты передают только в фигурных скобках. Оба результата проверены запуском.

### Логические значения

```jsx
<ProductCard isFavorite />               // то же, что isFavorite={true}
<ProductCard isFavorite={false} />       // false нужно писать явно
<ProductCard />                          // isFavorite не передан: придёт undefined
<ProductCard isExpired={daysLeft < 0} /> // результат сравнения: true или false
```

В условии `undefined` ведёт себя как `false`, поэтому непереданный логический проп обычно работает как «нет». Есть отличие от обычного HTML: в браузере `disabled="false"` всё равно отключает кнопку. А в React `<button disabled={false}>` превращается в `<button>` без атрибута — это тоже проверено.

### Массивы и объекты: двойные фигурные скобки

```jsx
<ProductCard tags={['молочное', 'охлаждённое']} />
<ProductCard expiry={{ date: '2026-11-13', daysLeft: 3 }} />
<div style={{ color: 'red', fontSize: 14 }}>Просрочено</div>
```

Двойные скобки — не особый синтаксис. Внешние скобки открывают «окно в JavaScript», а внутренние — обычный литерал объекта. Вторая строка равносильна такой записи:

```jsx
const expiry = { date: '2026-11-13', daysLeft: 3 };

<ProductCard expiry={expiry} />
```

### Функции: передаём ссылку, а не результат

```jsx
<ProductCard onDelete={handleDelete} />                   // передаём саму функцию
<ProductCard onDelete={() => handleDelete(product.id)} /> // обёртка, если нужен аргумент
<ProductCard onDelete={handleDelete()} />                 // ОШИБКА: функция вызовется сразу при рендере
```

В третьей строке в проп попадёт не функция, а то, что она вернула. Функциям в пропсах посвящён раздел 7.

### JSX как значение пропа

```jsx
<ProductList
  products={products}
  emptyState={<p>Холодильник пуст. Пора в магазин!</p>}
/>
```

Компонент получит готовый кусок разметки и сам решит, где его показать. На этом построены «слоты» из раздела 8.

### Spread: передать все поля объекта разом

**Spread-синтаксис** `{...obj}` раскладывает объект на отдельные пропсы, как раскладывают покупки из пакета на полки.

```jsx
const product = { name: 'Молоко', quantity: 2 };

<ProductCard {...product} />
// то же самое, что:
<ProductCard name={product.name} quantity={product.quantity} />
```

Порядок важен: если имя повторяется, побеждает то, что записано правее.

```jsx
<ProductCard {...product} quantity={0} /> // quantity === 0
<ProductCard quantity={0} {...product} /> // quantity === 2
```

Документация React советует не злоупотреблять spread ([источник](https://react.dev/learn/passing-props-to-a-component)). Если он стоит в каждом втором компоненте, уже непонятно, какие пропсы реально нужны каждому из них.

### Полный пример: карточка со всеми видами пропсов

```jsx
function FridgeShelf() {
  const product = { id: 7, name: 'Молоко', quantity: 2 };
  const daysLeft = 3;

  function handleDelete(id) {
    console.log('Удалить продукт', id);
  }

  return (
    <ProductCard
      name={product.name}                       // строка из объекта
      quantity={product.quantity}               // число
      unit="шт."                                // строка-литерал
      tags={['молочное', 'охлаждённое']}        // массив
      expiry={{ date: '2026-11-13', daysLeft }} // объект
      isFavorite                                // true
      isExpired={daysLeft < 0}                  // логическое выражение
      onDelete={() => handleDelete(product.id)} // функция
      badge={<span className="badge">Скоро истекает</span>} // JSX
      title={`Осталось ${daysLeft} дн.`}        // шаблонная строка
    />
  );
}
```

Запись `{ date: '2026-11-13', daysLeft }` использует сокращение JavaScript: `daysLeft` здесь значит `daysLeft: daysLeft`. Комментарии `//` между атрибутами допустимы: сборщик их просто вырезает.

Вот что получил компонент в проверочном запуске (имя пропа, тип, значение):

```text
name:       string = "Молоко"
quantity:   number = 2
unit:       string = "шт."
tags:       array  = ["молочное","охлаждённое"]
expiry:     object = {"date":"2026-11-13","daysLeft":3}
isFavorite: boolean = true
isExpired:  boolean = false
onDelete:   function
badge:      React-элемент
title:      string = "Осталось 3 дн."
```

## 4. Получение пропсов: как прочитать то, что передали

Компонент получает все пропсы одним объектом. Читать его можно через точку (`props.name`) или сразу распаковать на отдельные переменные деструктуризацией — так пишут чаще всего.

### Способ 1. Объект props целиком

```jsx
function ProductCard(props) {
  return (
    <h3>
      {props.name} — {props.quantity} {props.unit}
    </h3>
  );
}
```

Удобно, когда пропсов мало или объект нужно целиком передать дальше. Минус: по первой строке функции не видно, какие пропсы компонент ожидает.

### Способ 2. Деструктуризация прямо в параметрах

**Деструктуризация** — синтаксис JavaScript, который достаёт поля объекта в отдельные переменные. Простыми словами: распаковать коробку и разложить вещи по полкам.

```jsx
// Распаковываем пропсы прямо в скобках параметров
function ProductCard({ name, quantity, unit }) {
  return (
    <h3>
      {name} — {quantity} {unit}
    </h3>
  );
}
```

Это ровно то же самое, что:

```jsx
function ProductCard(props) {
  const { name, quantity, unit } = props; // та же деструктуризация, но отдельной строкой
  // ...
}
```

Этот способ считается стандартным в документации React. Список пропсов виден сразу, как список параметров у обычной функции.

Частая ошибка — забыть фигурные скобки:

```jsx
function ProductCard(name) { // ОШИБКА: нет { }
  return <h3>{name}</h3>;    // name — это весь объект { name: 'Молоко' }
}
```

В проверочном запуске React упал с ошибкой «Objects are not valid as a React child (found: object with keys {name})». Смысл: объект нельзя вывести на экран как текст.

### Значения по умолчанию

```jsx
function ProductCard({ name, quantity = 1, unit = 'шт.' }) {
  return <p>{name}: {quantity} {unit}</p>;
}
```

`quantity = 1` читается так: «если `quantity` не передали, считай его равным 1». Срабатывает оно только для `undefined`:

| Что передал родитель | Что получит компонент |
| --- | --- |
| Ничего: `<ProductCard name="Молоко" />` | `1` |
| `quantity={undefined}` | `1` |
| `quantity={null}` | `null` — значение по умолчанию не сработало |
| `quantity={0}` | `0` — ноль тоже настоящее значение |

Все четыре строки проверены запуском. Если нужно подменять и `null`, поможет оператор `??` («объединение с null»): `const q = quantity ?? 1;` подставит 1 и для `null`, и для `undefined`.

Раньше значения по умолчанию задавали так: `ProductCard.defaultProps = { quantity: 1 }`. В React 19 для функциональных компонентов это убрали: запись молча игнорируется, и в проверочном запуске компонент получил `undefined`. Подробнее в разделе 11.

### Переименование при распаковке

```jsx
// Проп называется name, а внутри компонента удобнее playerName
function PlayerSeat({ name: playerName, isDealer }) {
  return <p>{playerName}{isDealer ? ' (сдаёт)' : ''}</p>;
}
```

Запись `name: playerName` значит «возьми поле `name` и положи в переменную `playerName`». Слева от двоеточия — имя пропа, справа — имя переменной.

### Вложенная деструктуризация

```jsx
// expiry = { date: '2026-11-13', daysLeft: 3 }
function ExpiryBadge({ expiry: { date, daysLeft } = {} }) {
  if (!date) return <span>Срок не указан</span>;
  return <span>До {date}, осталось {daysLeft} дн.</span>;
}
```

Хвост `= {}` защищает от падения. Без него `<ExpiryBadge />` без пропа `expiry` падает с ошибкой «Cannot read properties of undefined (reading 'date')». Проверено запуском.

### Остаточные пропсы: ...rest

**Rest-синтаксис** `...rest` собирает в один объект всё, что вы не распаковали по имени. Простыми словами: «всё остальное — в этот пакет».

```jsx
// Своя кнопка для холодильника: сама знает только variant, остальное отдаёт <button>
function FridgeButton({ variant = 'primary', ...rest }) {
  // rest = { disabled: true, title: 'Удалить продукт', children: 'Удалить' }
  return <button className={`btn btn-${variant}`} {...rest} />;
}

<FridgeButton variant="danger" disabled title="Удалить продукт">
  Удалить
</FridgeButton>
// Результат: <button class="btn btn-danger" disabled="" title="Удалить продукт">Удалить</button>
```

В параметрах `...rest` собирает пропсы в объект, а в JSX `{...rest}` снова раскладывает их на атрибуты. Так устроены обёртки над HTML-элементами: им не нужно перечислять все возможные атрибуты кнопки. Результат в комментарии получен запуском.

### Классовые компоненты: this.props

В старом коде встречаются компоненты-классы. Пропсы там лежат в `this.props`:

```jsx
import { Component } from 'react';

class ProductCard extends Component {
  static defaultProps = { quantity: 1 }; // у классов defaultProps работает и в React 19

  render() {
    const { name, quantity } = this.props; // пропсы читаются из this.props
    return <p>{name}: {quantity}</p>;
  }
}
```

Новый код пишут на функциях. Классы стоит уметь читать: они ещё встречаются в старых проектах и статьях.

### Какой способ выбрать

| Способ | Запись | Когда использовать |
| --- | --- | --- |
| Деструктуризация | `function Card({ name, quantity })` | По умолчанию, почти всегда |
| Значения по умолчанию | `{ quantity = 1 }` | Для необязательных пропсов |
| Объект целиком | `function Card(props)` | Пропсов мало или объект нужно передать дальше |
| Переименование | `{ name: playerName }` | Имя пропа неудобно или конфликтует с переменной |
| Остаточные пропсы | `{ variant, ...rest }` | Обёртки над HTML-элементами и чужими компонентами |
| `this.props` | `class Card extends Component` | Только для чтения старого кода |

## 5. Однонаправленный поток данных и неизменяемость пропсов

Данные в React текут только сверху вниз, от родителя к детям, и ребёнок свои пропсы не меняет. Благодаря этим двум правилам любое значение на экране можно отследить: достаточно пройти по дереву компонентов вверх.

### Простыми словами

Представьте водопровод в многоэтажке. Вода приходит из бака на крыше и по трубам спускается на каждый этаж. Жилец пятого этажа пользуется водой, но не может закачать её обратно в бак.

Если жильцу нужно что-то поменять, он звонит управляющему. В React это вызов функции, которую родитель передал ребёнку в пропсах (раздел 7). Бак на крыше — это **состояние** родителя, трубы — пропсы.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| Однонаправленный поток данных (one-way data flow) | Данные передаются только от родителя к потомкам через пропсы | Данные текут вниз по дереву, как вода по трубам |
| Дерево компонентов | Иерархия, в которой у каждого компонента один родитель | Схема «кто внутри кого», как генеалогическое древо |
| Потомок | Любой компонент ниже по дереву: ребёнок, «внук» и так далее | Все, кто живёт этажами ниже |
| Неизменяемость (immutability) | Данные не меняют после создания, для изменений создают новый объект | Не исправлять оригинал, а делать новую копию с правкой |
| Мутация | Изменение существующего объекта или массива на месте | Исправить запись прямо в оригинале документа |
| Только для чтения (read-only) | Значение можно прочитать, но нельзя присвоить новое | Документ под стеклом: смотреть можно, исправлять нельзя |
| Чистая функция | При одинаковых входных данных даёт одинаковый результат и ничего не меняет снаружи | Калькулятор: на 2 + 2 всегда отвечает 4 и не трогает ничего вокруг |
| Побочный эффект (side effect) | Любое действие функции, кроме возврата результата | Функция «сделала что-то ещё»: поменяла внешнюю переменную или отправила запрос |

### Как текут данные по дереву

&#91;embedded content: дерево компонентов · данные сверху вниз\]

Рядом с каждой стрелкой подписан проп, который родитель отдаёт ребёнку.

В «Умном холодильнике» список продуктов хранит `App`. Он отдаёт массив в `ProductList`, а тот раздаёт по одному продукту каждой `ProductCard`. Ни один ребёнок не может подняться и переписать массив у `App` напрямую.

### Почему пропсы нельзя менять: эксперимент

```jsx
function ProductCard(props) {
  props.quantity = props.quantity - 1; // ОШИБКА: пытаемся изменить чужие данные
  return <p>{props.name}: {props.quantity}</p>;
}

<ProductCard name="Молоко" quantity={2} />
```

| Режим сборки | Что произошло в проверочном запуске |
| --- | --- |
| Разработка (development) | Ошибка «TypeError: Cannot assign to read only property 'quantity' of object» |
| Продакшен (production) | Ошибки нет, на экране «Молоко: 1». Но изменился только временный объект пропсов этого рендера: данные родителя прежние |

В режиме разработки React замораживает объект пропсов (`Object.freeze`), чтобы такие ошибки сразу бросались в глаза. В продакшене заморозку отключают ради скорости, поэтому ошибка становится тихой. Тихая ошибка опаснее громкой.

### Ловушка: заморозка неглубокая

```jsx
const milk = { id: 1, name: 'Молоко', quantity: 2 }; // объект принадлежит родителю

function ProductCard({ product }) {
  product.quantity -= 1; // ошибки НЕ будет: заморожен только сам объект props
  return <p>{product.name}: {product.quantity}</p>;
}

<ProductCard product={milk} />
// После рендера milk.quantity === 1 — объект родителя испорчен
```

`Object.freeze` замораживает только верхний уровень. Объект `product` внутри пропсов остаётся изменяемым, и мутация проходит без единого предупреждения. React при этом ничего не узнаёт и не перерисует другие места, где показан этот продукт. Проверено запуском в обоих режимах.

### Как правильно: «изменить проп» значит «попросить владельца данных»

```jsx
import { useState } from 'react';

// Ребёнок ничего не меняет сам — только сообщает о желании
function ProductCard({ product, onEat }) {
  return (
    <div>
      <p>{product.name}: {product.quantity} шт.</p>
      <button onClick={() => onEat(product.id)}>Съесть одну</button>
    </div>
  );
}

// Родитель — владелец данных: он создаёт НОВЫЙ массив и НОВЫЙ объект
function Fridge() {
  const [products, setProducts] = useState([
    { id: 1, name: 'Молоко', quantity: 2 },
    { id: 2, name: 'Яйца', quantity: 10 },
  ]);

  function handleEat(id) {
    setProducts(
      products.map((p) =>
        p.id === id ? { ...p, quantity: p.quantity - 1 } : p // копия с правкой вместо мутации
      )
    );
  }

  return products.map((p) => (
    <ProductCard key={p.id} product={p} onEat={handleEat} />
  ));
}
```

Разбор по шагам:

1. `ProductCard` не трогает `product`. Он вызывает `onEat(product.id)` — «звонит управляющему».
2. `Fridge` создаёт новый массив через `map` и новый объект через `{ ...p, quantity: ... }`. Старые данные остаются нетронутыми.
3. `setProducts` сообщает React о новом состоянии. React перерисует `Fridge`, и все карточки получат свежие пропсы.

### Компонент должен быть чистым

React рассчитывает, что компонент ведёт себя как формула: одинаковые пропсы дают одинаковый JSX. Во время рендера компонент не должен менять ничего, что существовало до его вызова ([документация React](https://react.dev/learn/keeping-components-pure)).

```jsx
let renderedCards = 0; // переменная снаружи компонента

// ПЛОХО: компонент меняет внешнюю переменную во время рендера
function ProductCard({ name }) {
  renderedCards = renderedCards + 1; // побочный эффект
  return <p>№{renderedCards}: {name}</p>;
}
```

Номера в таком списке зависят от того, сколько раз React вызвал функцию. В режиме разработки внутри `<StrictMode>` React специально вызывает компоненты дважды, чтобы такие ошибки были видны. Номера начнут «прыгать».

```jsx
// ХОРОШО: всё нужное приходит в пропсах
function ProductCard({ name, position }) {
  return <p>№{position}: {name}</p>;
}

// Номер вычисляет родитель из индекса в массиве
{products.map((p, i) => (
  <ProductCard key={p.id} name={p.name} position={i + 1} />
))}
```

### Пропсы — это снимок

Документация React называет пропсы «снимками во времени»: каждый рендер получает свою новую версию пропсов ([источник](https://react.dev/learn/passing-props-to-a-component)). Простыми словами: каждый рендер — новая фотография. Старую фотографию не перерисовывают, а делают новую.

Если родитель сначала передал `quantity={2}`, а потом `quantity={1}`, первый объект пропсов не меняется. React создаёт второй объект и снова вызывает компонент.

## 6. Пропсы и состояние (state): в чём разница

Пропсы компонент получает снаружи и только читает, а состояние хранит сам и может менять. Состояние одного компонента очень часто становится пропсами его детей.

### Простыми словами

Документация React сравнивает пропсы с аргументами функции, а состояние — с памятью компонента. Аналогия из жизни: состояние — ваш собственный холодильник, вы сами кладёте и достаёте продукты.

Пропсы — записка от соседа «возьми молоко». Её можно прочитать и выполнить, но переписывать бессмысленно: у соседа останется свой экземпляр.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| Состояние (state) | Данные, которые компонент хранит между рендерами и меняет через сеттер | Память компонента |
| Хук (hook) | Специальная функция React, имя которой начинается с `use` | «Крючок», которым компонент цепляется за возможности React |
| `useState` | Хук, который создаёт переменную состояния и функцию для её изменения | «Дай мне ячейку памяти и кнопку, чтобы её менять» |
| Сеттер (set-функция) | Функция вида `setProducts`, которая заменяет значение состояния и запускает перерисовку | Кнопка «сохранить новое значение и обновить экран» |
| Перерисовка (re-render) | Повторный вызов функции-компонента с новыми данными | Компонент «перефотографировали» со свежими данными |
| Производное значение | Значение, которое можно вычислить из пропсов или состояния | Не хранится отдельно, а посчитывается на лету |

### Сравнение пропсов и состояния

| Вопрос | Пропсы | Состояние |
| --- | --- | --- |
| Откуда берутся | Их передаёт родитель | Компонент создаёт сам через `useState` |
| Кто может изменить | Только родитель, передав новые значения | Только сам компонент, через сеттер |
| Можно ли присвоить напрямую | Нет | Нет: только через сеттер |
| Что запускает перерисовку | Перерисовка родителя | Вызов сеттера с новым значением |
| Аналогия | Аргументы функции | Память компонента |
| Пример из холодильника | `product` у `ProductCard` | `products` у `App` |

### Одни и те же данные: состояние для одного, пропсы для другого

```jsx
import { useState } from 'react';

function App() {
  // СОСТОЯНИЕ App: список продуктов живёт здесь
  const [products, setProducts] = useState([
    { id: 1, name: 'Молоко', quantity: 2 },
    { id: 2, name: 'Яйца', quantity: 10 },
  ]);

  return (
    <main>
      {/* Состояние App становится ПРОПСАМИ детей */}
      <FridgeSummary count={products.length} />
      <ProductList products={products} />
    </main>
  );
}

function FridgeSummary({ count }) {
  // Для FridgeSummary count — это пропс: читаем и показываем
  return <p>Продуктов в холодильнике: {count}</p>;
}
```

Для `App` массив `products` — состояние: он его создал и может менять через `setProducts`. Для `ProductList` тот же массив — пропсы, их можно только читать. Роль данных зависит от того, чей компонент на них смотрит.

### Цикл перерисовки

1. Пользователь нажимает кнопку.
2. Обработчик вызывает сеттер, например `setProducts(newProducts)`.
3. React запоминает новое состояние и снова вызывает компонент-владелец состояния.
4. Компонент возвращает JSX с новыми значениями пропсов для детей.
5. React вызывает детей с новыми пропсами и обновляет в DOM только те места, что изменились.

&#91;embedded content: цикл перерисовки · 5 шагов\]

Подсвечен шаг, который запускает весь круг: без вызова сеттера новых пропсов не будет.

### Важная деталь: дети перерисовываются вместе с родителем

По умолчанию React перерисовывает всех детей вместе с родителем, даже тех, чьи пропсы не изменились. В проверочном запуске ребёнок с постоянным пропом `label` перерисовался после клика по кнопке родителя.

Обычно это не проблема: в DOM React всё равно меняет только реальные отличия. Как пропустить лишние перерисовки, когда они действительно мешают, рассказано в разделе 10.

### Ловушка: копирование пропа в состояние

```jsx
// ПЛОХО: состояние «запоминает» проп только на первом рендере
function ProductCard({ quantity }) {
  const [qty, setQty] = useState(quantity);
  return <p>{qty} шт.</p>;
}
```

Аргумент `useState(quantity)` используется только один раз, при первом рендере. В проверочном запуске родитель сначала передал `quantity={2}`, потом `quantity={1}`. Проп стал 1, а на экране осталось 2.

```jsx
// ХОРОШО: читаем проп напрямую, а производное значение вычисляем при рендере
function ProductCard({ quantity }) {
  const isRunningOut = quantity <= 1; // пересчитывается при каждом рендере
  return <p>{quantity} шт.{isRunningOut ? ' — пора докупить' : ''}</p>;
}

// Если нужно именно НАЧАЛЬНОЕ значение, скажите об этом в имени пропа
function QuantityEditor({ initialQuantity }) {
  const [quantity, setQuantity] = useState(initialQuantity);
  // дальше компонент сам управляет quantity, новые initialQuantity игнорирует
  return <input type="number" value={quantity} onChange={(e) => setQuantity(Number(e.target.value))} />;
}
```

Приставка `initial` честно предупреждает того, кто будет использовать компонент: позже переданные значения учитываться не будут.

### Где хранить данные: три вопроса

1. Можно ли вычислить значение из пропсов или другого состояния? Если да — не храните его, вычисляйте при рендере.
2. Меняется ли оно со временем и нужно ли только одному компоненту? Если да — это состояние этого компонента.
3. Нужно ли оно нескольким компонентам? Если да — храните в их общем родителе, а детям передавайте пропсами. Это подъём состояния из раздела 7.

## 7. Функции в пропсах: «данные вниз, события вверх»

Ребёнок не может изменить данные родителя, но может сообщить ему о событии. Для этого родитель передаёт в пропсах функцию, а ребёнок вызывает её в нужный момент. Коротко: данные идут вниз, события — вверх.

### Простыми словами

Родитель даёт ребёнку пульт с одной кнопкой. Ребёнок не знает, что именно делает кнопка: он нажимает её в нужный момент и сообщает подробности, например «удалить продукт номер 7». Что сделать с этим сообщением, решает родитель.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| Колбэк (callback) | Функция, которую передают другой функции или компоненту, чтобы тот вызвал её позже | «Перезвони мне, когда что-то случится». Вы уже встречали колбэки в функциях высшего порядка |
| Обработчик события (event handler) | Функция, которую React вызывает в ответ на действие пользователя | Реакция на клик, ввод текста или отправку формы |
| Проп-событие | Проп-функция с именем на `on`: `onDelete`, `onSearch` | Канал, по которому ребёнок сообщает родителю о событии |
| Подъём состояния (lifting state up) | Перенос состояния из детей в их ближайшего общего родителя | Вместо двух холодильников в разных комнатах — один на общей кухне |
| Единый источник истины | Каждое значение хранится ровно в одном месте | У данных один хозяин, остальные получают их через пропсы |

### Соглашение об именах

| Что называем | Правило | Примеры |
| --- | --- | --- |
| Проп-функцию, которую получает ребёнок | `on` + событие с большой буквы | `onDelete`, `onSearch`, `onCardPlay` |
| Функцию-обработчик в родителе | `handle` + событие | `handleDelete`, `handleSearch` |

Такие имена рекомендует документация React ([источник](https://react.dev/learn/responding-to-events)). Называйте пропсы по смыслу события в приложении (`onDelete`), а не по действию мышью (`onButtonClick`). Тогда тот же проп потом можно будет вызвать и с клавиатуры.

### Схема: данные вниз, события вверх

&#91;embedded content: данные вниз, события вверх\]

Сплошная стрелка — пропсы, которые идут вниз; пунктир — вызов функции, который идёт вверх.

### Пример 1. Удаление продукта

```jsx
import { useState } from 'react';

// Ребёнок: показывает продукт и СООБЩАЕТ о желании его удалить
function ProductCard({ product, onDelete }) {
  return (
    <li>
      {product.name} — {product.quantity} шт.
      <button onClick={() => onDelete(product.id)}>Удалить</button>
    </li>
  );
}

// Родитель: хранит список и РЕШАЕТ, что значит «удалить»
function ProductList() {
  const [products, setProducts] = useState([
    { id: 1, name: 'Молоко', quantity: 2 },
    { id: 7, name: 'Яйца', quantity: 10 },
    { id: 9, name: 'Сыр', quantity: 1 },
  ]);

  function handleDelete(id) {
    setProducts(products.filter((p) => p.id !== id)); // новый массив без удалённого
  }

  return (
    <ul>
      {products.map((p) => (
        <ProductCard key={p.id} product={p} onDelete={handleDelete} />
      ))}
    </ul>
  );
}
```

Что происходит после клика по «Удалить» у яиц:

1. `ProductList` заранее передал функцию `handleDelete` под именем `onDelete`.
2. Клик запускает стрелочную функцию, и она вызывает `onDelete(7)`.
3. На самом деле выполняется `handleDelete(7)`: родитель создаёт массив без яиц и вызывает `setProducts`.
4. React перерисовывает список. В проверочном запуске до клика было «Молоко, Яйца, Сыр», после — «Молоко, Сыр».

### Типичная ошибка: вызов вместо передачи

```jsx
<button onClick={onDelete(product.id)}>Удалить</button>       // ОШИБКА
<button onClick={() => onDelete(product.id)}>Удалить</button> // ПРАВИЛЬНО
```

В первой строке `onDelete` вызывается сразу, во время рендера. В проверочном запуске все три продукта удалились сами, без единого клика. React при этом предупредил: «Cannot update a component while rendering a different component».

Стрелочная функция во второй строке откладывает вызов до клика. Правило простое: во время рендера функции-пропсы не вызывают, их вызывают только из обработчиков событий.

### Пример 2. Подъём состояния: поиск по холодильнику

Задача: поле поиска `SearchBar` и список `ProductList` должны знать один и тот же текст запроса. Это соседи, а соседи не могут передавать друг другу пропсы напрямую. Решение: поднять состояние `query` в их общего родителя `FridgePage`.

&#91;embedded content: подъём состояния · до и после\]

После подъёма оба ребёнка получают данные из одного места, а поле поиска сообщает о новом тексте через `onQueryChange`.

```jsx
import { useState } from 'react';

// Поле поиска: само ничего не хранит, всё получает от родителя
function SearchBar({ query, onQueryChange }) {
  return (
    <input
      value={query}                                   // значение пришло сверху
      onChange={(e) => onQueryChange(e.target.value)} // событие ушло наверх
      placeholder="Найти продукт"
    />
  );
}

// Список: показывает только то, что дали
function ProductList({ products }) {
  if (products.length === 0) return <p>Ничего не найдено</p>;
  return (
    <ul>
      {products.map((p) => <li key={p.id}>{p.name}</li>)}
    </ul>
  );
}

// Общий родитель — единственный владелец query
function FridgePage({ products }) {
  const [query, setQuery] = useState('');

  // производное значение: вычисляем при рендере, а не храним
  const visible = products.filter((p) =>
    p.name.toLowerCase().includes(query.toLowerCase())
  );

  return (
    <section>
      <SearchBar query={query} onQueryChange={setQuery} />
      <ProductList products={visible} />
    </section>
  );
}
```

Результат проверочного запуска на продуктах «Молоко», «Яйца», «Сыр»:

| Ввели в поле | Показал список |
| --- | --- |
| `мол` | Молоко |
| `ы` | Сыр |
| `хлеб` | Ничего не найдено |
| пустая строка | Молоко, Яйца, Сыр |

Запись `onQueryChange={setQuery}` передаёт сеттер напрямую, и это нормально. Если позже понадобится дополнительная логика, её добавят в родительский `handleQueryChange`, а `SearchBar` менять не придётся.

### Как передать данные вместе с событием

- **Один аргумент:** `onDelete(product.id)`.
- **Несколько значений:** удобнее один объект, например `onSearch({ username, dish })`. Порядок не важен, а имена полей объясняют сами себя.
- **Перевод DOM-события в данные:** ребёнок достаёт `e.target.value` и отдаёт наверх простой текст. Родителю не нужно знать, что внутри был именно `<input>`.

## 8. Проп children и композиция

Всё, что стоит между открывающим и закрывающим тегом компонента, приходит в него как проп `children`. Так строят обёртки — карточки, модальные окна, раскладки страницы, — которые не знают заранее, что окажется внутри.

### Простыми словами

Документация React называет `children` «дыркой», которую родитель заполняет любым содержимым. Бытовая аналогия — рамка для фотографий: рамка одна, а фотографии в ней разные. Рамка отвечает за оформление и не задумывается, что изображено на снимке.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| Композиция (composition) | Построение интерфейса вложением одних компонентов в другие | Сборка интерфейса из деталей, как из конструктора |
| `children` | Особый проп с содержимым между тегами компонента | «Начинка» компонента |
| Обёртка (wrapper) | Компонент, который добавляет оформление или поведение вокруг чужого содержимого | Рамка вокруг картины |
| Слот (slot) | Именованное место в компоненте, куда родитель вставляет разметку через проп | Подписанная ячейка: «сюда заголовок, сюда кнопки» |
| ReactNode | Всё, что React умеет отрисовать: строка, число, элемент, массив, `null`, `undefined`, `true` и `false` | Любое содержимое, которое можно положить в JSX |
| Портал (portal) | Отрисовка детей в другой DOM-узел через `createPortal` | Телепорт: компонент живёт в одном месте дерева, а виден в другом месте страницы |

### Как это устроено технически

`children` — обычный ключ объекта пропсов, просто его заполняет сборщик. Запись `<Modal title="Ошибка">Текст</Modal>` превращается в `jsx(Modal, { title: 'Ошибка', children: 'Текст' })`. Форма значения зависит от того, что стоит между тегами:

| Что между тегами | Что придёт в `children` |
| --- | --- |
| Текст: `<Card>Текст</Card>` | строка |
| Один тег: `<Card><b /></Card>` | один React-элемент |
| Несколько тегов: `<Card><b /><b /></Card>` | массив из двух элементов |
| Ничего: `<Card />` | `undefined` |

Все четыре случая проверены запуском. Вывод: не стройте логику на форме `children`. Если компоненту нужно что-то посчитать или перебрать, передайте ему массив данных обычным пропом.

### Пример 1. Карточка-обёртка

```jsx
function Card({ title, children }) {
  return (
    <section className="card">
      <h2 className="card-title">{title}</h2>
      <div className="card-body">{children}</div> {/* сюда встанет всё, что передали */}
    </section>
  );
}

function FridgeDashboard() {
  return (
    <>
      <Card title="Скоро истекает срок">
        <p>Молоко — до 13 ноября</p>
        <p>Йогурт — до 14 ноября</p>
      </Card>

      <Card title="Совет шефа">
        <p>Из молока и яиц выйдет омлет.</p>
      </Card>
    </>
  );
}
```

Пустые теги `<>` и `</>` — это **фрагмент**: обёртка, которая группирует элементы и не добавляет лишнего тега в DOM. Первая карточка в проверочном запуске превратилась в такой HTML:

```html
<section class="card">
  <h2 class="card-title">Скоро истекает срок</h2>
  <div class="card-body"><p>Молоко — до 13 ноября</p><p>Йогурт — до 14 ноября</p></div>
</section>
```

### Пример 2. Модальное окно для ошибок «Умного холодильника»

В вашем проекте есть требование: ошибки показывать пользователю в модальном окне, а не в консоли. Идеальный случай для `children`: окно одно, а тексты ошибок разные.

```jsx
import { useState } from 'react';

// Рамка: заголовок, кнопка и «дырка» для содержимого
function ErrorModal({ isOpen, title = 'Ошибка', onClose, children }) {
  if (!isOpen) return null; // окно закрыто — ничего не рисуем

  return (
    <div className="modal-backdrop" onClick={onClose}>
      <div
        className="modal"
        role="dialog"
        aria-modal="true"
        aria-label={title}
        onClick={(e) => e.stopPropagation()} // клик внутри окна не доходит до фона
      >
        <h2>{title}</h2>
        <div className="modal-body">{children}</div>
        <button onClick={onClose}>Понятно</button>
      </div>
    </div>
  );
}

// Использование: родитель решает, КОГДА показать окно и ЧТО в нём написать
function App() {
  const [error, setError] = useState(null);

  function handleSearch({ username, dish }) {
    if (!username || !dish) {
      setError('Введите имя пользователя и название блюда.');
      return;
    }
    // ... запрос к AI-шефу; при неудаче: setError('AI-шеф не ответил. Попробуйте ещё раз.')
  }

  return (
    <>
      <SearchForm onSearch={handleSearch} />
      <ErrorModal isOpen={error !== null} onClose={() => setError(null)}>
        <p>{error}</p>
      </ErrorModal>
    </>
  );
}
```

Разбор пропсов `ErrorModal`:

- `isOpen` — логический проп: показывать окно или нет. Окно не хранит это знание само, им управляет родитель.
- `title` — строка со значением по умолчанию `'Ошибка'`.
- `onClose` — проп-событие: окно сообщает «меня хотят закрыть», а родитель очищает `error`.
- `children` — текст ошибки или любая другая разметка. То же окно подойдёт для сообщения «У роли GUEST нет доступа».

Поведение проверено запуском в эмуляции браузера. Окно открывается при ошибке и не закрывается от клика по тексту. Закрывается оно от клика по тёмному фону или по кнопке «Понятно».

&#91;embedded content: ErrorModal · куда попадает каждый проп\]

Проп `children` — это «дырка» в рамке: родитель кладёт туда любой текст или элементы, а само окно не знает, что именно в ней лежит.

В реальных приложениях модальное окно часто рисуют через портал — `createPortal(…, document.body)`. Тогда его не обрежут стили родительских блоков. На работу с пропсами это не влияет: `isOpen`, `onClose` и `children` остаются теми же.

### Пример 3. Несколько «дырок»: слоты через обычные пропсы

```jsx
// Раскладка страницы: четыре места для содержимого
function PageLayout({ header, sidebar, children, footer }) {
  return (
    <div className="layout">
      <header>{header}</header>
      <aside>{sidebar}</aside>
      <main>{children}</main>
      <footer>{footer}</footer>
    </div>
  );
}

<PageLayout
  header={<h1>Умный холодильник</h1>}
  sidebar={<CategoryFilter />}
  footer={<small>Данные обновлены сегодня</small>}
>
  <ProductList products={products} />
</PageLayout>
```

`children` — главный слот, остальные слоты — обычные пропсы со значением-JSX. Раскладка отвечает за расстановку, а что именно стоит в каждом месте, решает родитель.

### Почему композиция лучше «универсального компонента с флажками»

```jsx
// ПЛОХО: окно обязано знать обо всех своих вариантах
<Modal type="error" showRetryButton showIcon iconName="warning" text="AI-шеф не ответил" />

// ХОРОШО: окно даёт рамку, а содержимое собирает родитель
<ErrorModal isOpen onClose={close}>
  <WarningIcon />
  <p>AI-шеф не ответил</p>
  <RetryButton onRetry={retry} />
</ErrorModal>
```

В первом варианте каждый новый случай добавляет флажок, и компонент растёт без конца. Во втором окно не меняется, а разнообразие даёт содержимое. Композиция ещё и спасает от протаскивания пропсов через много уровней, об этом раздел 12.

### Тонкости

- `children` можно показать по условию: `{isOpen && children}`.
- Значения `null`, `undefined`, `true` и `false` в разметке ничего не рисуют. Число `0` рисует, и это частая ловушка из раздела 16.
- В React есть утилиты `Children.map` и `Children.count` для разбора `children`. Документация React считает их редко нужными: такой код легко ломается. Обычно лучше передать массив данных.

## 9. Особые пропсы: key, ref и атрибуты HTML-элементов

Почти все пропсы — это ваши данные, но у нескольких имён особая роль. `key` React забирает себе, чтобы различать элементы списка, `ref` даёт доступ к DOM-узлу, а пропсы встроенных тегов вроде `<input>` подчиняются правилам браузера.

### Списки: из массива данных — в массив компонентов

```jsx
function ProductList({ products }) {
  return (
    <ul>
      {products.map((product) => (
        <ProductCard key={product.id} product={product} />
      ))}
    </ul>
  );
}
```

Метод `map` превращает массив данных в массив React-элементов: один продукт — одна карточка. Это та же функция высшего порядка, что в ваших заданиях по JavaScript. Каждому элементу списка нужен проп `key`.

### key — «номерок» элемента списка

**key** (ключ) — уникальная среди соседей строка или число. По ключу React узнаёт элемент между рендерами.

Простыми словами: представьте гардероб. Номерок привязан к пальто, а не к крючку, поэтому перевешенное пальто всё равно найдут. Ключ — такой номерок для компонента, а индекс в массиве — номер крючка.

Эксперимент. В каждой строке списка есть поле для заметки со своим состоянием. В строку «Молоко» ввели «купить ещё», затем в начало списка добавили «Хлеб».

| Что стояло в key | До добавления | После добавления хлеба |
| --- | --- | --- |
| Индекс `i` | Молоко \[купить ещё\], Яйца \[ \] | Хлеб \[купить ещё\], Молоко \[ \], Яйца \[ \] |
| `product.id` | Молоко \[купить ещё\], Яйца \[ \] | Хлеб \[ \], Молоко \[купить ещё\], Яйца \[ \] |

С индексом заметка «переехала» к хлебу: React увидел элемент с ключом 0 и решил, что это прежняя строка. С `id` заметка осталась у молока. Результат получен в эмуляции браузера.

Правила для key:

- Ключ уникален среди соседей в одном списке. В разных списках ключи могут повторяться.
- Ключ стабилен: у одного и того же продукта он не меняется между рендерами. Лучше всего подходит id из базы или файла, например из вашего `fridge.json`.
- `Math.random()` в роли ключа — ошибка: на каждом рендере ключи новые, и React пересоздаёт все элементы заново.
- Индекс допустим, только если список никогда не сортируют, не фильтруют и не дополняют в начале или середине.
- `key` ставят на самый внешний элемент внутри `map`, то есть на `<ProductCard key={…} />`, а не внутри самой карточки.
- Если ключ забыли, React предупредит в консоли: «Each child in a list should have a unique "key" prop».

### key не попадает в пропсы

```jsx
// ПЛОХО: внутри компонента key всегда undefined, а React выдаст предупреждение
function ProductCard({ key, product }) { /* ... */ }

// ХОРОШО: если id нужен внутри, передайте его отдельным пропом
<ProductCard key={product.id} productId={product.id} product={product} />
```

В разделе 2 это проверено запуском: React вернул `undefined` и сообщил «`key` is not a prop».

### Бонус: смена key сбрасывает компонент

Новый ключ для React означает новый компонент: старый удаляется вместе со своим состоянием. Это удобно с редактором из раздела 6:

```jsx
// При выборе другого продукта редактор создаётся заново и берёт свежее initialQuantity
<QuantityEditor key={selected.id} initialQuantity={selected.quantity} />
```

### ref как проп (React 19)

**ref** (ссылка) — объект `{ current: … }`, который React заполняет DOM-узлом. Простыми словами: закладка на конкретный элемент страницы, чтобы потом, например, поставить в него курсор.

Начиная с React 19 функциональный компонент получает `ref` как обычный проп. Раньше для этого требовалась обёртка `forwardRef`.

```jsx
import { useRef } from 'react';

// React 19: ref приходит вместе с остальными пропсами
function SearchInput({ ref, ...rest }) {
  return <input ref={ref} className="search-input" {...rest} />;
}

function SearchForm() {
  const dishRef = useRef(null); // сюда React положит DOM-узел <input>

  function handleSubmit(e) {
    e.preventDefault();
    if (!dishRef.current.value.trim()) {
      dishRef.current.focus(); // поле пустое — ставим в него курсор
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <SearchInput ref={dishRef} placeholder="Название блюда" />
      <button>Искать</button>
    </form>
  );
}
```

```jsx
// До React 19 то же самое писали так. Это всё ещё работает, но уже не нужно
import { forwardRef } from 'react';

const SearchInput = forwardRef(function SearchInput(props, ref) {
  return <input ref={ref} className="search-input" {...props} />;
});
```

В эмуляции браузера на React 19.3.1 проверены три факта. `SearchInput` получил `ref` в пропсах, и отправка пустой формы поставила курсор в поле. Запись `{...props}` теперь передаёт дальше и `ref`. Старый `forwardRef` тоже по-прежнему работает.

### Пропсы встроенных HTML-элементов

У тегов `<div>`, `<input>`, `<button>` набор пропсов задан заранее и почти совпадает с атрибутами HTML. Отличий немного, и все они объяснимы:

| В HTML | В React | Почему так |
| --- | --- | --- |
| `class="card"` | `className="card"` | `class` — зарезервированное слово JavaScript |
| `for="dish"` | `htmlFor="dish"` | `for` — тоже слово JavaScript |
| `onclick="go()"` (строка) | `onClick={go}` (функция) | События пишутся в camelCase и принимают функцию |
| `style="background-color: red"` | `style={{ backgroundColor: 'red' }}` | Стиль — объект, свойства в camelCase |
| `tabindex="2"` | `tabIndex={2}` | Имена атрибутов в camelCase |
| `aria-label`, `data-role` | так же, с дефисами | Исключение: `aria-*` и `data-*` пишутся как в HTML |

**camelCase** — способ записи, где слова идут слитно, а каждое следующее начинается с большой буквы: `backgroundColor`, `tabIndex`. Вот что React сделал с такими пропсами в проверочном запуске:

```jsx
<label htmlFor="dish" className="label">Блюдо</label>
<input id="dish" tabIndex={2} aria-label="Название блюда" data-role="dish" />
<p style={{ backgroundColor: 'red', fontSize: 14, zIndex: 2 }}>Просрочено</p>
```

```html
<label for="dish" class="label">Блюдо</label>
<input id="dish" tabindex="2" aria-label="Название блюда" data-role="dish"/>
<p style="background-color:red;font-size:14px;z-index:2">Просрочено</p>
```

Число 14 в `fontSize` React сам дополнил единицей `px`. У свойств без единиц, вроде `zIndex`, число осталось как есть.

### Свои компоненты — не HTML-теги

У вашего компонента нет «встроенных» атрибутов. `<ProductCard className="highlight" />` не добавит класс сам по себе: это просто проп, и компонент должен сам передать его своему тегу. В проверочном запуске компонент без пересылки вернул `<p>Молоко</p>` без всякого класса.

Обратная ошибка — случайно отдать свой проп HTML-тегу через `{...rest}`. На `<div isActive>` React выдал предупреждение «React does not recognize the `isActive` prop on a DOM element». Лечение — забрать свои пропсы до того, как раскладывать остальное:

```jsx
function ProductCard({ isActive, className = '', children, ...rest }) {
  // isActive забрали себе, в <div> уходит только то, что он понимает
  const classes = ['card', isActive && 'card--active', className].filter(Boolean).join(' ');
  return (
    <div className={classes} {...rest}>
      {children}
    </div>
  );
}
```

## 10. Пропсы и производительность

React сравнивает пропсы по ссылке, а не по содержимому. Объект, массив или функция, созданные заново при рендере, для него новое значение, даже если внутри всё то же самое. Это становится важным, когда вы оптимизируете компонент с помощью `memo`.

### Простыми словами: «тот же» и «такой же»

Две одинаковые кружки из магазина — такие же, но не те же: это два разных предмета. React спрашивает «это та же самая кружка?», а не «похожа ли она?». Строки и числа сравниваются по значению, а объекты, массивы и функции — по ссылке.

```js
// Результаты проверены в Node.js
({ a: 1 }) === ({ a: 1 })   // false — два разных объекта
[] === []                   // false — два разных массива
(() => {}) === (() => {})   // false — две разные функции
2 === 2                     // true  — числа сравниваются по значению
'Молоко' === 'Молоко'       // true  — строки тоже
Object.is(NaN, NaN)         // true  — так сравнивает React (NaN === NaN даёт false)
```

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| Сравнение по ссылке | Два объекта равны, только если это один и тот же объект в памяти | «Это тот же самый предмет?», а не «похож ли он?» |
| Поверхностное сравнение (shallow comparison) | Сравнение каждого пропа через `Object.is` без заглядывания внутрь объектов | Проверили пропсы по одному, внутрь не полезли |
| Мемоизация | Запоминание результата, чтобы не вычислять его повторно при тех же входных данных | «Уже считали — возьми из памяти» |
| `memo` | Функция React, которая пропускает перерисовку компонента, если его пропсы не изменились | Охранник: «пропсы те же — перерисовывать не нужно» |
| `useCallback` | Хук, который возвращает ту же функцию, пока не изменятся зависимости | «Не создавай функцию заново без причины» |
| `useMemo` | Хук, который запоминает результат вычисления между рендерами | То же самое для объектов, массивов и долгих расчётов |
| Массив зависимостей | Второй аргумент хука: список значений, при изменении которых результат считается заново | «Пересчитай, только если поменялось вот это» |

### Как работает memo

`memo(Component)` возвращает компонент-«охранника». Когда родитель перерисовывается, охранник сравнивает каждый новый проп со старым через `Object.is`. Если все равны, React берёт прошлый результат и не вызывает компонент.

&#91;embedded content: memo · когда рендер пропускается\]

`memo` сравнивает каждый проп со старым через `Object.is` и пропускает рендер, только если ни один проп не изменился.

### Эксперимент: что ломает memo

```jsx
import { memo, useState, useCallback } from 'react';

// Карточка с «охранником»: перерисуется, только если изменились пропсы
const ProductCard = memo(function ProductCard({ product, onDelete }) {
  return (
    <li>
      {product.name}
      <button onClick={() => onDelete(product.id)}>Удалить</button>
    </li>
  );
});

function Fridge() {
  const [products, setProducts] = useState([
    { id: 1, name: 'Молоко' },
    { id: 2, name: 'Яйца' },
  ]);
  const [query, setQuery] = useState(''); // меняется при каждом нажатии клавиши

  // Та же самая функция на всех рендерах: зависимостей нет
  const handleDelete = useCallback((id) => {
    setProducts((prev) => prev.filter((p) => p.id !== id));
  }, []);

  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <ul>
        {products.map((p) => (
          <ProductCard key={p.id} product={p} onDelete={handleDelete} />
        ))}
      </ul>
    </>
  );
}
```

Запись `setProducts((prev) => …)` — это **функция-обновитель**: React сам передаёт в неё актуальное состояние. Поэтому `handleDelete` не зависит от `products`, и массив зависимостей пустой.

В эмуляции браузера в поле поиска ввели три буквы и посчитали перерисовки двух карточек:

| Вариант кода | Перерисовок карточек | Почему |
| --- | --- | --- |
| Без `memo` | 6 | Дети перерисовываются вместе с родителем: 2 карточки × 3 нажатия |
| `memo`, но `handleDelete` — обычная функция внутри `Fridge` | 6 | На каждом рендере создаётся новая функция, и «охранник» видит новый проп |
| `memo` + `useCallback` | 0 | Все пропсы те же самые, перерисовка пропущена |
| `memo`, но в JSX `product={{ ...p }}` | 6 | Новый объект на каждом рендере, даже с тем же содержимым |
| `memo`, но внутрь карточки передан тег `<small>` | 6 | `children` — тоже проп, и JSX создаёт новый элемент каждый рендер |

### Как не ломать memo

- Константы выносите за пределы компонента, а изменяемые данные храните в состоянии. Тогда ссылки на них стабильны.
- Функции для пропсов оборачивайте в `useCallback`, вычисленные массивы и объекты — в `useMemo`.
- Помните, что `children` — тоже проп. Новый JSX между тегами на каждом рендере выключает `memo`.
- Если компоненту нужно одно поле, передайте его напрямую: `name={p.name}`. Строки и числа сравниваются по значению.

### Когда вообще оптимизировать

Не по умолчанию. Большинство перерисовок дешёвые: React вызывает функцию, сравнивает результат и не трогает DOM, если отличий нет. `memo` имеет смысл, когда компонент тяжёлый — длинный список, сложные расчёты, графики, — и часто перерисовывается с теми же пропсами. Сначала измерьте вкладкой Profiler в React DevTools, потом оптимизируйте.

Есть и автоматический путь. 7 октября 2025 года вышла первая стабильная версия **React Compiler** — инструмента сборки, который сам добавляет мемоизацию ([блог React](https://react.dev/blog/2025/10/07/react-compiler-1)). В проекте с компилятором большую часть ручных `memo`, `useCallback` и `useMemo` писать не нужно. Понимание сравнения по ссылке всё равно пригодится: оно объясняет, что именно делает компилятор.

## 11. Проверка типов пропсов: TypeScript, JSDoc и что изменилось в React 19

Сам JavaScript не проверяет, что в проп пришло значение нужного типа: `quantity="2"` вместо числа пройдёт молча. Сегодня пропсы описывают типами TypeScript или JSDoc-комментариями, и редактор ловит ошибку ещё до запуска. Старый способ, `propTypes`, в React 19 удалён.

### Простыми словами

Описание типов — это договор между родителем и ребёнком: «я принимаю `name` — строку, `quantity` — число, `onDelete` — функцию, которая получает id». Если договор нарушен, редактор сразу подчёркивает ошибку. Это как форма вилки и розетки: неподходящую вилку просто не вставить.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| Тип | Описание множества допустимых значений | «Что сюда можно класть» |
| TypeScript | Надстройка над JavaScript со статическими типами; перед запуском код переводится в обычный JS | JavaScript с проверкой «правописания» данных |
| Статическая проверка | Поиск ошибок по тексту программы, без её запуска | Проверка домашки до сдачи, а не на экзамене |
| Тип пропсов | Описание формы объекта props: какие поля и каких типов | Анкета: какие поля есть и что в них писать |
| Необязательный проп | Проп, помеченный знаком `?`, его можно не передавать | Поле анкеты «по желанию» |
| Объединение типов (union) | Тип «одно из перечисленных значений» | Выбор из выпадающего списка |
| JSDoc | Комментарии `/** … */` с описанием типов в обычном JavaScript | Типы в комментариях, без перехода на TypeScript |
| PropTypes | Устаревшая проверка пропсов во время работы программы | Старый контролёр, которого React 19 отключил |

### TypeScript: пропсы карточки продукта

```tsx
// ProductCard.tsx
import type { ReactNode } from 'react';

// Роли из «Умного холодильника»: допустима только одна из трёх строк
export type Role = 'ADMIN' | 'USER' | 'GUEST';

export type Product = {
  id: number;
  name: string;
  quantity: number;
  expiryDate?: string; // необязательное поле
};

type ProductCardProps = {
  product: Product;
  canDelete?: boolean;            // необязательный проп
  onDelete: (id: number) => void; // функция: получает число, результат не важен
  children?: ReactNode;           // любое содержимое между тегами
};

export function ProductCard({ product, canDelete = false, onDelete, children }: ProductCardProps) {
  return (
    <li>
      {product.name} — {product.quantity} шт.
      {children}
      {canDelete && <button onClick={() => onDelete(product.id)}>Удалить</button>}
    </li>
  );
}
```

Разбор записей:

- `type ProductCardProps = { … }` — описание формы пропсов. После двоеточия в параметрах (`}: ProductCardProps`) мы говорим: «пропсы должны быть вот такими».
- `canDelete?: boolean` — знак `?` делает проп необязательным, а `= false` в параметрах задаёт значение по умолчанию.
- `(id: number) => void` — тип функции. `void` значит «ничего полезного не возвращает».
- `ReactNode` — тип «всё, что React умеет отрисовать», из раздела 8.
- `Role` — объединение типов: опечатку в названии роли компилятор не пропустит.

### Какие ошибки ловит TypeScript

Примеры прогнаны через компилятор TypeScript 7.0.2. Вот что он сказал на ошибочный код:

| Ошибочный код | Сообщение компилятора | Смысл |
| --- | --- | --- |
| `<ProductCard product={milk} />` | `Property 'onDelete' is missing in type '{ product: Product; }' but required in type 'ProductCardProps'.` | Забыли обязательный проп |
| `quantity: '10'` в объекте продукта | `Type 'string' is not assignable to type 'number'.` | Строка вместо числа |
| `onDelete={(id) => id.toUpperCase()}` | `Property 'toUpperCase' does not exist on type 'number'.` | `id` — число, а у числа нет такого метода |
| `const role: Role = 'MODERATOR'` | `Type '"MODERATOR"' is not assignable to type 'Role'.` | Такой роли нет |

### Пропсы HTML-элементов: ComponentProps

Чтобы не переписывать все атрибуты кнопки вручную, берут готовый тип `ComponentProps<'button'>` и добавляют к нему свои пропсы:

```tsx
import type { ComponentProps } from 'react';

// Все атрибуты <button> плюс наш собственный variant
type FridgeButtonProps = ComponentProps<'button'> & {
  variant?: 'primary' | 'danger';
};

export function FridgeButton({ variant = 'primary', ...rest }: FridgeButtonProps) {
  return <button className={`btn btn-${variant}`} {...rest} />;
}

// В React 19 тип ComponentProps<'input'> уже содержит ref
export function SearchInput({ ref, ...rest }: ComponentProps<'input'>) {
  return <input ref={ref} className="search-input" {...rest} />;
}
```

На `<FridgeButton variant="warning">` компилятор ответил, что тип `"warning"` нельзя присвоить пропу, допускающему только `"primary"` и `"danger"`. Оба компонента прошли проверку без ошибок.

### Без TypeScript: JSDoc в обычном .js или .jsx

Если проект на обычном JavaScript, типы можно написать в комментариях. Строка `// @ts-check` в начале файла включает проверку в VS Code.

```jsx
// @ts-check

/**
 * Карточка продукта.
 * @param {{
 *   product: { id: number, name: string, quantity: number },
 *   canDelete?: boolean,
 *   onDelete: (id: number) => void
 * }} props
 */
export function ProductCard({ product, canDelete = false, onDelete }) {
  return (
    <li>
      {product.name}
      {canDelete && <button onClick={() => onDelete(product.id)}>Удалить</button>}
    </li>
  );
}
```

Тот же компилятор проверил и этот файл. На `quantity: '2'` он выдал ту же ошибку «Type 'string' is not assignable to type 'number'», хотя файл остался обычным JavaScript.

### PropTypes и defaultProps: что изменилось в React 19

| Механизм | До React 19 | В React 19 | Чем заменить |
| --- | --- | --- | --- |
| `Component.propTypes` | Предупреждения в консоли в режиме разработки | Удалено: проверки молча игнорируются | TypeScript или JSDoc |
| `defaultProps` у функции | Работал | Удалено: значение не подставляется | Значения по умолчанию при деструктуризации |
| `static defaultProps` у класса | Работал | Работает | Можно оставить |

Все три строки проверены на React 19.3.1 в разделе 4: проверка `propTypes` не сработала, функция с `defaultProps` получила `undefined`, а класс — своё значение по умолчанию. PropTypes были помечены устаревшими ещё в апреле 2017 года, в React 15.5. Для перевода старого кода на TypeScript есть автоматический переводчик: `npx codemod@latest react/prop-types-typescript` ([руководство по переходу на React 19](https://react.dev/blog/2024/04/25/react-19-upgrade-guide)).

### Важная граница: типы не проверяют данные снаружи

TypeScript и JSDoc проверяют текст программы, а не данные, которые придут во время работы. Ответ сервера или AI-шефа на Gemini может прийти в неожиданном виде — вы сталкивались с этим, когда разбирали ответы модели в домашнем задании. Такие данные проверяют кодом перед тем, как передать их в пропсы: вручную или библиотекой валидации вроде Zod.

## 12. Prop drilling и Context: когда пропсов становится слишком много

Prop drilling — это передача пропа через несколько уровней компонентов, которым он сам не нужен. От него есть два лекарства: композиция через `children` и Context, который доставляет значение сразу тем потомкам, кому оно нужно.

### Простыми словами

Prop drilling похож на записку, которую передают через весь класс: каждый ученик передаёт её соседу, не читая. Context похож на объявление по громкой связи: его слышит каждый, кому оно нужно, и никому не приходится работать почтальоном.

### Термины раздела

| Термин | Строгое определение | Простыми словами |
| --- | --- | --- |
| Prop drilling (протаскивание пропсов) | Передача пропа через промежуточные компоненты, которые его только пересылают | Записка, которую передают через весь класс |
| Context (контекст) | Механизм React для передачи значения всем потомкам без явных пропсов | Громкая связь для всего поддерева |
| `createContext` | Функция, которая создаёт объект контекста со значением по умолчанию | Завести «радиостанцию» |
| Провайдер (Provider) | Компонент, который задаёт значение контекста для всего, что внутри него | Передатчик: «вещаю для всех внутри меня» |
| `useContext` и `use` | Хуки, которые читают значение ближайшего провайдера выше по дереву | Приёмник: «настроиться на станцию» |
| Глобальное состояние | Данные, нужные многим частям приложения сразу | Общая доска объявлений |

### Проблема на примере: роль пользователя в холодильнике

В «Умном холодильнике» есть роли ADMIN, USER и GUEST. Кнопку «Удалить» должен видеть только администратор, а решает это карточка продукта глубоко внизу дерева.

```jsx
function App() {
  const user = { name: 'Алексей', role: 'ADMIN' };
  return <FridgePage user={user} products={products} />;
}

function FridgePage({ user, products }) {
  // FridgePage роль не нужна — он только пересылает user дальше
  return <ProductList user={user} products={products} />;
}

function ProductList({ user, products }) {
  // и ProductList тоже только пересылает
  return <ul>{products.map((p) => <ProductCard key={p.id} product={p} user={user} />)}</ul>;
}

function ProductCard({ product, user }) {
  const canDelete = user.role === 'ADMIN'; // и только здесь user наконец нужен
  return <li>{product.name}{canDelete && <button>Удалить</button>}</li>;
}
```

Чем это плохо:

- Промежуточные компоненты знают о данных, которые им не нужны, и их труднее переиспользовать.
- Новое поле для карточки заставляет править все уровни по пути.
- Чем глубже дерево, тем длиннее цепочка пересылки.

&#91;embedded content: prop drilling и Context · сравнение\]

Провайдер делает `user` доступным всему поддереву: `ProductCard` читает его через `useContext`, а промежуточным компонентам больше не нужно передавать его по цепочке.

### Лекарство 1: композиция

Документация React советует сначала попробовать обычные пропсы или передачу JSX через `children` и лишь потом браться за контекст ([источник](https://react.dev/learn/passing-data-deeply-with-context)). Если `FridgePage` — просто рамка страницы, пусть она принимает содержимое, а список создаст `App`, у которого уже есть `user`:

```jsx
function App() {
  const user = { name: 'Алексей', role: 'ADMIN' };
  return (
    <FridgePage title="Мой холодильник">
      <ProductList user={user} products={products} /> {/* создаём там, где данные уже есть */}
    </FridgePage>
  );
}

// Теперь FridgePage ничего не знает о пользователе
function FridgePage({ title, children }) {
  return (
    <section>
      <h1>{title}</h1>
      {children}
    </section>
  );
}
```

Один лишний уровень пересылки исчез. Часто этого уже достаточно.

### Лекарство 2: Context

```jsx
import { createContext, useContext, useState } from 'react';

// 1. Создаём контекст. Значение по умолчанию — гость, как в правилах вашего приложения
export const UserContext = createContext({ name: 'Гость', role: 'GUEST' });

// 2. Провайдер: всё, что внутри <UserContext>, видит user
function App() {
  const [user] = useState({ name: 'Алексей', role: 'ADMIN' });
  return (
    <UserContext value={user}>
      <FridgePage products={products} /> {/* user больше не передаём */}
    </UserContext>
  );
}

function FridgePage({ products }) {
  return <ProductList products={products} />;
}

function ProductList({ products }) {
  return <ul>{products.map((p) => <ProductCard key={p.id} product={p} />)}</ul>;
}

// 3. Потребитель: читает значение напрямую, минуя промежуточные уровни
function ProductCard({ product }) {
  const user = useContext(UserContext);
  const canDelete = user.role === 'ADMIN';
  return <li>{product.name}{canDelete && <button>Удалить</button>}</li>;
}
```

Что показал проверочный запуск на React 19.3.1:

| Ситуация | Результат |
| --- | --- |
| `<UserContext value={user}>` с ролью ADMIN | У каждого продукта есть кнопка «Удалить» |
| Провайдера выше нет | Работает значение по умолчанию GUEST, кнопок нет |
| Старая запись `<UserContext.Provider value={…}>` | Тоже работает |
| Два вложенных провайдера | Компонент читает ближайший сверху |
| `use(UserContext)` вместо `useContext` | Работает так же |

Запись `<UserContext value={…}>` без `.Provider` появилась в React 19. В статьях и старом коде вы чаще увидите `.Provider` — оба варианта делают одно и то же.

### Когда что выбирать

| Ситуация | Инструмент |
| --- | --- |
| Данные нужны ребёнку или внуку | Обычные пропсы |
| Промежуточные компоненты — просто рамки и раскладки | Композиция через `children` |
| Значение нужно многим компонентам на разных уровнях: тема, язык, текущий пользователь | Context |
| Большое общее состояние, которое часто меняется | Context + `useReducer` или отдельная библиотека состояния |

### Осторожности с Context

- Все компоненты, которые читают контекст, перерисуются при смене его значения. `memo` от этого не спасает.
- Новый объект в `value` на каждом рендере заставит перерисоваться всех читателей. Храните значение в состоянии или оборачивайте в `useMemo`, как в разделе 10.
- Контекст делает поток данных менее заметным: по пропсам компонента уже не видно, от чего он зависит. Поэтому контекст — инструмент для по-настоящему общих данных, а не замена любым пропсам.

## 13. Паттерны работы с пропсами

На пропсах строится несколько повторяющихся приёмов: условный рендеринг, управляемые компоненты, компонент как проп, render props и HOC. **Паттерн** — это проверенное типовое решение частой задачи, рецепт вместо импровизации.

### 1. Условный рендеринг по пропсам

**Условный рендеринг** — компонент показывает разную разметку в зависимости от пропсов. Инструментов три: ранний `return`, тернарный оператор `? :` и оператор `&&`.

```jsx
// Ранний return: простой if внутри компонента
function ExpiryBadge({ daysLeft }) {
  if (daysLeft < 0) return <span className="badge badge--danger">Просрочено</span>;
  if (daysLeft <= 2) return <span className="badge badge--warning">Скоро истекает</span>;
  return null; // null — «ничего не показывать»
}

function ProductCard({ product }) {
  return (
    <li>
      {product.name}
      <ExpiryBadge daysLeft={product.daysLeft} />
      {/* тернарный оператор: одно из двух */}
      {product.quantity > 0 ? ` — ${product.quantity} шт.` : ' — закончился'}
      {/* &&: показать или ничего */}
      {product.isFavorite && <span> (избранное)</span>}
    </li>
  );
}
```

Проверка на трёх продуктах дала такой результат:

| Пропсы продукта | На экране |
| --- | --- |
| Молоко: `daysLeft: -1`, `quantity: 2`, `isFavorite: true` | Молоко · Просрочено · 2 шт. · (избранное) |
| Йогурт: `daysLeft: 1`, `quantity: 0` | Йогурт · Скоро истекает · закончился |
| Сыр: `daysLeft: 10`, `quantity: 1` | Сыр · 1 шт. |

Ловушка с нулём:

```jsx
{product.quantity && <span>{product.quantity} шт.</span>}     // при 0 на экране появится «0»
{product.quantity > 0 && <span>{product.quantity} шт.</span>} // правильно: слева логическое значение
```

Оператор `&&` возвращает левую часть, если она «ложная». `false` React не рисует, а число `0` рисует. В проверочном запуске первая строка дала `<p>0</p>`, вторая — пустой `<p></p>`.

### 2. Управляемые и неуправляемые компоненты

**Управляемый компонент** (controlled) получает своё значение через проп `value` и сообщает об изменениях через `onChange`. Простыми словами: руль у родителя. **Неуправляемый** (uncontrolled) хранит значение сам, а родитель может задать только начальное значение, например `<input defaultValue="Молоко" />`.

```jsx
import { useState } from 'react';

// Управляемый счётчик количества: своего состояния нет
function QuantityStepper({ value, onChange, min = 0, max = 99 }) {
  return (
    <div className="stepper">
      <button onClick={() => onChange(Math.max(min, value - 1))} disabled={value <= min}>−</button>
      <span>{value}</span>
      <button onClick={() => onChange(Math.min(max, value + 1))} disabled={value >= max}>+</button>
    </div>
  );
}

// Родитель держит значение и всегда знает его
function AddProductForm() {
  const [qty, setQty] = useState(1);
  return (
    <>
      <QuantityStepper value={qty} onChange={setQty} max={3} />
      <p>Родитель знает: {qty}</p>
    </>
  );
}
```

В эмуляции браузера счётчик вёл себя так. С 1 кнопка «−» дала 0 и стала неактивной. Четыре нажатия «+» довели до 3, и кнопка «+» отключилась. Родитель на каждом шаге показывал то же число.

Два предупреждения React, которые стоит узнавать в лицо:

- `<input value="Молоко" />` без `onChange` — «You provided a `value` prop to a form field without an `onChange` handler». Поле станет только для чтения.
- `value` сначала `undefined`, потом строка — «A component is changing an uncontrolled input to be controlled». Лечение: начинайте с пустой строки, `useState('')`.

Оба текста получены в проверочном запуске.

### 3. Компонент как проп

Можно передать не готовую разметку, а сам компонент — функцию, которую получатель вызовет со своими пропсами:

```jsx
function CompactCard({ product }) {
  return <li className="compact">{product.name}</li>;
}

// renderAs: Card — переименование с большой буквы, иначе JSX примет его за HTML-тег
function ProductList({ products, renderAs: Card = ProductCard }) {
  return <ul>{products.map((p) => <Card key={p.id} product={p} />)}</ul>;
}

<ProductList products={products} renderAs={CompactCard} />
// Результат: <ul><li class="compact">Молоко</li><li class="compact">Сыр</li></ul>
```

Разница с передачей JSX: `icon={<SnowIcon />}` — это уже созданный элемент со своими пропсами. `renderAs={CompactCard}` — «чертёж», по которому получатель сам создаст элементы с нужными данными.

### 4. Render props: проп-функция, которая возвращает разметку

**Render prop** — проп-функция, которую компонент вызывает, чтобы узнать, что нарисовать, и передаёт в неё свои данные. Простыми словами: компонент делает работу, а внешний вид спрашивает у родителя.

```jsx
// Список сам фильтрует, а КАК рисовать элемент и пустой список — решает родитель
function FilteredList({ items, filter, renderItem, renderEmpty }) {
  const visible = items.filter(filter);
  if (visible.length === 0) return renderEmpty();
  return <ul>{visible.map((item) => renderItem(item))}</ul>;
}

<FilteredList
  items={products}
  filter={(p) => p.daysLeft <= 2}
  renderItem={(p) => <li key={p.id}>{p.name}: осталось {p.daysLeft} дн.</li>}
  renderEmpty={() => <p>Срочных продуктов нет</p>}
/>
```

На продуктах «Молоко» (1 день) и «Сыр» (10 дней) компонент вернул одну строку «Молоко: осталось 1 дн.». С фильтром «просроченные» он вызвал `renderEmpty` и показал «Срочных продуктов нет». Ключ `key` здесь ставит тот, кто создаёт `<li>`, то есть функция `renderItem`.

### 5. HOC: компонент высшего порядка

**HOC** (higher-order component) — функция, которая принимает компонент и возвращает новый с дополнительными пропсами. Это та же идея, что функции высшего порядка из ваших заданий, только на уровне компонентов.

```jsx
import { useContext } from 'react';

// Принимает компонент → возвращает компонент, который добавляет проп user
function withUser(Component) {
  return function WithUser(props) {
    const user = useContext(UserContext);
    return <Component {...props} user={user} />;
  };
}

function RoleCard({ product, user }) {
  return <li>{product.name}{user.role === 'ADMIN' && <button>Удалить</button>}</li>;
}

const RoleCardWithUser = withUser(RoleCard);
```

Внутри провайдера с ролью ADMIN `RoleCardWithUser` показал кнопку, без провайдера — нет. Сегодня ту же задачу чаще решают хуком прямо в компоненте, но HOC ещё встречается в библиотеках и старом коде.

### Сводка паттернов

| Паттерн | Что передаётся в пропсах | Когда применять |
| --- | --- | --- |
| Условный рендеринг | Данные, от которых зависит вид | Всегда, когда вид меняется от данных |
| Управляемый компонент | `value` + `onChange` | Значение нужно родителю: формы, фильтры, счётчики |
| JSX в пропе (слот) | Готовая разметка | Рамки, раскладки, модальные окна (раздел 8) |
| Компонент как проп | Сама функция-компонент | Получатель должен создать элементы со своими данными |
| Render props | Функция, возвращающая JSX | Компонент даёт данные, а внешний вид выбирает родитель |
| HOC | Дополнительные пропсы от обёртки | В старом коде и библиотеках; в новом чаще хуки |

## 14. Пример из ваших проектов: «Умный холодильник» на React

Веб-интерфейс из ТЗ-28 ложится на React целиком: всё состояние живёт в одном компоненте `App`, а семь компонентов получают данные только через пропсы. Ниже рабочий набросок: код прогнан в эмуляции браузера, но в вашем репозитории его пока нет.

### Что берём из проекта

- Приложение хранит продукты и их сроки годности и умеет спрашивать рецепт у AI-шефа на Gemini.
- ТЗ-28: поле имени пользователя, поле названия блюда, кнопка «Искать» и область результата.
- Роли ADMIN, USER и GUEST ищутся по имени, незнакомое имя даёт GUEST.
- Ошибки показываются в модальном окне, а не в консоли.
- Сейчас цепочка такая: `index.html` → `main.js` → `authService.js`, `fileService.js`, `promptService.js`, `aiService.js`, `config.js`.

### Полный код с комментариями

```jsx
// FridgeApp.jsx — набросок React-интерфейса «Умного холодильника» (ТЗ-28)
// Все данные приходят в компоненты через пропсы, состояние живёт в App.
import { useState } from 'react';

// Роли по ТЗ: роль ищется по имени, незнакомое имя — гость
export const ROLES = { ADMIN: 'ADMIN', USER: 'USER', GUEST: 'GUEST' };
const KNOWN_USERS = { alexey: ROLES.ADMIN, maria: ROLES.USER }; // пример данных

export function getRole(username) {
  return KNOWN_USERS[username.trim().toLowerCase()] ?? ROLES.GUEST;
}

// ---------- «Глупые» компоненты: только пропсы, без своего состояния ----------

function Header({ userName, role }) {
  return (
    <header>
      <h1>Умный холодильник</h1>
      {userName && <p className="who">Вы вошли как {userName} ({role})</p>}
    </header>
  );
}

function ExpiryBadge({ daysLeft }) {
  if (daysLeft < 0) return <span className="badge danger">Просрочено</span>;
  if (daysLeft <= 2) return <span className="badge warning">Скоро истекает</span>;
  return null; // срок в порядке — плашка не нужна
}

function ProductCard({ product, canDelete, onDelete }) {
  return (
    <li className="product-card">
      <span>{product.name} — {product.quantity} шт.</span>
      <ExpiryBadge daysLeft={product.daysLeft} />
      {canDelete && <button onClick={() => onDelete(product.id)}>Удалить</button>}
    </li>
  );
}

function ProductList({ products, canDelete, onDelete }) {
  if (products.length === 0) return <p>Холодильник пуст</p>;
  return (
    <ul className="product-list">
      {products.map((p) => (
        <ProductCard key={p.id} product={p} canDelete={canDelete} onDelete={onDelete} />
      ))}
    </ul>
  );
}

function RecipeResult({ result, isLoading }) {
  if (isLoading) return <p className="result">AI-шеф думает…</p>;
  if (!result) return null;
  return (
    <section className="result">
      <h2>{result.dish}</h2>
      <p>{result.text}</p>
    </section>
  );
}

function ErrorModal({ isOpen, onClose, children }) {
  if (!isOpen) return null;
  return (
    <div className="modal-backdrop" onClick={onClose}>
      <div className="modal" role="dialog" aria-modal="true" aria-label="Ошибка" onClick={(e) => e.stopPropagation()}>
        <h2>Ошибка</h2>
        <div className="modal-body">{children}</div>
        <button onClick={onClose}>Понятно</button>
      </div>
    </div>
  );
}

// ---------- Форма из ТЗ-28: поля хранит сама, наружу отдаёт только событие ----------

function SearchForm({ onSearch, isLoading }) {
  const [username, setUsername] = useState('');
  const [dish, setDish] = useState('');

  function handleSubmit(e) {
    e.preventDefault(); // не перезагружать страницу
    onSearch({ username: username.trim(), dish: dish.trim() });
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="username" value={username} onChange={(e) => setUsername(e.target.value)} placeholder="Имя пользователя" />
      <input name="dish" value={dish} onChange={(e) => setDish(e.target.value)} placeholder="Название блюда" />
      <button type="submit" disabled={isLoading}>{isLoading ? 'Ищем…' : 'Искать'}</button>
    </form>
  );
}

// ---------- Корень: единственный владелец состояния ----------

export default function App({ initialProducts, findRecipe }) {
  const [user, setUser] = useState(null); // { name, role }
  const [products, setProducts] = useState(initialProducts);
  const [result, setResult] = useState(null);
  const [error, setError] = useState(null);
  const [isLoading, setIsLoading] = useState(false);

  const canDelete = user?.role === ROLES.ADMIN; // производное значение: не храним, а вычисляем

  async function handleSearch({ username, dish }) {
    if (!username || !dish) {
      setError('Введите имя пользователя и название блюда.');
      return;
    }
    const role = getRole(username);
    setUser({ name: username, role });
    setIsLoading(true);
    try {
      const recipe = await findRecipe({ role, dish, products }); // сервис пришёл пропом
      setResult(recipe);
    } catch (err) {
      setError(err.message); // ошибку показываем в модальном окне, а не в консоли
    } finally {
      setIsLoading(false);
    }
  }

  function handleDelete(id) {
    setProducts((prev) => prev.filter((p) => p.id !== id));
  }

  return (
    <>
      <Header userName={user?.name} role={user?.role} />
      <SearchForm onSearch={handleSearch} isLoading={isLoading} />
      <ProductList products={products} canDelete={canDelete} onDelete={handleDelete} />
      <RecipeResult result={result} isLoading={isLoading} />
      <ErrorModal isOpen={error !== null} onClose={() => setError(null)}>
        <p>{error}</p>
      </ErrorModal>
    </>
  );
}
```

### Разбор решений

- **Состояние в одном месте.** `user`, `products`, `result`, `error` и `isLoading` нужны нескольким компонентам, поэтому живут в их общем родителе `App` (раздел 7).
- **Локальное состояние формы.** Набираемый текст нужен только `SearchForm`. Наружу форма отдаёт готовый результат через `onSearch({ username, dish })`.
- **Права как производное значение.** `canDelete` не хранится, а вычисляется из роли при каждом рендере. Запись `user?.role` — опциональная цепочка: если `user` равен `null`, результат будет `undefined` без ошибки.
- **Сервис приходит пропом.** `App` не знает, как устроен поиск рецепта: он просто вызывает `findRecipe`. Благодаря этому в проверке ниже вместо Gemini подставлена функция-заглушка.
- **Ошибки — в модальное окно.** И пустые поля, и ошибка сервиса попадают в `error`, а окно показывает текст через `children`.

### Запуск: откуда берутся initialProducts и findRecipe

```jsx
// main.jsx — точка входа вместо нынешнего main.js
import { createRoot } from 'react-dom/client';
import App from './FridgeApp.jsx';

// Запрос к своему серверу. Адрес /api/recipe условный — его ещё нужно сделать
async function findRecipe({ role, dish, products }) {
  const response = await fetch('/api/recipe', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ role, dish, products }),
  });
  if (!response.ok) throw new Error('AI-шеф не ответил. Попробуйте ещё раз.');
  return response.json(); // ожидаем { dish, text }
}

const initialProducts = [
  { id: 1, name: 'Молоко', quantity: 2, daysLeft: 1 },
  { id: 2, name: 'Яйца', quantity: 10, daysLeft: 7 },
  { id: 3, name: 'Йогурт', quantity: 1, daysLeft: -2 },
];

createRoot(document.getElementById('root')).render(
  <App initialProducts={initialProducts} findRecipe={findRecipe} />
);
```

Почему через сервер: в вашем `aiService.js` ключ Gemini читается из `.env` в Node.js. В браузере ключ увидел бы любой посетитель, поэтому запрос к AI должен идти с сервера. Структура продукта `{ id, name, quantity, daysLeft }` здесь условная: подстройте её под свой `fridge.json`.

## 15. Пример из ваших проектов: стол для преферанса в Kosmo Game Hub

В карточной игре пропсы решают сразу две задачи: показывают игроку его взгляд на партию и не дают интерфейсу узнать лишнего. Движок хранит полное состояние, а компоненты получают только то, что положено видеть этому игроку. Ниже набросок стола, проверенный в эмуляции браузера; движок в нём не реализован.

### Архитектурная идея: интерфейс — функция от «вида игрока»

- **Движок знает всё:** все руки, прикуп, взятки, чей ход.
- **Вид игрока** (player view) — объект, который движок строит для одного игрока: свои карты открыты, у соперников только количество карт. В boardgame.io для этого есть опция `playerView`, которая вырезает секреты из состояния.
- **Компоненты получают вид игрока пропсами** и рисуют его. Правила хранения и расчёта им неизвестны.
- **Ходы уходят наверх** через проп-функции `onPlayCard(cardId)` и `onBid(bid)`. Движок проверяет ход и строит новое состояние.
- **ИИ думает отдельно**, например ISMCTS в Web Worker. Столу достаточно пропа `isThinking` у нужного соперника и итогового хода.

Почему это важно: если `OpponentSeat` получает только `cardCount`, то даже ошибка в вёрстке не покажет чужие карты — их просто нет в пропсах. Для сетевой игры вид игрока нужно строить на сервере: всё, что попало в браузер, можно увидеть в инструментах разработчика, включая пропсы в React DevTools.

### Дерево компонентов стола

Движок отдаёт интерфейсу только вид игрока, поэтому `GameTable` не может показать чужие карты, а ходы возвращаются наверх через `onPlayCard` и `onBid`.

| Компонент | Пропсы | Что важно |
| --- | --- | --- |
| `GameTable` | `view`, `onPlayCard`, `onBid` | Единственный вход: вид игрока и два колбэка |
| `OpponentSeat` | `name`, `cardCount`, `isActive`, `isDealer`, `isThinking`, `lastBid` | Приходит только количество карт |
| `TrickArea` | `trick`, `trump` | Карты текущей взятки и козырь |
| `BiddingPanel` | `availableBids`, `onBid` | Появляется только в торговле и только в ваш ход |
| `PlayerHand` | `cards`, `playableIds`, `onPlayCard` | Ваши карты и список разрешённых |
| `Card` | `card`, `isPlayable`, `onPlay` | Без `onPlay` — просто картинка, с `onPlay` — кнопка |

### Код стола

```jsx
// PreferansTable.jsx — стол для преферанса (Kosmo Game Hub): набросок на пропсах
// Компоненты ничего не знают о движке: они получают «вид игрока» и отдают наверх ходы.

const SUIT_SYMBOL = { spades: '♠', clubs: '♣', diamonds: '♦', hearts: '♥' };

// Правило хода: в масть; нет масти — козырем; нет и козыря — любой картой
export function getPlayableIds(hand, trick, trump) {
  if (trick.length === 0) return hand.map((c) => c.id); // заходить можно с любой карты
  const leadSuit = trick[0].card.suit;
  const sameSuit = hand.filter((c) => c.suit === leadSuit);
  if (sameSuit.length > 0) return sameSuit.map((c) => c.id);
  const trumps = trump ? hand.filter((c) => c.suit === trump) : [];
  if (trumps.length > 0) return trumps.map((c) => c.id);
  return hand.map((c) => c.id);
}

// Карта: если onPlay не передали — просто картинка, иначе кнопка
function Card({ card, isPlayable = false, onPlay }) {
  const label = `${card.rank}${SUIT_SYMBOL[card.suit]}`;
  if (!onPlay) return <span className={`card card--${card.suit}`}>{label}</span>;
  return (
    <button className={`card card--${card.suit}`} disabled={!isPlayable} onClick={() => onPlay(card.id)}>
      {label}
    </button>
  );
}

function CardBack() {
  return <span className="card card--back" aria-label="Закрытая карта" />;
}

// Соперник: получает только КОЛИЧЕСТВО карт, а не сами карты
function OpponentSeat({ name, cardCount, isActive, isDealer, isThinking, lastBid }) {
  return (
    <div className={isActive ? 'seat seat--active' : 'seat'}>
      <strong>{name}</strong>{isDealer && ' (сдаёт)'}
      <div className="seat-cards">
        {/* рубашки одинаковые и без состояния, поэтому индекс в роли key здесь допустим */}
        {Array.from({ length: cardCount }, (_, i) => <CardBack key={i} />)}
      </div>
      {lastBid && <p className="bid">Заявка: {lastBid}</p>}
      {isThinking && <p className="thinking">думает…</p>}
    </div>
  );
}

function TrickArea({ trick, trump }) {
  return (
    <div className="trick">
      <p>Козырь: {trump ? SUIT_SYMBOL[trump] : 'без козыря'}</p>
      {trick.map(({ seat, card }) => (
        <div key={card.id}>
          <small>{seat}</small> <Card card={card} />
        </div>
      ))}
    </div>
  );
}

function BiddingPanel({ availableBids, onBid }) {
  return (
    <div className="bidding">
      {availableBids.map((bid) => (
        <button key={bid} onClick={() => onBid(bid)}>{bid}</button>
      ))}
    </div>
  );
}

function PlayerHand({ cards, playableIds, onPlayCard }) {
  return (
    <div className="hand">
      {cards.map((card) => (
        <Card key={card.id} card={card} isPlayable={playableIds.includes(card.id)} onPlay={onPlayCard} />
      ))}
    </div>
  );
}

// Стол целиком: всё состояние приходит в пропе view, ходы уходят через onPlayCard и onBid
export default function GameTable({ view, onPlayCard, onBid }) {
  const { phase, me, opponents, trick, trump, availableBids } = view;

  // производное значение: какие карты сейчас можно сыграть
  const playableIds = phase === 'playing' && me.isActive ? getPlayableIds(me.cards, trick, trump) : [];

  return (
    <div className="table">
      <div className="opponents">
        {opponents.map((o) => (
          <OpponentSeat key={o.name} {...o} /> // форма объекта совпадает с пропсами — spread уместен
        ))}
      </div>
      {phase === 'playing' && <TrickArea trick={trick} trump={trump} />}
      {phase === 'bidding' && me.isActive && <BiddingPanel availableBids={availableBids} onBid={onBid} />}
      <PlayerHand cards={me.cards} playableIds={playableIds} onPlayCard={onPlayCard} />
    </div>
  );
}
```

### Как выглядит вид игрока

```jsx
// Такой объект движок строит для игрока «Алексей». Чужих карт в нём нет
const view = {
  phase: 'playing',
  trump: 'hearts',
  me: {
    name: 'Алексей',
    isActive: true,
    cards: [
      { id: '7S', rank: '7', suit: 'spades' },
      { id: 'QS', rank: 'Д', suit: 'spades' },
      { id: '10D', rank: '10', suit: 'diamonds' },
      { id: 'AH', rank: 'Т', suit: 'hearts' },
      { id: 'KC', rank: 'К', suit: 'clubs' },
    ],
  },
  opponents: [
    { name: 'Мария', cardCount: 9, isActive: false, isDealer: true, lastBid: '6♠' },
    { name: 'Бот', cardCount: 10, isActive: false, isThinking: false },
  ],
  trick: [{ seat: 'Мария', card: { id: '9S', rank: '9', suit: 'spades' } }],
  availableBids: ['Пас', '6♠', '6♣', 'Мизер'],
};

// engine — условный объект вашего движка
<GameTable view={view} onPlayCard={(id) => engine.play(id)} onBid={(bid) => engine.bid(bid)} />
```

В примере достоинства записаны по-русски: Т — туз, К — король, Д — дама, В — валет.

### Разбор решений

- **Один `Card` — два режима.** Необязательный проп-функция `onPlay` превращает карту в кнопку. Во взятке карта просто показана, в руке её можно сыграть.
- **Список разрешённых карт — производное значение.** `playableIds` вычисляется из пропсов при каждом рендере. В настоящем проекте лучше брать список допустимых ходов из движка, чтобы правила жили в одном месте.
- **Spread по делу.** Объект соперника в `view` по форме совпадает с пропсами `OpponentSeat`, поэтому `{...o}` здесь читается легко.
- **Индекс в роли key — осознанно.** Рубашки карт одинаковые и не имеют состояния, так что ловушка из раздела 9 здесь не сработает.
- **Условный рендеринг по фазе.** Панель торговли видна только при `phase === 'bidding'` и только в ваш ход, взятка — только при `phase === 'playing'`.

### Что показала проверка

| Ситуация на столе | Результат |
| --- | --- |
| Заход с 9♠, козырь ♥ | Активны только 7♠ и Д♠ |
| Клик по неактивной 10♦, потом по Д♠ | `onPlayCard` вызван один раз, с `'QS'` |
| Заход с трефы, треф нет, козырь ♥ | Активен только Т♥: нужно козырять |
| То же без козыря | Активны все карты |
| Не ваш ход | Ни одной активной карты |
| Соперники Мария (9 карт) и Бот (10 карт) | 9 и 10 рубашек, ни одной открытой карты |
| Торговля, ваш ход | Панель с заявками; клик по 6♣ передал `'6♣'` в `onBid` |
| Ходит Бот, `isThinking: true` | У Бота подсветка активного места и подпись «думает…» |

### Связь с производительностью

Пока ИИ думает, движок может часто обновлять `view` — например, флаг `isThinking`. Вместе со столом перерисуются и десять карт в руке, хотя для них ничего не изменилось. Если это станет заметно, помогут `memo(Card)` и стабильный `onPlayCard` через `useCallback` из раздела 10. Ещё лучше сделать так, чтобы движок не пересоздавал массив `me.cards`, когда рука не менялась: тогда ссылка останется прежней.

### Десять правил одной строкой

1. Пропсы — единственный аргумент компонента, один объект.
2. Строки — в кавычках, всё остальное — в фигурных скобках.
3. Данные текут вниз, события — вверх через функции.
4. Пропсы только читают, а изменения делает владелец данных.
5. Вычисляйте значения из пропсов при рендере, а не копируйте их в состояние.
6. Передавайте функцию, а не результат её вызова.
7. У элемента списка нужен стабильный `key`, и в пропсы он не попадает.
8. `children` — обычный проп с содержимым между тегами.
9. React сравнивает объекты и функции по ссылке.
10. Сначала пропсы и композиция, и лишь потом Context.

function CategoryFilter({ categories, selected, onSelect }) {
  return (

### Ответ 4

```jsx
import { useState } from 'react';

// Форма хранит только набираемый текст, а список живёт у родителя
function AddProductForm({ onAdd }) {
  const [name, setName] = useState('');

  function handleSubmit(e) {
    e.preventDefault();
    if (!name.trim()) return; // пустое название не добавляем
    onAdd(name.trim());       // событие уходит наверх
    setName('');              // очищаем поле
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="Новый продукт" />
      <button>Добавить</button>
    </form>
  );
}

function Fridge() {
  const [items, setItems] = useState([{ id: 'milk', name: 'Молоко' }]);

  function handleAdd(name) {
    setItems((prev) => [...prev, { id: crypto.randomUUID(), name }]); // уникальный id для key
  }

  return (
    <>
      <AddProductForm onAdd={handleAdd} />
      <p>Продуктов: {items.length}</p>
      <ul>{items.map((p) => <li key={p.id}>{p.name}</li>)}</ul>
    </>
  );
}
```

Проверка: ввели «  Сыр » с пробелами — в списке появился «Сыр», счётчик показал 2. Ввод из одних пробелов ничего не добавил. `crypto.randomUUID()` создаёт случайный уникальный id. Он создаётся один раз при добавлении и потом не меняется, поэтому годится в роли `key`, в отличие от `Math.random()` внутри JSX.

### Ответ 5

```jsx
function TrickCounter({ tricks, declarer, contract }) {
  return (
    <ul className="tricks">
      {Object.entries(tricks).map(([player, count]) => {
        const isDeclarer = player === declarer;
        const left = contract - count; // сколько ещё нужно взять
        return (
          <li key={player} className={isDeclarer ? 'declarer' : undefined}>
            {player}: {count}
            {isDeclarer &&
              (left > 0 ? ` из ${contract}, осталось взять ${left}` : ` из ${contract}, контракт выполнен`)}
          </li>
        );
      })}
    </ul>
  );
}

<TrickCounter tricks={{ Алексей: 4, Мария: 2, Бот: 1 }} declarer="Алексей" contract={6} />
```

Проверка: при 4 взятках показано «Алексей: 4 из 6, осталось взять 2», при 6 — «Алексей: 6 из 6, контракт выполнен». `Object.entries` превращает объект в массив пар `[имя, число]`, а имя игрока уникально и подходит для `key`. `className={undefined}` React просто не выводит.
